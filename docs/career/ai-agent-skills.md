# 北京30K+岗位：AI／Agent能力总结与针对性学习路线

更新日期：2026-11-05
示例画像：有前端开发经验、熟悉Agent辅助开发、希望转向AI应用工程。文中优先级采用约4年前端经验这一历史初筛口径；请按个人能力与当前完整JD调整。
范围：上一份清单中的React前端5岗、AI应用／Agent 15岗，编号沿用F1–F5、A1–A15。

## 1. 先确定学习重点

建议优先补齐这条链路：

**模型API与结构化输出 → 工具调用 → 可恢复的Agent执行流程 → MCP → 评测与排错 → React产品交互 → 部署交付。**

已有前端经验可以用于AI产品界面、任务工作台、可视化编排和全栈交付。接下来要积累的是：能亲自解释模型如何接入、工具如何执行、任务为什么失败，以及怎样衡量系统效果。

本文把两类能力分别记录：

- **使用Agent完成研发**：需求拆解、Skill与工具组织、代码审查、测试和交付提效。F1、A1与此直接相关。
- **开发供用户使用的Agent系统**：模型接入、工具执行、编排、状态、评测和后端服务。A4、A5、A7、A10、A15等涉及这类工作。

### 阅读口径

上一轮多个BOSS详情页受到访问限制，取得的信息包括公开列表摘要、搜索索引和关联原帖的转载。**本文覆盖现有材料能识别的AI／Agent能力类别，不能保证穷尽20份完整JD的所有要求。**

全文使用以下标记，避免把学习建议当成招聘方要求：

|标记|含义|
|---|---|
|**D**|BOSS公开列表或索引中明确出现；摘要未必能判断是必需还是加分|
|**R**|带BOSS原帖链接的转载中明确出现；原帖尚未完整核验|
|**E**|为了实现岗位职责而补充的学习建议，原有材料未明确写出|
|**U**|信息不足，仍需完整JD或招聘方确认|

优先级是针对示例画像的学习排序，不是统计出的岗位出现频率：

- **P0**：先能独立实现、讲清楚，并留下可演示证据。
- **P1**：基础跑通后补齐，或根据目标岗位提前。
- **P2**：选定方向再深挖；若目标岗位明确要求，则应上调。

## 3. 每项能力具体学什么、学到什么程度

以下练习与验收目标均为学习设计（**E**），不代表招聘方统一考核标准。

### 3.1 模型API、结构化输出与Prompt｜P0

**学习内容**

- 理解messages、角色、上下文窗口、Token、流式响应、停止原因及模型输出的不确定性。
- 把模型调用放在服务端，处理鉴权、超时、限流、取消和错误分类。
- 用Schema约束结构化结果，并在程序侧校验；为字段缺失、拒答和格式错误设计分支。
- Prompt写清任务、输入边界、输出契约和例子；保存版本并用固定案例比较修改效果。
- 理解“模型生成工具调用请求”和“应用程序执行工具”的分工。

**完成标准**

做一个服务：接收工单文本，返回经过校验的分类、摘要和待补信息；提供流式进度。对于信息不足、模型拒答或结构错误，能给出可解释状态。

可参考[Claude工具调用官方文档](https://platform.claude.com/docs/en/agents-and-tools/tool-use/overview)理解模型与程序之间的调用往返；TypeScript实现也可参考[AI SDK官方文档](https://ai-sdk.dev/docs/introduction)。选择你能正常访问的模型服务即可，不需要先同时接入多家。

### 3.2 工具调用与单Agent执行循环｜P0

**学习内容**

- 定义工具名称、用途、输入Schema、输出格式和错误类型。
- 实现“模型决定下一步 → 程序校验 → 执行工具 → 返回结果 → 继续或结束”。
- 设置最大执行步数、超时、调用预算和终止条件，避免无限循环。
- 为写操作做权限校验和幂等处理；需要确认的操作应进入明确的确认状态。
- 对无效参数、空结果、工具不可用、重复调用分别处理。

**练习**

实现三个工具：检索研发文档、读取工单、生成工单草稿。先让单Agent根据问题选择工具并整理带来源的答复。工具执行接口的职责可结合[工具调用说明](https://platform.claude.com/docs/en/agents-and-tools/tool-use/overview)理解。

**完成标准**

能定位一次失败究竟来自工具描述、模型选错工具、参数错误、执行失败还是结果解释错误；工具异常时任务能够停止或按规则恢复。

### 3.3 上下文、状态与记忆｜P0基础，P1长期记忆

**学习内容**

- 区分输入上下文、会话历史、任务状态、长期偏好和外部知识。
- 保存事实、来源与状态；对大段工具结果进行筛选或摘要。
- 学会按Token预算组织上下文，避免无限追加历史。
- 长期记忆需要用户隔离、更新、纠错和删除机制；检索到的知识也不自动等于记忆。
- 恢复任务时，先核对哪些动作已完成，再决定是否继续执行。

**完成标准**

任务运行到一半重启服务后，能够恢复已保存状态；不会因为“重新请求一次”重复创建草稿。说明摘要丢失信息时如何发现和补救。

可在实现时参考[LangGraph持久化与状态编排概览](https://docs.langchain.com/oss/javascript/langgraph/overview)；框架只是实现方式之一。

### 3.4 MCP｜P0

**学习内容**

- 理解Host、Client、Server及tools、resources、prompts的职责。
- 掌握一个本地连接方式，再了解远程连接方式；以所用SDK支持的协议版本为准。
- 实现工具发现、调用、输入校验、错误返回和访问控制。
- 让Agent通过MCP连接你的工具服务，并记录调用结果。
- 能区分MCP协议、模型工具调用和你的业务执行逻辑。

**完成标准**

自行实现一个研发知识MCP Server，提供文档检索和工单查询；能从一个Client正常发现并调用，权限不足或参数错误时返回明确结果。

学习入口：[MCP官方架构](https://modelcontextprotocol.io/docs/learn/architecture)、[官方SDK列表](https://modelcontextprotocol.io/docs/sdk)。针对你当前背景，可优先选TypeScript SDK。

### 3.5 Workflow、DAG与可恢复执行｜P0基础，P1可视化

**学习内容**

- 区分固定代码路径的Workflow与由模型动态选择步骤的Agent。
- 学会顺序、条件路由、并行、汇总，以及节点输入输出契约。
- 保存节点状态和产物，处理失败重试、恢复、取消与人工介入。
- 前端负责展示执行进度，执行状态由服务端维护。
- 在可视化编排中表达依赖关系，而不只是画一组连线。

**完成标准**

构建“读取工单 → 检索文档 → 形成方案 → 人工检查 → 输出草稿”的流程；失败节点可重试，完成节点不重复执行。

架构概念可读[Anthropic关于Workflow与Agent的说明](https://www.anthropic.com/research/building-effective-agents)；该文章较早，适合学习基本模式，具体API以当前官方文档为准。状态编排可任选[LangGraph TypeScript](https://docs.langchain.com/oss/javascript/langgraph/overview)等实现，先解释清楚自己的状态机。

### 3.6 Multi-Agent｜P1

**学习内容**

- 只在可分解的任务上引入角色分工，例如资料检索、方案生成和结果检查。
- 为子任务定义输入、输出、来源与成功条件。
- 处理信息交接、冲突、重复劳动、共享状态和预算。
- 对比单Agent、固定Workflow和多Agent的效果、时间及调用量。

**完成标准**

同一批任务分别运行单Agent和多Agent版本。给出多Agent在哪些任务上有帮助、在哪些任务上增加成本，以及产生差异的原因。

不要用“角色数量多”作为项目完成标准。可结合[Agent架构模式](https://www.anthropic.com/research/building-effective-agents)设计实验。

### 3.7 评测、Benchmark与失败分析｜P0

**学习内容**

- 建立固定输入、预期产物、评分规则和数据版本。
- 将任务完成率、工具选择／参数正确率、事实与来源一致性分别测量。
- 记录端到端时延、首次响应时间、工具耗时和实际API用量。
- 用程序判断能确定验证的结果；开放式回答再结合人工评分或经过校准的模型评分。
- 改Prompt、工具、模型或流程时跑同一批回归任务；保留未用于调优的测试集。

**完成标准**

先自建50个练习案例：30个常规任务、10个异常任务、10个权限或恶意内容案例。报告各类结果、代表性失败和修复前后变化。50条是练习规模，不是生产系统充分验证的证明。

可以使用[Promptfoo官方工具](https://www.promptfoo.dev/docs/intro/)管理评测，也可以先用脚本和JSON数据集实现，重点是结果可复现。

### 3.8 LLM网关、监控、部署与沙盒｜P0能交付，P1平台化

**学习内容**

- 抽象模型请求、响应、错误及用量信息；增加模型路由、并发限制和降级策略。
- 区分可重试错误与不可重试错误，控制重试次数；切换模型后检查结构化输出与工具兼容性。
- 用任务ID关联模型调用和工具调用，记录耗时、错误、模型与Prompt版本。
- 使用数据库保存任务，按需增加队列与缓存；能通过容器启动完整应用。
- 编码Agent或可执行工具需要受限的文件、进程、网络与资源环境，并提供超时和终止能力。

**完成标准**

演示模型超时、工具故障、服务重启与用户取消后的系统行为。输出调用链与失败原因。只记录真实返回的用量；缺失字段标为未知。

可观测性概念参考[OpenTelemetry Traces官方文档](https://opentelemetry.io/docs/concepts/signals/traces/)。A10的平台职责还涉及Go、数据库和容器能力，不能用一个模型API演示替代其后端经验要求。

### 3.9 AI产品前端｜P0，你最容易形成优势的部分

**学习内容**

- 设计任务事件：创建、执行中、等待确认、完成、失败、取消。
- 分别处理文本增量、工具开始／结束、结构化产物和错误事件。
- 处理流式内容的分块渲染、Markdown与代码块、列表性能及滚动。
- 重连后按事件ID或任务状态恢复；前端停止显示与服务端停止执行要保持一致。
- 展示任务摘要、工具记录、证据和结果，给用户明确的重试与修改入口。

**完成标准**

做一个Agent工作台：用户可查看任务进度、检查工具结果、取消任务、恢复连接、修改草稿。刷新页面后仍能看到真实任务状态。

这些是基于前端职责的学习展开；现有JD未全部明示。实现选择可参考[AI SDK Core与UI官方说明](https://ai-sdk.dev/docs/introduction)，同时理解底层HTTP流和事件契约。

### 3.10 AI Coding、Skill与交付提效｜P0，整理已有经验

**学习内容**

- 将需求、验收条件、项目约束、上下文和工具组织成可复用研发流程。
- 让Agent参与代码生成、排错、测试、重构和文档；保留关键人工判断。
- 检查生成代码的正确性、依赖、边界条件、可维护性及回归风险。
- 记录任务类型、人工耗时、返工、测试与最终交付，解释统计口径。
- 区分业务工具、项目Skill、插件和Workflow各自承担的作用。

**完成标准**

整理两类你做过的实际任务：一个功能交付、一个复杂缺陷修复。能说明Agent完成了什么、你纠正了什么、如何验证，以及效率结论能支持到什么范围。没有对照数据时，给出可核实的绝对结果，不编造提效比例。

这是F1转载中明确关注的能力；A1公开摘要也重视Agent参与交付。具体证据见第7节岗位表。

### 3.11 RAG与知识整合｜P1补充，不冒充本批高频硬要求

**学习内容**

- 理解文档接入、清洗、切块、Embedding、检索、重排和引用的职责。
- 分别验证检索是否找到正确材料、回答是否忠于材料。
- 设计数据更新、删除、版本与权限过滤。
- 能解释何时直接查数据库或调用业务接口更合适。
- 缺乏证据时返回不足信息；不能把外部文档中的指令当成系统指令。

**完成标准**

做一个带引用的研发知识问答；用户只能检索有权限的材料。对命中、漏检、过期、冲突和无答案案例分别分析。

概念与实现分层可参考[LangChain官方Retrieval文档](https://docs.langchain.com/oss/python/deepagents/retrieval)。A12的知识整合职责可作为应用场景，但现有摘要不足以证明它指定了这套技术。

### 3.12 代码生成Agent｜P1专项，对应A3、A8

**学习内容**

- 获取必要的代码上下文、定位文件和依赖。
- 生成变更、展示diff、运行构建与有意义的测试。
- 根据可观察的报错继续修复，限制循环次数。
- 使用隔离工作区与执行环境，保留输入、变更和验证产物。
- 用功能是否完成、构建测试结果和人工审查衡量效果。

**完成标准**

给定一份小型示例仓库和明确任务，Agent能提交可检查的补丁与验证报告；失败时输出具体阻塞信息，不能只声明“已完成”。

### 最小版本：先做这些

- 草稿可以修改，写入动作有明确状态和幂等控制。
- 用户能取消；页面刷新和服务重启后，结果与任务状态不丢失。

### 项目完成时应交付的材料

1. **可运行说明**：依赖、配置、示例数据、启动方式与已知限制；不要把密钥放入仓库。
2. **设计说明**：模型、工具、MCP、任务状态、数据保存和权限分别在哪里实现。
3. **功能演示**：至少包含一个正常任务，以及工具失败、取消、中断恢复等场景。
4. **评测报告**：案例来源、数据版本、评分方法、结果和失败分类；对比一次修改前后的表现。
5. **技术取舍记录**：为什么选单Agent或Workflow，多Agent在哪些情况下值得使用。
6. **AI Coding记录**：Agent参与了什么，你负责了哪些设计、审查和问题定位。
7. **真实能力边界**：明确哪些数据为模拟、哪些故障为注入、哪些结果经过实际运行，避免将学习演示描述成生产经验。

## 9. 可以直接从今天开始的三件事
