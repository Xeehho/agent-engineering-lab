# 求职能力与证据路线

主攻方向：AI 应用全栈；保留 AI 前端的任务交互、复杂状态与产品理解优势。目标筛选条件是北京、月薪不低于 30k。以下是课程训练口径，不是薪资保证或招聘公司统计。

## 需要交出的作品

主作品为“研发知识与工单 Agent 工作台”，按同一业务纵向扩展，避免做多个只展示聊天框的玩具项目。

|里程碑|用户可见价值|工程证据|课程|
|---|---|---|---|
|A 可信分诊|输入后得到可验证分类与摘要，失败能解释|契约、取消、流式状态与故障回归|01|
|B 受控工具助手|检索与读取后生成草稿，确认后执行有限写入|工具参数/权限、预算、幂等与注入拒绝|02–03|
|C 可恢复工作台|长任务排队、暂停确认、刷新/重启恢复|SQL、事务/竞争、队列、租约、React 竞态|04|
|D 有证据的知识问答|引用可回查，无答案不编造|数据版本、检索/重排、权限、分层评测|05|
|E 可衡量交付|新版本可比较，错误可追踪，可回滚|架构对照、评测、Trace、容量、部署、真实模型|06–07|
|F 求职材料|别人能复现、看演示、追问代码|README、架构图、ADR、脱敏结果、简历段|08|

教材提供机制示例与任务约束；学习者需要完成项目实现。不能把浏览器数组过滤说成向量库生产检索，把 Map 去重说成分布式恰好一次，把合成分数说成真实模型效果。

## 必须准备的证据包

- 一页项目说明：用户问题、价值路径、个人职责、技术取舍。
- 可从干净环境启动的代码与锁文件；运行命令、迁移、配置和密钥说明。
- 一张数据流/权限/失败路径架构图；至少两份 ADR，说明替代方案与取舍。
- 一份分层评测：样本、规则、版本、实际结果、失败、成本与延迟口径。
- 三份故障复盘：复现、证据、定位、最小修复、回归、未验证项。
- 真实模型接入记录；没有授权服务时留待验证，毕业前补齐。
- 三分钟讲解与十分钟演示；至少包含一次取消、一次拒绝与一次恢复。
- 个人贡献与 AI 协作记录；你本人能够阅读与解释关键实现。

## 公开面试训练题

这些是练习题，不是阶段正式考试。

1. HTTP 200、合法 JSON、字段合法、业务正确为什么不能互相替代？
2. 取消浏览器请求后，如何验证模型调用真正停止？不能直接推出什么？
3. 模型建议调用一个工具，权限、参数和副作用分别由谁负责？
4. 创建动作成功但响应丢失，重试为何可能重复？怎样设计幂等？
5. MCP 与普通函数调用各解决什么？如何证明真实互通？
6. worker 崩溃在写入和 checkpoint 之间，恢复如何避免重复？
7. 相关性很高但无权限的文档应在哪些路径被排除？
8. 正确证据没召回与已经召回却答错，怎样分别定位？
9. 多 Agent 的收益如何与模型、数据和 Prompt 变化区分？
10. 没有 usage 时费用面板怎样显示？哪些日志必须脱敏？
11. 备用模型能接通但输出契约不同，降级如何验证？
12. 项目用了大量 AI Coding，你怎样证明本人能判断、阅读和排错？

每题练习“结论 → 具体场景 → 实现边界 → 验证证据 → 代价/未验证项”，不背模板长答案。

## 简历项目段的写法

使用“为谁解决什么 → 个人负责什么 → 怎样实现与取舍 → 在什么条件下验证”。

示例骨架（请用真实信息替换）：

“个人 AI 应用工程项目：面向研发工单与知识查询，负责 React 任务工作台和应用服务。实现结构化契约、受限工具调用、任务恢复及带引用问答；按固定样本分别验证检索、回答、权限和取消路径。真实模型/数据库/部署的验证环境与结果见项目记录。”

不要直接填入未经实测的“准确率提升 40%”“支持百万用户”“节约 90% 成本”。如有真实数据，附样本数、环境、基线、日期和来源。个人/课程项目不写成雇佣经历。

## 面试演练节奏

第一轮：本人三分钟讲解，老师追问两段关键代码。第二轮：十分钟产品演示与一个陌生故障。第三轮：四十五分钟系统设计，先问约束再画方案。每轮只针对暴露缺口补学，不用重复做已经用证据证明的内容。

达到作品集准备标准后可以开始有针对性投递，同时继续补弱项；不需要把所有研究或平台方向都学完才行动。是否达到目标岗位水平，要由实际项目、本人答辩与招聘反馈持续校准。
