## 1. 先判断问题是否需要分工

“根据工单和版本文档写回复草稿”有两个独立读取，可以并行；草稿必须等它们完成。把检索者、写作者、审阅者命名为三个角色并不自动提升质量。若它们共享同一错误证据，增加角色可能只增加费用和互相附和。

路由适用于按任务特征选择固定处理器；workflow 适用于已知依赖；动态 Agent 适用于需要根据中间结果探索路径。先用最简单可测的流程建立基线，再用同一数据集验证复杂度带来的净收益。

## 代码阅读：先验证依赖，再执行工作

### 图里每个字段的含义

节点包含id、deps和run：id用于关联，deps列出必须先完成的节点，run接收依赖结果。ticket与docs互不依赖，draft同时依赖它们，因此前两项可以并行，最后一项必须等待。

workflow 输入节点列表与全局节点/并发上限，输出 results 与 waves。它是确定性编排，不是模型自动规划；给函数起一个角色名不会改变这个事实。

### 为什么先做一遍不执行的遍历

validatedNodeIds 只记录依赖图能否逐层推进，不调用任何run。第一轮找到没有依赖的节点，后续轮次找到所有依赖都已验证的节点。如果还没覆盖全部节点，却找不到下一层，就存在环。

|图|验证过程|是否执行|
|---|---|---|
|ticket、docs→draft|先两项，再draft|允许|
|a依赖b，b依赖a|第一轮没有可推进节点|拒绝，执行数0|
|a依赖不存在的节点|建图时就发现缺失|拒绝|

### 结果怎样送给下一步

completedResults 保存已完成产物；Object.fromEntries 把依赖ID和值组装成对象。因此draft收到的不是全部聊天历史，而是 {ticket,docs}。每波用 Promise.all 等待，最多启动 maxParallel 项。

这份调度器有波次屏障，且 Promise.all 不自动取消其他任务。需要持续填充并发槽、失败取消和费用预留时，应在明确需求后扩展，不把课堂版本写成生产调度器。

### 带提示的练习

先手画依赖图，再预测waves。把maxParallel改为1，观察顺序。让ticket失败而docs持续等待，指出主Promise结束后哪些工作可能还在运行，再接取消信号验证清理。

## 2. 建一张能拒绝环的依赖图

### 完整实操文件：S6-L01.mjs

~~~js file=S6-L01.mjs
// 先验证依赖图，再分波执行；本例不会自动取消 Promise.all 中的其他任务。
import assert from "node:assert/strict";
// 输入节点列表与并发预算，返回所有结果和每波执行记录。
async function workflow(nodes, { maxNodes = 8, maxParallel = 2 } = {}) {
  if (
    !Number.isInteger(maxNodes) ||
    !Number.isInteger(maxParallel) ||
    nodes.length > maxNodes ||
    maxParallel < 1
  ) {
    throw new Error("BUDGET");
  }
  const nodeById = new Map(nodes.map((node) => [node.id, node]));
  if (nodeById.size !== nodes.length) {
    throw new Error("DUPLICATE");
  }
  for (const node of nodes) {
    for (const dependencyId of node.deps) {
      if (!nodeById.has(dependencyId)) {
        throw new Error("MISSING_DEP");
      }
    }
  }
  const pendingNodeIds = new Set(nodeById.keys()),
    completedResults = new Map(),
    waves = [];
  // 先只验证图，任何环都在执行副作用之前拒绝。
  const validatedNodeIds = new Set();
  while (validatedNodeIds.size < nodes.length) {
    const readyNodes = nodes.filter(
      (node) =>
        !validatedNodeIds.has(node.id) &&
        node.deps.every((dependencyId) => validatedNodeIds.has(dependencyId)),
    );
    if (!readyNodes.length) {
      throw new Error("CYCLE");
    }
    readyNodes.forEach((node) => validatedNodeIds.add(node.id));
  }
  while (pendingNodeIds.size) {
    const readyNodes = nodes
      .filter(
        (node) =>
          pendingNodeIds.has(node.id) &&
          node.deps.every((dependencyId) => completedResults.has(dependencyId)),
      )
      .slice(0, maxParallel);
    waves.push(readyNodes.map((node) => node.id));
    const completedWave = await Promise.all(
      readyNodes.map(async (node) => {
        const dependencyResults = Object.fromEntries(
          node.deps.map((dependencyId) => [
            dependencyId,
            completedResults.get(dependencyId),
          ]),
        );
        return [node.id, await node.run(dependencyResults)];
      }),
    );
    for (const [nodeId, value] of completedWave) {
      completedResults.set(nodeId, value);
      pendingNodeIds.delete(nodeId);
    }
  }
  return { results: Object.fromEntries(completedResults), waves };
}
const nodes = [
  { id: "ticket", deps: [], run: async () => ({ id: "T-42", issue: "白屏" }) },
  { id: "docs", deps: [], run: async () => ({ version: 2, fix: "升级依赖" }) },
  {
    id: "draft",
    deps: ["ticket", "docs"],
    run: async ({ ticket, docs }) => ticket.issue + "：" + docs.fix,
  },
];
const workflowResult = await workflow(nodes);
assert.deepEqual(workflowResult.waves, [["ticket", "docs"], ["draft"]]);
assert.equal(workflowResult.results.draft, "白屏：升级依赖");
let executedNodeCount = 0;
await assert.rejects(
  workflow([
    { id: "a", deps: ["b"], run: async () => executedNodeCount++ },
    { id: "b", deps: ["a"], run: async () => executedNodeCount++ },
  ]),
  /CYCLE/,
);
assert.equal(executedNodeCount, 0);
await assert.rejects(
  workflow([{ id: "a", deps: ["missing"], run: async () => 1 }]),
  /MISSING/,
);
await assert.rejects(
  workflow([
    {
      id: "a",
      deps: [],
      run: async () => {
        throw new Error("UPSTREAM");
      },
    },
  ]),
  /UPSTREAM/,
);
console.log("waves=ticket+docs -> draft; cycle rejected before execution");
console.log(
  "missing dependency and upstream failure surfaced; no model agents executed",
);
~~~

missing dependency and upstream failure surfaced; no model agents executed
~~~

**选做本地验证：**运行 npm run tutorial -- S6-L01。依赖图先验证再执行，避免执行了一半才发现环。每一波最多启动 maxParallel 个，简单但存在屏障：一条慢任务会阻挡下一波，本例没有实现持续填满并发槽的调度器。

## 3. 并行、预算和取消要一起考虑

Promise.all 在一个任务失败后拒绝，但不会自动取消其他任务。真实版本必须把任务级 AbortSignal 传给每个子工作，失败时按策略取消并清理；不能因为主 Promise 结束就认为所有费用停止。

全局预算要在子任务启动前预留，完成后结算。每个角色各有“最多10步”，四个角色可能消耗40步，不能当全局10步。递归分解要限制深度、节点总数、并发和总期限，防止角色不断创建角色。

最短总耗时由关键路径与资源限制决定，所有子任务时长相加是总工作量，不是并行墙钟时长。S6-L03 会用配对样本计算差异。

## 故障练习与项目迁移

加一个依赖不存在的节点，确认没有任何工作执行。让 ticket 失败、docs 长时间等待，观察 Promise.all 的取消缺口，再接 S1 的取消机制修复。给每个节点标预计费用，写全局预留与超额拒绝测试。

项目练习：同一任务分别写确定性流程、单 Agent 和有依据的多角色方案。提交依赖图、权限边界、预算、失败传播与基线结果。若没有真实模型对照，只能报告编排机制，不宣称多 Agent 提升准确率。

## 单页速记

- 先选路由、workflow 或动态探索，再决定角色数。
- 依赖先验证，独立节点才可并行。
- Promise.all 不负责取消其余工作。
- 全局预算、关键路径和失败策略必须跨角色统一。
