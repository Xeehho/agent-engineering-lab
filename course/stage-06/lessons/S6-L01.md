# S6-L01｜路由与分工：先证明需要多 Agent

教材状态：已编写，可提前学习；不代表学习者已作答或通过考试。
阶段：06 多 Agent 与架构取舍。先修：02 的有限循环，05 的证据包，07 评测可交叉学习。
建议投入：35–60 分钟 + 项目练习。允许 AI 协作，要求本人解释与验证。

## 本课目标

- 从单体基线开始
- 定义分工单位与路由契约
- 控制上下文和权限

## 1. 从单体基线开始

一个助手同时检索、拟方案和校验看起来很忙，但拆成三个 Agent 并不必然更好。先用单 Agent 或确定性 Workflow 跑相同任务，找到上下文冲突、并行任务或专业约束的具体瓶颈。没有基线，就无法判断多角色是提升质量还是增加延迟。

## 2. 定义分工单位与路由契约

按可独立验收的任务划分，例如检索返回证据包、方案生成返回结构化草稿、校验返回逐条问题。仅把 Prompt 改成“你是专家 A/B”却共享全部上下文，可能既没有隔离也没有明确产物。路由依据应可追踪，无法分类时有 fallback，而不是盲目派给所有 Agent。

## 3. 控制上下文和权限

每个角色只接收完成任务所需的信息与工具。总预算需覆盖所有分支、重试和汇总；子 Agent 结束不等于全任务正确。并行工作只有独立时才自然成立，依赖上一步证据的任务不能靠同时启动消除依赖。

## 动手验证

先写预测，再运行，最后修改一个条件观察反例。不要把网页机制演示当成真实基础设施验证。

## 实验：先按可验收任务路由

先预测输出，再运行并修改一个条件。这是教学用的 JavaScript 机制演示，不是真实模型、数据库、协议 SDK 或生产系统。

~~~js
const tasks=[{type:"retrieve",id:1},{type:"draft",id:2},{type:"unknown",id:3}];
const routes={retrieve:"证据检索",draft:"草稿生成"};
for (const task of tasks) console.log(task.id,routes[task.type] ?? "人工澄清/受控回退");
~~~

观察方向：未知任务走明确回退；这是确定性路由，不是真实多模型协作。

提示：每条路由要有输入输出，而不仅是角色名字。

## 本课项目任务

S6-T1：实现一种清晰分工的候选方案，保留单体基线，记录角色契约与路由失败案例。

先写你预期的行为，再让 AI 协作实现。提交具体 commit、输入、预期、实际、命令、失败复盘与未验证项；本教材不代做学习者项目。

## 本阶段验收边界

- 每个角色有可验收输入/输出与最小权限
- 交接携带来源、版本、未解决项和副作用状态
- 冲突回退与总预算有程序上限
- 单 Agent/Workflow/多 Agent 同集对照，失败、费用和延迟不漏算
