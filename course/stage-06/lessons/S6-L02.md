# S6-L02｜交接、证据包与冲突处理

教材状态：已编写，可提前学习；不代表学习者已作答或通过考试。
阶段：06 多 Agent 与架构取舍。先修：02 的有限循环，05 的证据包，07 评测可交叉学习。
建议投入：35–60 分钟 + 项目练习。允许 AI 协作，要求本人解释与验证。

## 本课目标

- 交接的是任务契约
- 识别共享上下文的污染
- 把冲突变成流程分支

## 1. 交接的是任务契约

一个角色把结果交给另一个角色时，要提供任务 ID、输入版本、证据引用、已完成动作、未解决问题与可继续执行的条件。只说“已经检查过了”会丢失来源、假设和失败。结构化交接仍需接收方校验，不能自动提升可信度。

## 2. 识别共享上下文的污染

多个角色共享同一错误证据时，即使都赞同也不构成独立验证。外部文本中的恶意指令可能沿交接摘要传播；摘要应保留来源与信任级别。校验角色最好能回查原证据，不能只看到生成角色的结论。

## 3. 把冲突变成流程分支

检索认为文档 A 最新，校验发现版本已过期，应用应按规则重新检索、暂停或请求人工确认，而不是让角色投票。冲突可能来自规则不清、数据不一致或模型误读，先定位证据层。设置最大往返次数，避免“请再检查”成为无限循环。

## 动手验证

先写预测，再运行，最后修改一个条件观察反例。不要把网页机制演示当成真实基础设施验证。

## 实验：赞成票不是独立证据

先预测输出，再运行并修改一个条件。这是教学用的 JavaScript 机制演示，不是真实模型、数据库、协议 SDK 或生产系统。

~~~js
const reports=[{agent:"A",source:"doc-old",claim:"可执行"},{agent:"B",source:"doc-old",claim:"可执行"}];
console.log("赞同数:",reports.length);
console.log("不同来源数:",new Set(reports.map(x=>x.source)).size);
console.log("同一旧证据的两次赞同不等于独立核验");
~~~

观察方向：两个角色只使用同一来源，不能据此声称相互独立验证。

提示：检查证据来源是否重合，而不只是角色是否不同。

## 本课项目任务

S6-T2：实现交接包校验、来源追溯和冲突回退；注入同源误判与过期证据案例。

先写你预期的行为，再让 AI 协作实现。提交具体 commit、输入、预期、实际、命令、失败复盘与未验证项；本教材不代做学习者项目。

## 本阶段验收边界

- 每个角色有可验收输入/输出与最小权限
- 交接携带来源、版本、未解决项和副作用状态
- 冲突回退与总预算有程序上限
- 单 Agent/Workflow/多 Agent 同集对照，失败、费用和延迟不漏算
