# S6-L03｜协作评测：质量、延迟与成本

教材状态：已编写，可提前学习；不代表学习者已作答或通过考试。
阶段：06 多 Agent 与架构取舍。先修：02 的有限循环，05 的证据包，07 评测可交叉学习。
建议投入：35–60 分钟 + 项目练习。允许 AI 协作，要求本人解释与验证。

## 本课目标

- 把比较条件固定
- 统计端到端成本
- 设定保留与回退准则

## 1. 把比较条件固定

对同一批任务、数据快照和评分口径比较单体与多角色，记录模型、Prompt、工具、并发和预算。架构 A 用强模型、架构 B 用弱模型会混淆结论。必要时分别控制模型能力和架构变化，不把所有变化绑成一个“升级”。

## 2. 统计端到端成本

并行能降低某些等待时间，但总工作量和费用可能增加。记录每个分支的模型、工具与重试开销，以及等待人工的时间。P95 是延迟分布指标；几条样本算出的分位数不具有稳定生产代表性。失败与超时也不能悄悄从统计中删去。

## 3. 设定保留与回退准则

在实验前说明最低质量收益、最大延迟/费用、关键错误上限与预算终止行为。若多角色没有稳定收益，就回到简单方案，并把这一取舍写进 ADR。可解释地拒绝复杂架构，同样是工程能力。

## 动手验证

先写预测，再运行，最后修改一个条件观察反例。不要把网页机制演示当成真实基础设施验证。

## 实验：并行变快，却更贵

先预测输出，再运行并修改一个条件。这是教学用的 JavaScript 机制演示，不是真实模型、数据库、协议 SDK 或生产系统。

~~~js
const variants=[{name:"单体",quality:8,cost:2,latency:900},{name:"多角色",quality:8,cost:6,latency:650}];
console.table(variants);
console.log("合成数值：同等质量下，是否值得增加费用取决于事先约定的目标");
~~~

观察方向：质量相同，延迟下降但费用上升。它只是取舍示例，不是实测模型结论。

提示：先明确业务目标，再看哪个指标值得付费。

## 本课项目任务

S6-T3：提交同集架构对照报告与 ADR，含失败、超时、总费用、延迟和选择理由；Mock 结果仅算机制验证。

先写你预期的行为，再让 AI 协作实现。提交具体 commit、输入、预期、实际、命令、失败复盘与未验证项；本教材不代做学习者项目。

## 本阶段验收边界

- 每个角色有可验收输入/输出与最小权限
- 交接携带来源、版本、未解决项和副作用状态
- 冲突回退与总预算有程序上限
- 单 Agent/Workflow/多 Agent 同集对照，失败、费用和延迟不漏算
