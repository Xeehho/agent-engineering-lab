# S7-L04｜真实模型接入与可复现证据

教材状态：已编写，可提前学习；不代表学习者已作答或通过考试。
阶段：07 评测、观测与生产交付。先修：01–05 项目基础；可提前读评测与 trace。
建议投入：35–60 分钟 + 项目练习。允许 AI 协作，要求本人解释与验证。

## 本课目标

- 先实现受控适配层
- 保留可复现的最小实测
- 把效果与工程分别验收

## 1. 先实现受控适配层

内部模型接口应表达输入、期限、取消与完成结果，再把一家服务的请求/响应映射进去。不同服务在结构化输出、工具、流式、拒答与 usage 上存在差异，要按真实版本文档检查。Mock 很适合故障注入，但不能代替 SDK/HTTP 互通与真实内容质量。

## 2. 保留可复现的最小实测

仅使用已经授权的服务与本机环境变量；密钥不进入仓库、网页代码、截图或日志。先跑少量正常/失败案例，记录日期、模型标识、Prompt 版本、输入、脱敏输出、完成状态、用量和实际错误。再比较离线契约与真实响应有什么差异。

## 3. 把效果与工程分别验收

一次 API 200 证明互通的一部分，字段合法证明契约的一部分，业务效果仍需固定样本。给预算、重试和费用设置上限，取消后的计费不能凭本地 UI 推断。没有授权 API 时明确 live_pending，不编造模型调用、token 数或线上准确率。

## 动手验证

先写预测，再运行，最后修改一个条件观察反例。不要把网页机制演示当成真实基础设施验证。

## 实验：真实接入证据是否完整

先预测输出，再运行并修改一个条件。这是教学用的 JavaScript 机制演示，不是真实模型、数据库、协议 SDK 或生产系统。

~~~js
const record={provider:"mock",model:null,promptVersion:"v1",usage:null,output:"示意结果"};
console.log({liveVerified:record.provider==="live" && Boolean(record.model) && record.usage!==null});
console.log("缺少真实接入不能靠改标签补齐证据");
~~~

观察方向：false。即使把标签改成 live，也需要实际可核验的调用证据，布尔检查不是防伪认证。

提示：元数据检查只能发现缺项，不能自行证明其真实性。

## 本阶段验收边界

- 固定分层样本、评分器校准、关键错误发布门槛
- 模型/工具/检索/状态可关联，usage 未知不填零
- 干净环境启动、迁移、限流、降级、回滚和故障演练
- 已授权真实 API 的互通/完成/契约/效果分别验证；无 Key 留 live_pending
