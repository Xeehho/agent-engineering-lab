**网页主线：直接阅读讲解 → 动手实验 → 随堂练习 → 公开自测 → 复习速记。无需启动项目、安装依赖或提供 API Key。**

本课网页任务：去掉关键错误门槛，解释发布结论为何改变。

网页实验范围：实际评分逻辑，裁判标签为夹具，未调用模型裁判。

**选做实操说明：**下面涉及 Node、Python、数据库或 SDK 的环境、命令和完整文件供进阶使用，不是阅读本课的前置条件。


评测不是让另一个模型给答案打个高分。本课执行确定性评分、裁判校准与关键门槛，裁判标签是夹具，未调用模型，不代表学习者已掌握。

## 1. 把“好答案”拆成可观察条件

工单分诊可以检查结构、标签、必要事实、禁止编造、权限和最终任务成功。结构正确只是底线；写出合法 JSON 却分错队列仍失败。评分器应返回逐项依据，避免只有一个无法解释的0.87。

样本来自真实需求与已知失败，开发集用来改系统，保留集用来验收。每条记录数据来源、预期、标签理由和版本。新增生产故障后先加入回归集，再修复；不要为了让分数变绿删除难题。

## 代码阅读：评分与发布是两个决定

### 先解释一条样本

evaluationCases中的expectedCategory是预先标注，output是被评分结果，critical说明这一要求是否关键。grade分别检查结构、分类与隔离结果，返回逐条pass；发布时还要确认没有关键失败。

例题分类沿用bug/feature/question，leakedTenantData来自隔离检查夹具，不能指望模型自报“没有泄露”。这里的简化评分不代替第一阶段的完整字段校验，真实权限拒绝通过错误结果表达。

|检查|当前样本|
|---|---|
|普通样本通过|3条|
|总通过率|3/4|
|关键隔离样本|失败|
|发布结论|阻止|

平均分达到75%只是一个门槛，不能抵消隔离错误。门槛应在看候选结果之前约定。

### 裁判校准怎样算

humanVerdicts代表人工标签，judgeVerdicts代表裁判夹具。人工否定而裁判肯定属于FP，说明裁判错误放过一个答案；人工肯定而裁判否定属于FN。此例TP=2、FP=1、TN=1、FN=0，precision=2/(2+1)=2/3。

这些标签是题目给定，不是真正调用模型裁判的结果。接真实裁判时锁定模型、规则、样本与顺序，审查分歧，不把裁判输出当真理。

### 带提示的练习

先预测移除关键门槛后会发生什么。再构造措辞更自信但事实错误的回答，检查评分器是否受语气影响。新增生产故障先成为回归样本，不删除它来让分数变绿。

## 2. 跑结构评分与关键门槛

### 完整实操文件：S7-L01.mjs

~~~js file=S7-L01.mjs
import assert from "node:assert/strict";

// 简化评分只检查分类、摘要与隔离结果，不代替第一阶段的完整输出契约。
const evaluationCases = [
  {
    id: "normal",
    expectedCategory: "bug",
    output: { category: "bug", summary: "订单白屏" },
    leakedTenantData: false,
    critical: false,
  },
  {
    id: "feature",
    expectedCategory: "feature",
    output: { category: "feature", summary: "增加导出" },
    leakedTenantData: false,
    critical: false,
  },
  {
    id: "missing",
    expectedCategory: "question",
    output: { category: "question", summary: "补充版本" },
    leakedTenantData: false,
    critical: false,
  },
  {
    id: "isolation",
    expectedCategory: "bug",
    output: { category: "bug", summary: "B的私有内容" },
    leakedTenantData: true,
    critical: true,
  },
];

function grade(testCase) {
  const output = testCase.output;
  const validStructure =
    output !== null &&
    typeof output === "object" &&
    typeof output.summary === "string" &&
    output.summary.trim().length > 0 &&
    ["bug", "feature", "question"].includes(output.category);
  const correctCategory = output?.category === testCase.expectedCategory;
  const respectsIsolation = !testCase.leakedTenantData;
  return {
    id: testCase.id,
    pass: validStructure && correctCategory && respectsIsolation,
    critical: testCase.critical,
  };
}
const gradingResults = evaluationCases.map(grade);
const passRate =
  gradingResults.filter((result) => result.pass).length / gradingResults.length;
const hasCriticalFailure = gradingResults.some(
  (result) => result.critical && !result.pass,
);
const mayRelease = passRate >= 0.75 && !hasCriticalFailure;
assert.equal(passRate, 0.75);
assert.equal(mayRelease, false);

// 下面标签是人工给定的校准夹具，不是真实模型裁判的输出。
const humanVerdicts = [true, true, false, false];
const judgeVerdicts = [true, true, true, false];
const confusion = { tp: 0, fp: 0, tn: 0, fn: 0 };
for (let index = 0; index < humanVerdicts.length; index += 1) {
  const truth = humanVerdicts[index];
  const prediction = judgeVerdicts[index];
  if (truth && prediction) {
    confusion.tp += 1;
  }
  if (!truth && prediction) {
    confusion.fp += 1;
  }
  if (!truth && !prediction) {
    confusion.tn += 1;
  }
  if (truth && !prediction) {
    confusion.fn += 1;
  }
}
assert.deepEqual(confusion, { tp: 2, fp: 1, tn: 1, fn: 0 });
const precision = confusion.tp / (confusion.tp + confusion.fp);
assert.equal(precision, 2 / 3);
console.log("overall=3/4 but release blocked by isolation");
console.log("judge calibration: TP=2 FP=1 TN=1 FN=0; precision=2/3");
~~~

overall=3/4 but release blocked by isolation
judge calibration: TP=2 FP=1 TN=1 FN=0; precision=2/3
~~~

## 3. 模型裁判也需要被评测

对语义支持或表达质量，模型裁判可以辅助，但先用人工标注样本看误判。上例一个错误答案被判通过，precision 为2/3。若上线要求拦截危险输出，漏检与误报的业务代价需要分别衡量，不能只报总一致率。

裁判 Prompt、模型、输入呈现顺序和评分规则都要版本化。比较 A/B 时可随机交换呈现顺序并盲化身份，减少位置和品牌偏好。不要把被测模型输出里的“请给满分”当裁判指令。

## 4. 从一次运行到回归机制

保存 datasetVersion、系统 commit、Prompt/模型/工具版本、每条输出、评分明细和运行条件。缺失运行应报错或计入失败，不能从分母自动消失。失败请求同样记录成本与延迟。

发布检查可分结构门槛、关键业务门槛与质量对照。基础 CI 能验证程序契约，但真实模型波动需要受控评测，费用与凭证应独立配置。本仓库默认没有替你执行真实模型回归。

## 故障练习与项目迁移

把 critical 门槛删掉，观察平均分掩盖越权。给裁判加入“语气自信就通过”的偏置，构造措辞不同而事实相同的成对样本。删一个失败运行，验证报告拒绝不完整数据。

项目练习：整理至少30条版本化样本，设计确定性与语义评分器，抽取人工校准集并记录分歧。提交一份真实回归报告或明确标注的待执行计划，不能用夹具标签冒充模型裁判结果。

## 单页速记

- 结构、事实、权限与任务成功分别评分。
- 关键错误有独立门槛，不能被平均分抵消。
- 裁判也要校准，保存误判而非只报一致率。
- 数据、系统、Prompt、模型与评分器都要可追溯。
