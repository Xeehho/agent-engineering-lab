## 本课目标

- 给一次任务建立关联链
- 记录足够信息而不泄漏
- 让指标与追踪互相解释

## 1. 给一次任务建立关联链

Trace 用于关联一次操作跨组件的执行，span 记录其中的步骤和时间关系。taskId 是业务身份，traceId 是一次观测关联，二者用途不同。把 provider、检索、工具和状态更新放进可关联的执行记录，才能定位是模型慢、排队慢还是工具重试。

## 2. 记录足够信息而不泄漏

日志应有时间、任务/尝试关联、版本、步骤、结果类别和耗时。完整 Prompt 与工具返回可能含个人信息或密钥，必须脱敏、控制访问和保留期限；不是记录越多越专业。不要把本地调试日志直接放入公开作品集。

## 3. 让指标与追踪互相解释

成功率、取消率、错误类别、P50/P95 延迟、并发、队列等待和 token/费用需要明确口径。usage 缺失时应显示未知或估算，不要写成 0。费用估算记录实际模型、服务定价来源与日期；模拟值不能写成真实生产节省。

## 动手验证

先写预测，再运行，最后修改一个条件观察反例。不要把网页机制演示当成真实基础设施验证。

## 实验：有任务 ID，但哪一步慢？

先预测输出，再运行并修改一个条件。这是教学用的 JavaScript 机制演示，不是真实模型、数据库、协议 SDK 或生产系统。

~~~js
const spans=[{name:"queue",ms:500},{name:"retrieval",ms:80},{name:"model",ms:420},{name:"tool",ms:50}];
console.table(spans);
console.log("串行演示合计",spans.reduce((s,x)=>s+x.ms,0));
console.log("真实并行 span 不能简单相加当墙钟时间");
~~~

观察方向：合成串行路径中队列比模型更慢；优化前先定位实际瓶颈。

提示：时间线关系决定如何解释耗时。
