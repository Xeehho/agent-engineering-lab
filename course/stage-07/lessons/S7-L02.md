## 1. 先分清三种信号

日志记录离散事件，指标描述一群请求的统计，trace 关联一次任务中的操作与耗时。taskId 可以跨多次执行；traceId 通常对应一次链路；spanId 标识其中一次操作。不要把业务 taskId 直接当所有协议的 spanId。

一次用户任务可能并行检索文档和工单，再调用模型。只在控制台按时间打印，容易把不同请求混在一起。上下文传播让异步工作知道自己属于哪条链路。

## 代码阅读：并发任务为什么不会串 trace

### 把ID和时间读清楚

traceId关联一条执行链路，spanId标识其中一次操作，parentId指向调用它的操作。taskId是业务目标，可以跨多条trace。durationMs来自本地单调时钟测量，不是题目手填的模型耗时。

withSpan先读取父上下文，再创建当前span，使用AsyncLocalStorage.run让这个异步调用树携带对应身份。两个任务交错执行时，不会像全局变量那样互相覆盖。

### 追踪任务A和B

每个任务有一个根span，并行启动docs与ticket两个子span，因此两个任务共6个span。验证检查每个根恰好有两个孩子，孩子traceId与父相同，两条根traceId不同。

recordEvent只提取taskId、code、attempt。输入中故意放入apiKey，但允许列表没有它，所以日志中找不到密钥。若直接展开整个data，敏感内容就会被记录。

### 失败时也要记录结束

withSpan的catch把status改为error后继续抛出；finally无论成功失败都计算耗时并保存span。若只在正常返回后写记录，最需要调查的失败路径反而缺失。

当前格式是课堂自定义记录，不是OpenTelemetry exporter。接真实平台后还要验证跨HTTP传播、采样、导出、关闭flush与敏感字段治理。

### 带提示的练习

先用全局变量代替AsyncLocalStorage并增加异步交错，复现串链路。再删除finally观察失败span丢失。费用统计沿attempt累加，usage未知保持未知，不用字符串长度填token。

## 2. 实际验证并行上下文

### 完整实操文件：S7-L02.mjs

~~~js file=S7-L02.mjs
// 异步上下文负责关联；观测数据仅采用允许字段，避免整包记录敏感内容。
import assert from "node:assert/strict";
import { AsyncLocalStorage } from "node:async_hooks";
import { randomBytes } from "node:crypto";
import { setTimeout as sleep } from "node:timers/promises";
const traceStorage = new AsyncLocalStorage(),
  finishedSpans = [],
  logEntries = [];
const createRandomId = (bytes) => randomBytes(bytes).toString("hex");
// 创建当前操作并继承父链路，在 finally 记录完成或失败耗时。
async function withSpan(name, operation) {
  const parentSpan = traceStorage.getStore();
  const currentSpan = {
    traceId: parentSpan?.traceId || createRandomId(16),
    spanId: createRandomId(8),
    parentId: parentSpan?.spanId || null,
    name,
  };
  const startedAt = performance.now();
  return traceStorage.run(currentSpan, async () => {
    let status = "ok";
    try {
      return await operation();
    } catch (error) {
      status = "error";
      throw error;
    } finally {
      finishedSpans.push({
        ...currentSpan,
        status,
        durationMs: performance.now() - startedAt,
      });
    }
  });
}
// 只保留允许字段，并带上当前异步链路身份。
function recordEvent(event, eventData) {
  // 采用允许列表，不记录任意 request、headers 或原文。
  const { taskId, code, attempt } = eventData;
  logEntries.push({ ...traceStorage.getStore(), event, taskId, code, attempt });
}
// 一个任务并行创建文档和工单两个子操作。
async function runObservedTask(taskId) {
  return withSpan("task", async () => {
    recordEvent("start", {
      taskId,
      code: "START",
      attempt: 1,
      apiKey: "do-not-record",
    });
    await Promise.all([
      withSpan("docs", async () => {
        await sleep(2);
        recordEvent("read", { taskId, code: "DOCS", attempt: 1 });
      }),
      withSpan("ticket", async () => {
        await sleep(1);
        recordEvent("read", { taskId, code: "TICKET", attempt: 1 });
      }),
    ]);
  });
}
await Promise.all([runObservedTask("A"), runObservedTask("B")]);
assert.equal(finishedSpans.length, 6);
const rootSpans = finishedSpans.filter((spanRecord) => spanRecord.parentId === null);
assert.equal(rootSpans.length, 2);
assert.notEqual(rootSpans[0].traceId, rootSpans[1].traceId);
for (const rootSpan of rootSpans) {
  const childSpans = finishedSpans.filter(
    (spanRecord) => spanRecord.parentId === rootSpan.spanId,
  );
  assert.equal(childSpans.length, 2);
  assert.ok(childSpans.every((spanRecord) => spanRecord.traceId === rootSpan.traceId));
}
assert.equal(JSON.stringify(logEntries).includes("do-not-record"), false);
assert.equal(
  new Set(
    logEntries
      .filter((logEntry) => logEntry.taskId === "A")
      .map((logEntry) => logEntry.traceId),
  ).size,
  1,
);
await assert.rejects(
  withSpan("failure", async () => {
    throw new Error("EXPECTED");
  }),
  /EXPECTED/,
);
assert.equal(finishedSpans.at(-1).status, "error");
console.log("two parallel tasks: isolated traces, two children each");
console.log(
  "allowlist logs omitted key; error span closed; durations measured locally",
);
~~~

allowlist logs omitted key; error span closed; durations measured locally
~~~

## 3. 迁移到 OpenTelemetry

正式接入时使用官方 SDK 的 tracer、context propagation 和 exporter，跨 HTTP 传递采用的上下文格式，服务端创建子 span。不要只给日志加 traceId 就称已完成分布式追踪；采样、批量导出、关闭 flush 和敏感字段策略都需要验证。

记录模型调用、工具、队列等待、数据库与重试 span。Span 属性适合受控的模型版本、错误码、attempt 和计量摘要；用户原文、凭证、完整工单内容不应默认进入可广泛检索的平台。

## 4. 成本与指标的常见陷阱

输入/输出 token、缓存计量与费用分别记录来源。估算值标 estimated，服务计量标 reported，账单对账标 reconciled，不能用字符串长度冒充 token。一次任务重试三次，费用需要把三次都计算。

指标标签避免 taskId、用户原文等高基数值；这些放 trace 或受控日志。可监控任务成功率、错误类别、等待时间、p95、取消后持续工作数、预算耗尽和每成功任务成本。指标阈值要对应用户影响与响应手册。

## 故障练习与项目迁移

用全局变量替换 AsyncLocalStorage，增加异步交错，观察 A/B 链路串用。把日志改为展开整个 data，验证密钥进入记录。删除 finally，观察失败 span 缺失。

项目练习：接一个真实观测后端或本地 collector，提交一条从请求到模型/工具/数据库的完整链路、一次错误与取消链路、脱敏验证和费用口径。尚未接 exporter 时，明确报告只有本地关联实验。

## 单页速记

- 日志、指标、trace 各自回答不同问题。
- 异步与跨服务上下文需要实际传播。
- 失败也闭合 span，重试与取消后消耗也计费。
- 属性允许列表、采样与基数控制属于工程设计。
