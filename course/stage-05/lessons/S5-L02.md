# S5-L02 Embedding、向量与混合检索

这一课区分“会计算相似度”与“已经有好语义表示”。实验执行关键词基线、余弦相似度和 RRF；向量是明确标注的合成数值，未运行训练好的 embedding 模型，不代表真实语义召回，不代表学习者已掌握。

## 1. 为什么关键词与语义各有用处

用户问“款项多久退回”，文档写“退款到账时效”。语义表示可能联系它们；而工单编号 T-42、错误码 E_CONN_RESET 需要精确匹配。纯向量与纯关键词都有失败场景，先建立能解释的关键词基线，再比较混合是否值得。

Embedding 把输入映射成固定维向量，训练目标决定哪些相似性被保留。维度更大不自动更好；模型、版本、归一化、语言、输入长度与 query/document 前缀都影响结果。更换模型后，旧文档向量通常需要重建，不能把不同空间的向量直接比较。

## 2. 计算相似度并融合排名

~~~js file=S5-L02.mjs
import assert from "node:assert/strict";
function cosine(a,b) {
  if (a.length !== b.length || !a.length || [...a,...b].some(x => !Number.isFinite(x)))
    throw new Error("INVALID_VECTOR");
  const norm = v => Math.sqrt(v.reduce((s,x) => s+x*x,0));
  if (!norm(a) || !norm(b)) throw new Error("ZERO_VECTOR");
  return a.reduce((s,x,i) => s+x*b[i],0)/(norm(a)*norm(b));
}
const docs = [
  {id:"refund",words:["refund","arrival"],vector:[1,0]},
  {id:"error",words:["E_CONN_RESET","retry"],vector:[0,1]},
  {id:"shipping",words:["shipping","arrival"],vector:[0.8,0.2]}
];
const terms = ["refund","arrival"];
const lexical = docs.map(d => ({
  id:d.id,score:terms.filter(t => d.words.includes(t)).length
})).filter(d => d.score>0).sort((a,b) => b.score-a.score || a.id.localeCompare(b.id)).map(d => d.id);
const vector = docs.map(d => ({id:d.id,score:cosine([1,0],d.vector)}))
  .sort((a,b) => b.score-a.score || a.id.localeCompare(b.id)).map(d => d.id);
function rrf(rankings,k=60) {
  const scores = new Map();
  for (const ranking of rankings) {
    if (new Set(ranking).size !== ranking.length) throw new Error("DUPLICATE_RANK");
    ranking.forEach((id,i) => scores.set(id,(scores.get(id)||0)+1/(k+i+1)));
  }
  return [...scores].sort((a,b) => b[1]-a[1] || a[0].localeCompare(b[0])).map(([id]) => id);
}
assert.equal(cosine([1,0],[1,0]),1);
assert.equal(cosine([1,0],[0,1]),0);
assert.throws(() => cosine([0,0],[1,0]),/ZERO/);
assert.throws(() => cosine([1],[1,2]),/INVALID/);
assert.deepEqual(lexical,["refund","shipping"]);
assert.deepEqual(rrf([lexical,vector]),["refund","shipping","error"]);
assert.deepEqual(rrf([["a","b"],["b","a"]]),["a","b"]);
console.log("cosine checks + lexical ranking + reciprocal-rank fusion: passed");
console.log("top=refund; vectors synthetic; no trained embedding model executed");
~~~

~~~

运行 npm run tutorial -- S5-L02。cosine 是点积除以两向量长度，零向量没有定义。不同维度直接拒绝，比悄悄截断可靠。RRF 对排名求 1/(k+rank) 后累加，避免直接相加两个不可比较的原始分数；它仍有候选数、k 与重复结果处理等参数。

## 3. 从课堂数值走向真实 embedding

下一步选择一个支持目标语言和部署条件的 embedding 模型，锁定名称、修订、维度与预处理，按其官方模型卡使用 encode 或服务接口。先用“退款/退回款项”“订单/订阅”“错误码/相近文本”等成对样本看排序，再建人工相关性标注。

不要根据本例的二维坐标解释真实模型某一维是“退款程度”。训练得到的维度通常没有这种单轴语义。也不要用聊天模型输出随机数字假装 embedding。远程接口需管理费用、限流、批量、失败重试与敏感数据出境范围；本课程默认不替你触发付费调用。

实际接入接口应返回 modelVersion、dimension 与向量数组，拒绝非有限数和维度不一致。索引写入同时保存块版本与 embedding 版本。重建采用新索引准备、对照验收、切换和可回滚引用。

## 4. 向量数据库解决什么

少量向量可以精确扫描；更多数据可能采用 ANN 索引，以一定召回损失换速度和内存。TopK 是“从候选里取几条”，不等于相关性保证。过滤是在搜索前、搜索中还是搜索后执行，会影响授权、候选数量和召回。

关键词侧可使用 BM25 等方法：同时考虑词频、文档频率和长度。实验只用词项重合计数，不能声称实现 BM25。中文需要分词、字粒度或适合语言的检索器，代码和编号还需要精确字段。

## 故障练习与项目迁移

把未归一化点积当 cosine，构造“大模长但方向差”的错误排序。把不同模型维度混入索引，验证立即拒绝。让两路排名重复同一块，检查融合前去重规则。

项目练习：保留关键词基线，接入一个实际 embedding 实现，提交固定数据集上的 Recall@K、延迟和索引版本。若只完成合成向量实验，如实标注尚未验证真实语义召回。

## 单页速记

- 表示模型决定向量含义，相似度公式不提供语义质量。
- 精确编号与语义改写需要不同检索优势。
- 混合排名可以融合，质量仍由标注集检验。
- 模型变更、索引版本、ACL 和重建属于检索工程。
