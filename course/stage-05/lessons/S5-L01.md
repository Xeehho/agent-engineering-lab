# S5-L01 RAG 入库：切块、版本、来源与删除

**网页主线：直接阅读讲解 → 动手实验 → 随堂练习 → 公开自测 → 复习速记。无需启动项目、安装依赖或提供 API Key。**

本课网页任务：把窗口改为4、重叠改为1，先手算来源行。

网页实验范围：实际切块算法，版本存储是内存，不是向量索引。

**选做实操说明：**下面涉及 Node、Python、数据库或 SDK 的环境、命令和完整文件供进阶使用，不是阅读本课的前置条件。


RAG 先检索外部证据，再把证据送给生成器。它不能保证模型一定忠实，也不能把无权限数据变成可用上下文。本课执行真实切块和 SQLite 版本替换，不调用 embedding 或模型，不代表学习者已掌握。

## 1. 从“引用为什么打不开”倒推入库契约

答案引用“退款说明第3段”，但文档刚被编辑，原第3段已经变成别的内容。只有 docId 不足以复现证据；需要文档版本、块 ID、原文位置、内容摘要、租户与删除状态。网页 URL 是入口，版本化快照才是当时事实。

入库流程可以拆成读取 → 解析 → 清洗 → 切块 → 索引 → 激活版本。解析失败时，不能悄悄把旧版本标成最新。更大规模可先构建新版本，全部成功后原子切换 activeVersion，避免读到半批索引。

## 代码阅读：一段原文怎样成为可引用的块

### 读清窗口与重叠

splitDocumentIntoChunks 输入原文、窗口行数与重叠行数，输出带起止行号和文本的块。窗口3、重叠1时，步长=3-1=2。内部数组从0开始，展示行号从1开始，所以 startIndex+1 才是来源行。

|块|内部切片|对外来源行|重叠|
|---|---|---|---|
|第一块|第0至2项|1–3|包含原第3行|
|第二块|第2至4项|3–5|也包含原第3行|

到达文末就 break，避免只因重叠又生成一块重复尾部。overlap 必须是整数，且在0到windowSize-1之间，否则可能跳错位置或不能推进。

### 再读入库事务

ingestDocument 先完成切块，再开始事务，删除同租户同文档的旧块，插入新版本，全部成功后提交。块ID包含租户、文档、版本、行号和内容摘要，帮助追踪“哪份文档的哪次快照”。

示例先写A的v1和B的独立文档，再写A的v2。只有A旧版本被替换。删除A后，B仍存在。这里真实删除的是SQLite行，向量索引、缓存和备份没有被本例自动处理。

### 关键限制为什么会被切丢

若“可退款”与“仅未发货”被分到不同块，检索只取其中一块就可能改变规则。标题、表格和否定条件通常需要结构感知切块或邻块扩展。重叠能缓解边界损失，也会增加重复候选，需要评测与去重。

### 带提示的练习

先用5行文本手算两个窗口，再改成4行观察尾块。给重叠输入1.5，程序应拒绝。最后在插入第二块前制造异常，核对旧版本是否保留；不要把“文件里有新文档”当作新索引已完整激活。

## 2. 一个保留行号的切块器

### 完整实操文件：S5-L01.mjs

~~~js file=S5-L01.mjs
// 先按行切块保留位置，再在事务里替换同租户同文档的版本。
import assert from "node:assert/strict";
import { createHash } from "node:crypto";
import { DatabaseSync } from "node:sqlite";
const database = new DatabaseSync(":memory:");
database.exec(
  `
CREATE TABLE chunks (
  id TEXT PRIMARY KEY,
  tenant TEXT,
  doc TEXT,
  version INTEGER,
  start_line INTEGER,
  end_line INTEGER,
  text TEXT
)
`,
);
// 输入原文、窗口和重叠行数，输出带来源行号的块。
function splitDocumentIntoChunks(sourceText, windowSize = 3, overlapLines = 1) {
  if (
    !Number.isInteger(windowSize) ||
    windowSize < 1 ||
    !Number.isInteger(overlapLines) ||
    overlapLines < 0 ||
    overlapLines >= windowSize
  ) {
    throw new Error("INVALID_WINDOW");
  }
  const documentLines = sourceText.replaceAll("\r\n", "\n").split("\n"),
    chunks = [];
  for (
    let startIndex = 0;
    startIndex < documentLines.length;
    startIndex += windowSize - overlapLines
  ) {
    const endIndex = Math.min(startIndex + windowSize, documentLines.length);
    chunks.push({
      start: startIndex + 1,
      end: endIndex,
      text: documentLines.slice(startIndex, endIndex).join("\n"),
    });
    if (endIndex === documentLines.length) {
      break;
    }
  }
  return chunks;
}
// 一次事务替换文档；发生错误时旧版本仍可保留。
function ingestDocument(tenantId, documentId, documentVersion, sourceText) {
  const chunks = splitDocumentIntoChunks(sourceText);
  database.exec("BEGIN");
  try {
    database
      .prepare("DELETE FROM chunks WHERE tenant=? AND doc=?")
      .run(tenantId, documentId);
    for (const chunk of chunks) {
      const contentDigest = createHash("sha256")
        .update(chunk.text)
        .digest("hex")
        .slice(0, 12);
      const chunkId = [
        tenantId,
        documentId,
        documentVersion,
        chunk.start,
        chunk.end,
        contentDigest,
      ].join(":");
      database
        .prepare("INSERT INTO chunks VALUES(?,?,?,?,?,?,?)")
        .run(
          chunkId,
          tenantId,
          documentId,
          documentVersion,
          chunk.start,
          chunk.end,
          chunk.text,
        );
    }
    database.exec("COMMIT");
  } catch (error) {
    database.exec("ROLLBACK");
    throw error;
  }
}
try {
  const originalDocument =
    "退款规则\n未发货可申请\n已发货先退货\n审核需两天\n到账以银行为准";
  const chunks = splitDocumentIntoChunks(originalDocument);
  assert.deepEqual(
    chunks.map((chunk) => [chunk.start, chunk.end]),
    [
      [1, 3],
      [3, 5],
    ],
  );
  assert.equal(chunks[0].text.split("\n")[2], chunks[1].text.split("\n")[0]);
  ingestDocument("A", "refund", 1, originalDocument);
  ingestDocument("B", "refund", 1, "B 的独立规则");
  ingestDocument("A", "refund", 2, "新版规则\n审核需三天");
  assert.equal(
    database
      .prepare(
        `
SELECT
  count(*) AS n
FROM
  chunks
WHERE
  tenant = 'A'
  AND version = 1
`,
      )
      .get().n,
    0,
  );
  assert.equal(
    database.prepare("SELECT count(*) AS n FROM chunks WHERE tenant='B'").get().n,
    1,
  );
  database.prepare("DELETE FROM chunks WHERE tenant=? AND doc=?").run("A", "refund");
  assert.equal(
    database.prepare("SELECT count(*) AS n FROM chunks WHERE tenant='A'").get().n,
    0,
  );
  assert.throws(() => splitDocumentIntoChunks(originalDocument, 3, 3), /WINDOW/);
  console.log("line provenance=1-3,3-5; overlap preserved");
  console.log("A v1 replaced by v2 then deleted; B remained isolated");
} finally {
  database.close();
}
~~~
~~~text expect=S5-L01.mjs
line provenance=1-3,3-5; overlap preserved
A v1 replaced by v2 then deleted; B remained isolated
~~~

**选做本地验证：**运行 npm run tutorial -- S5-L01。窗口3行、重叠1行，步长为2；overlap 必须小于 size，否则可能死循环。文档版本包含在块 ID 中，同段文字在不同版本不会被误认成同一证据。

## 3. 切块不是固定数字的选择题

窗口太小可能把限制条件切开，例如“可退款”与“仅未发货”分离；太大则稀释匹配并占用上下文。标题、表格、代码块与列表有语义结构，不能只靠字符数硬切。重叠减少边界损失，也会造成重复检索与引用，需要去重。

实验按行切，只适合说明来源位置。PDF 页码、OCR、网页清洗和代码仓库需要各自解析器与定位方法。解析后的行号不能冒充原始 PDF 页码；来源字段要明确基于哪种文本快照。

## 4. 权限和删除贯穿全部索引

实验删除实际 SQLite 行，但系统可能还有向量索引、关键词索引、缓存、答案快照和备份。需要删除事件、重试、审计和查询时兜底过滤，避免异步删除窗口泄露旧内容。备份删除策略依业务和合规要求另定，不能假设即时物理抹除。

文档级 ACL 与块级 ACL 需要同源版本。检索后再过滤容易使结果不足，且某些服务会把未授权候选发给 reranker；在数据离开权限边界前就要约束。

## 故障练习与项目迁移

把 DELETE 放在事务外，随后故意在插入第二块时失败，观察旧版本消失或半批状态。去掉租户条件，验证更新 A 会误删 B。构造跨块否定条件，解释为什么召回一块不足以支持答案。

项目练习：接入两种真实文档，保存解析快照与来源位置；实现版本激活、失败恢复和删除传播记录。验收不只看块数，还要随机抽取引用还原原文，并验证无权限候选未进入后续模型。

## 单页速记

- RAG 的可靠性从入库契约开始。
- 块需要版本、位置、来源、租户与可删除身份。
- 切块大小用样本评估，重叠有收益也有代价。
- 删除要传播到所有索引、缓存与派生结果。
