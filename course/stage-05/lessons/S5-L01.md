# S5-L01｜RAG 数据入口：切分、版本与权限

阶段：05 RAG 与知识数据工程。先修：01 的模型基础，03 的权限，04 的版本/状态。
建议投入：35–60 分钟 + 项目练习。允许 AI 协作，要求本人解释与验证。

## 本课目标

- 明确知识从哪里来
- 按任务定义 chunk
- 让索引与源数据一起更新

## 1. 明确知识从哪里来

研发知识可能来自 README、工单和规范。采集时保存文档 ID、来源、更新时间、版本、作者/所属范围和访问权限；清洗不能把标题、表格关系、否定词或代码块语境丢掉。真实企业资料要按授权采集，课程只使用合成文档。

## 2. 按任务定义 chunk

chunk 是索引与返回证据的单元，长度、重叠与结构切分都影响召回与成本。把一个排障步骤切成只有“执行此命令”会丢失前置条件；整份巨大文档又可能挤占上下文。先用真实问题检查答案位于哪些片段，再比较不同切分，不把固定字符数当作通用最优。

## 3. 让索引与源数据一起更新

文档删除、权限收回、版本更新后，旧索引、缓存与已生成答案可能仍存在。为采集、切分、embedding 与索引版本建立可追踪关系，支持删除传播和重新索引。权限过滤应在检索执行路径中落实，不能先拿到全部片段再靠 Prompt 祈祷模型不泄漏。

## 动手验证

先写预测，再运行，最后修改一个条件观察反例。不要把网页机制演示当成真实基础设施验证。

## 实验：相同文字不等于相同可见证据

先预测输出，再运行并修改一个条件。这是教学用的 JavaScript 机制演示，不是真实模型、数据库、协议 SDK 或生产系统。

~~~js
const chunks = [
 {id:"a",tenant:"A",version:2,text:"排障步骤"},
 {id:"b",tenant:"B",version:2,text:"排障步骤"},
 {id:"c",tenant:"A",version:1,text:"旧步骤"}
];
console.log(chunks.filter(c => c.tenant === "A" && c.version === 2));
~~~

观察方向：只有 A 当前版本可见；这只是数组过滤，还需在真实检索、缓存和引用中保持同一规则。

提示：检索前后的访问边界都要核查。
