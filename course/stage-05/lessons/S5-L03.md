# S5-L03｜重排、引用与拒答

教材状态：已编写，可提前学习；不代表学习者已作答或通过考试。
阶段：05 RAG 与知识数据工程。先修：01 的模型基础，03 的权限，04 的版本/状态。
建议投入：35–60 分钟 + 项目练习。允许 AI 协作，要求本人解释与验证。

## 本课目标

- 把召回与重排分开
- 让引用指向真正支持结论的片段
- 定义无答案、冲突与时效策略

## 1. 把召回与重排分开

召回先在较大范围中找到候选，重排用更昂贵的相关性判断重新排序；二者的目标、成本与失败位置不同。如果正确证据根本没进候选集，重排也无法从无中生有。先检查候选覆盖，再看最终前几条的质量。

## 2. 让引用指向真正支持结论的片段

引用不是在答案尾部随便加一个链接。把每个关键主张与具体片段、来源、版本绑定；检查片段是否真的包含该结论，是否只是关键词相似。模型生成的“来源 ID”必须存在于本次授权证据集，不能因为 ID 结构合法就信任。

## 3. 定义无答案、冲突与时效策略

没有证据时明确说明不足并要求补充信息；新旧文档冲突时展示来源与版本，而不是合并成自信结论。拒答阈值不能只凭一个相似度常数拍板，要用有答案、无答案、冲突等样本共同调整，衡量错误拒答与无依据作答的代价。

## 动手验证

先写预测，再运行，最后修改一个条件观察反例。不要把网页机制演示当成真实基础设施验证。

## 实验：引用存在与引用支持不同

先预测输出，再运行并修改一个条件。这是教学用的 JavaScript 机制演示，不是真实模型、数据库、协议 SDK 或生产系统。

~~~js
const authorized = new Map([["doc-2",{version:3,text:"超时默认 5 秒"}]]);
for (const claim of [{text:"超时 5 秒",source:"doc-2"},{text:"超时 1 秒",source:"doc-9"}]) {
 console.log(claim, {sourceExists:authorized.has(claim.source)});
}
console.log("存在性检查不能单独验证内容支持关系");
~~~

观察方向：不存在的来源会暴露；存在的引用是否支持主张，还需内容核对与评测。

提示：不要把引用存在误当作答案正确。
