# S5-L03 Rerank、引用与拒答

**网页主线：直接阅读讲解 → 动手实验 → 随堂练习 → 公开自测 → 复习速记。无需启动项目、安装依赖或提供 API Key。**

本课网页任务：给错误结论配一个真实quote，指出机械校验为何仍可能通过。

网页实验范围：固定评分和业务夹具；引用存在性不证明语义支持。

**选做实操说明：**下面涉及 Node、Python、数据库或 SDK 的环境、命令和完整文件供进阶使用，不是阅读本课的前置条件。


检索到相似文档，不代表答案已获支持。本课实现候选重排接口与机械引用校验，评分使用固定夹具，不是真实 reranker；校验通过也不证明语义蕴含，不代表学习者已掌握。

## 1. 两阶段检索各自负责什么

第一阶段从大量文档找出较宽候选，优先保召回；第二阶段对 query 与每个候选做更精细评分，换取较好的排序。典型 cross-encoder 联合读取 query/document，成本通常高于预先编码后向量搜索。

Reranker 无法挽救没召回的文档。若候选集缺少“已发货必须退货”的限制，只重排“未发货可退款”，可能让错误答案更自信。先检查候选覆盖，再检查排序，最后检查生成是否使用了正确证据。

## 代码阅读：找到来源与支持结论是两道题

### 三个函数分别回答什么

rerankCurrentChunks 排除旧版本并按给定分数排序，分数是夹具；validateCitation 检查来源ID、版本和引文是否存在；answerWithFixtureRule 只处理一个固定问题，证据不满足就拒答。三个函数都没有实现通用自然语言推理。

### 跟踪一个答复

问题是“已发货如何退款”，c2包含“需先完成退货”。c2排名最高后，固定规则返回结论、chunkId、version和quote。机械校验在当前候选中找到同版本c2，并确认 quote 是原文子串，因此通过。

|改动|机械检查|真实含义|
|---|---|---|
|quote改成无需退货|拒绝|引文伪造|
|version改成1|拒绝|来源版本不匹配|
|问题改问银行卡到账|拒答|固定证据不足|
|结论改成所有订单立即到账|仍可能通过|引文存在，但没有支持结论|

最后一行是本课最重要的反例：机械检查的边界已经被证明，不能把它当作忠实度评测。

### 怎样继续检查语义

把回答拆成可独立核查的 claims，再逐条检查条件、否定、数量、时间与结论范围。人工或模型裁判按明确准则判断支持度；模型裁判也要用人工标签校准。冲突无法裁决时应暴露冲突或拒答，不让最后一段话强行抹平。

### 带提示的练习

先写“未发货可以”和“已发货需先退货”的最小对比对。再让正确来源落在候选集外，区分召回缺失与排序错误。最后构造真实引文配错误结论，说明需要哪类新检查，不能只补一个sourceExists字段。

## 2. 让每个结论带证据定位

### 完整实操文件：S5-L03.mjs

~~~js file=S5-L03.mjs
// 把排序与引用检查分开，最后用反例证明真实引文不等于结论受支持。
import assert from "node:assert/strict";
const fixtureChunks = [
  { id: "c1", version: 2, text: "未发货订单可以申请退款。" },
  { id: "c2", version: 2, text: "已发货订单需先完成退货，再审核退款。" },
  { id: "c3", version: 1, text: "旧版：所有订单立即退款。" },
];
// 先排除旧版本，再调用题目给定评分函数排序，未使用真实重排模型。
function rerankCurrentChunks(candidateChunks, scoreCandidate) {
  return candidateChunks
    .filter((chunk) => chunk.version === 2)
    .map((chunk) => ({ ...chunk, score: scoreCandidate(chunk) }))
    .sort((a, b) => b.score - a.score || a.id.localeCompare(b.id));
}
// 仅核对来源版本和引文存在，不判断自然语言结论是否被蕴含。
function validateCitation(generatedClaim, availableChunks) {
  const chunk = availableChunks.find(
    (x) => x.id === generatedClaim.chunkId && x.version === generatedClaim.version,
  );
  if (!chunk) {
    return { ok: false, reason: "MISSING_OR_STALE_SOURCE" };
  }
  if (!generatedClaim.quote || !chunk.text.includes(generatedClaim.quote)) {
    return { ok: false, reason: "QUOTE_NOT_FOUND" };
  }
  return { ok: true, scope: "quote-exists-only" };
}
// 固定规则用于观察答复与拒答路径，不模拟通用语言理解能力。
function answerWithFixtureRule(questionText, rankedChunks) {
  // 固定业务规则夹具，用来验证证据路径，不是自然语言生成器。
  if (questionText !== "已发货如何退款" || rankedChunks[0]?.id !== "c2") {
    return { kind: "abstain", reason: "INSUFFICIENT_SUPPORTED_RULE" };
  }
  return {
    kind: "answer",
    claim: "已发货需先退货",
    chunkId: "c2",
    version: 2,
    quote: "需先完成退货",
  };
}
const rankedChunks = rerankCurrentChunks(
  fixtureChunks,
  (chunk) => ({ c1: 0.2, c2: 0.9 })[chunk.id],
);
assert.equal(rankedChunks[0].id, "c2");
assert.equal(
  rankedChunks.some((chunk) => chunk.id === "c3"),
  false,
);
const fixtureAnswer = answerWithFixtureRule("已发货如何退款", rankedChunks);
assert.equal(validateCitation(fixtureAnswer, rankedChunks).ok, true);
assert.equal(
  validateCitation({ ...fixtureAnswer, quote: "无需退货" }, rankedChunks).ok,
  false,
);
assert.equal(
  validateCitation({ ...fixtureAnswer, version: 1 }, rankedChunks).ok,
  false,
);
assert.equal(answerWithFixtureRule("多久到银行卡", rankedChunks).kind, "abstain");
// 反例：真实引用存在，但与答案无关；机械校验仍会通过。
const unsupportedClaim = { ...fixtureAnswer, claim: "所有订单都能立即到账" };
assert.equal(validateCitation(unsupportedClaim, rankedChunks).ok, true);
console.log("current candidates reranked; missing/stale/fabricated quote rejected");
console.log(
  "unsupported question abstained; valid quote alone did not prove entailment",
);
~~~

unsupported question abstained; valid quote alone did not prove entailment
~~~

**选做本地验证：**运行 npm run tutorial -- S5-L03。最后一个断言刻意揭示边界：引用真实，不等于结论受它支持。不要把机械引用校验的100%通过写成“答案忠实度100%”。

## 3. 设计可检查的生成契约

将答案拆成可独立核查的 claims，每条记录来源块、版本和短引文。没有支持的 claim 应删除、缩小范围或明确不确定。多个来源冲突时呈现冲突与时效，不把它们揉成一个确定结论。

可让模型生成结构化草稿，再由程序核对引用存在和版本；语义支持需人工标注或经过校准的评审器。模型裁判也会错，尤其在否定词、时间、数量和条件上，要保留人工抽查与反例。

## 4. 拒答并不意味着产品没完成

“资料里没有银行卡到账时间，可以补充支付渠道或联系人工”比编造“三天必到”更符合契约。拒答过多也伤害可用性，应区分可回答问题的错误拒答、不可回答问题的编造回答。阈值来自业务代价与验证集，不能凭一个分数取0.8当通用标准。

上下文排序与截断需要把限制条件、来源标题和版本一起保留。对比两份互相矛盾的材料，先按有效期和权威规则裁决；没有规则时应暴露冲突，不能默认最新抓取时间等于最新事实。

## 故障练习与项目迁移

用“可以”与“不可以”、已发货与未发货构造最小对比对，检查裁判是否真的懂条件。让正确来源排在 TopK 外，区分召回失败与重排失败。让引文存在但结论夸大，不能只修引用 ID。

项目练习：接一个真实 reranker 或先保留无重排基线，在同候选集比较排序。提交带 claim 的答案、引用校验、冲突处理和拒答样本，单独报告真实模型与固定夹具覆盖范围。

## 单页速记

- 先召回覆盖，再重排，再验证生成支持。
- 引用存在、引用当前、引用支持结论是三个检查。
- 条件、否定、数量和时效是高价值反例。
- 拒答率与编造率需要同时评估。
