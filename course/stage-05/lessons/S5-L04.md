# S5-L04 先找出哪一层失误，再优化 RAG

## 先说我们要解决什么问题

问答答错时，你不知道该换embedding、改切分还是改Prompt。如果所有错误都只记成“答案不对”，优化就只能靠猜。

## 先把概念讲清楚

RAG评测应分层：检索有没有找到需要的证据；生成是否使用证据并回答正确；每条引用是否支持主张；无答案或越权时是否拒答。数据集是固定的一组问题与期望依据，开发集用于调试，保留测试集用于最后验收，不能边看测试答案边调。

治理是长期保持资料可追溯、可删除、权限一致和版本明确。缓存键至少考虑租户/权限、资料版本和查询等边界，不能让A用户命中的答案直接返回B用户。

## 名字与字段从哪里来

|名字或字段|来源与含义|
|---|---|
|relevant / retrieved|课堂标注的相关证据编号与检索返回编号|
|recall|本例召回率：找回相关数除以相关总数|
|hits|交集数量，不等于回答正确数|
|Set|JavaScript去重集合，用于避免重复证据重复计分|

## 先读这个最小例子

网页“动手实验”运行相同代码。先找输入、检查与输出；assert 是课堂提供的检查函数，不是模型能力。

~~~js
const relevant = new Set(["doc-1", "doc-2"]);
const retrieved = new Set(["doc-1", "doc-3", "doc-1"]);
const hits = [...relevant].filter((id) => retrieved.has(id)).length;
const recall = hits / relevant.size;
console.log("相关资料找回：", hits + "/" + relevant.size, "召回率：", recall);
assert.equal(recall, 0.5);
~~~
## 运行结果与逐步解释

~~~text
相关资料找回： 1/2 召回率： 0.5
~~~

标注两份相关资料，只找到doc-1，所以1/2。doc-3是干扰项，重复doc-1不会加分。本例只算某个截断清单的召回，不测排序位置、答案或权限。真实数据应包含有答案、无答案、冲突、过期和跨租户样本，并报告每类分母，别用平均分掩盖越权。

## 1. 先定义样本与分母

每条样本需要 query、租户、语料版本、可回答性、相关文档集合、预期关键事实和限制条件。训练/调参集帮助改系统，保留集用于最后判断；把保留集看过并据此改阈值后，它就不再是干净的保留集。

Recall@K 是前K条命中相关文档数除以该问题相关文档总数；MRR 用第一个相关结果的倒数排名。两者衡量不同问题：只找到一个相关文档可能 MRR 很好，但多来源问题 Recall 仍低。无相关文档的问题不应硬填 Recall=1 来美化平均数。

## 代码阅读：逐条算清分子与分母

### 输入先于指标

goldCases 是人工相关性与可回答性标注，runByQuestionId 是系统实际输出记录。evaluateRetrieval 按问题ID对齐两者，缺一次运行就报错，不静默从分母删除。topK 决定只查看前几条去重候选。

### 手算当前三条样本

|问题|相关文档|前2条|Recall@2|倒数排名|
|---|---|---|---|---|
|q1|a、b|a、x|1/2|1|
|q2|c|x、c|1|1/2|
|q3|无|x|不适用|不适用|

宏平均Recall=(0.5+1)/2=0.75，MRR=(1+0.5)/2=0.75。检索分母是2，不是3。q3没有相关文档，指标使用null；没有可计算样本时总指标也应为null，不能产生NaN或默认100%。

拒答另算：q1应回答且回答，正确；q2可回答却拒答，错误；q3不可回答并拒答，正确。因此拒答决策准确率为2/3。检索成功没有自动解决生成与决策问题。

### 去重与缺失的区别

重复c不应算两次命中。缺失运行则意味着没有完成实验，不能包装为不可回答题，也不能从分母悄悄移除。标注相关文档集合本身也需要去重与一致性检查。

### 带提示的练习

先不运行程序，计算q1在K=3时的变化。再只保留不可回答题，预测哪些指标不适用。最后删除q2的运行记录，验证明确报错；报告保留失败ID与切片，不能只交一个总分。

## 2. 跑一份逐条报告

### 完整实操文件：S5-L04.mjs

~~~js file=S5-L04.mjs
import assert from "node:assert/strict";

// 标注与运行分开保存，评分不能根据输出临时改变答案。
const goldCases = [
  { id: "q1", relevant: ["a", "b"], answerable: true },
  { id: "q2", relevant: ["c"], answerable: true },
  { id: "q3", relevant: [], answerable: false },
];
const runByQuestionId = {
  q1: { retrieved: ["a", "x", "b"], abstained: false },
  q2: { retrieved: ["x", "c", "c"], abstained: true },
  q3: { retrieved: ["x"], abstained: true },
};

// 无可计算样本时返回 null，不能把 NaN 或0假装成确定指标。
function meanOrNull(values) {
  if (values.length === 0) {
    return null;
  }
  return values.reduce((sum, value) => sum + value, 0) / values.length;
}

function evaluateRetrieval(goldCases, runByQuestionId, topK) {
  if (!Number.isInteger(topK) || topK < 1) {
    throw new Error("INVALID_K");
  }
  if (new Set(goldCases.map((sample) => sample.id)).size !== goldCases.length) {
    throw new Error("DUPLICATE_QUESTION_ID");
  }

  const caseRows = goldCases.map((goldCase) => {
    const actualRun = runByQuestionId[goldCase.id];
    if (!actualRun) {
      throw new Error("MISSING_RUN:" + goldCase.id);
    }

    const relevantIds = new Set(goldCase.relevant);
    const uniqueCandidates = [...new Set(actualRun.retrieved)].slice(0, topK);
    const hitCount = uniqueCandidates.filter((id) => relevantIds.has(id)).length;
    const firstRelevantIndex = uniqueCandidates.findIndex((id) => relevantIds.has(id));

    let recall = null;
    let reciprocalRank = null;
    if (relevantIds.size > 0) {
      recall = hitCount / relevantIds.size;
      reciprocalRank = firstRelevantIndex < 0 ? 0 : 1 / (firstRelevantIndex + 1);
    }
    return {
      id: goldCase.id,
      recall,
      rr: reciprocalRank,
      correctAbstention: actualRun.abstained === !goldCase.answerable,
    };
  });

  const retrievalRows = caseRows.filter((row) => row.recall !== null);
  return {
    rows: caseRows,
    recall: meanOrNull(retrievalRows.map((row) => row.recall)),
    mrr: meanOrNull(retrievalRows.map((row) => row.rr)),
    abstentionAccuracy: meanOrNull(
      caseRows.map((row) => (row.correctAbstention ? 1 : 0)),
    ),
    retrievalDenominator: retrievalRows.length,
    total: caseRows.length,
  };
}

const report = evaluateRetrieval(goldCases, runByQuestionId, 2);
assert.equal(report.recall, 0.75);
assert.equal(report.mrr, 0.75);
assert.equal(report.abstentionAccuracy, 2 / 3);
assert.equal(report.rows[2].recall, null);
assert.throws(
  () => evaluateRetrieval(goldCases, { q1: runByQuestionId.q1 }, 2),
  /MISSING/,
);
assert.deepEqual(
  report.rows.filter((row) => !row.correctAbstention).map((row) => row.id),
  ["q2"],
);
assert.equal(evaluateRetrieval([goldCases[2]], runByQuestionId, 2).recall, null);
assert.equal(evaluateRetrieval([], {}, 2).abstentionAccuracy, null);
assert.throws(() => evaluateRetrieval(goldCases, runByQuestionId, 0), /INVALID_K/);
console.log("Recall@2=0.75; MRR@2=0.75; retrieval denominator=2");
console.log("abstention decisions=2/3; q2 false refusal; q3 retrieval N/A");
~~~
~~~text expect=S5-L04.mjs
Recall@2=0.75; MRR@2=0.75; retrieval denominator=2
abstention decisions=2/3; q2 false refusal; q3 retrieval N/A
~~~

**选做本地验证：**运行 npm run tutorial -- S5-L04。q1 只召回2个相关文档中的1个，Recall=0.5；q2 在第二位召回唯一相关文档，Recall=1、RR=0.5。平均后两者都是0.75，这只是本样本巧合。q2 检索成功却拒答，说明生成/决策层还存在问题。

## 3. 分层诊断比一个总分更有用

对每条失败分别问：文档是否正确入库？权限是否允许？候选是否包含证据？排序是否保留？生成是否忠实？引用是否定位正确？用户最终任务是否完成？不要因为答案错就先换模型。

报告按查询类型、语言、文档类型、租户与长尾场景切片。小样本百分比波动很大，要给出分子分母与失败 ID；上线前用代表性样本和适当不确定性估计。关键越权案例可以设零容忍发布门槛，但有限测试未发现不等于证明永远不会发生。

## 4. 数据生命周期是质量的一部分

语料需要来源许可、采集范围、敏感字段策略、更新与删除责任人。文档被撤权后，索引、rerank 输入、缓存和已生成引用都要处理。评测集本身也可能含个人信息，不能因为是测试数据就公开。

去重不仅是降低成本：相同模板的近重复问题同时出现在开发集和保留集，会让结果虚高。按文档、业务实体或时间切分，降低泄漏。保存数据集版本与标签变更理由，评审者有分歧时先写准则，再仲裁。

## 故障练习与项目迁移

删除一次运行记录，系统应该报缺失，不能从分母剔除。把重复候选当不同命中，构造虚高 Recall。把 q3 的 N/A 填成1，比较错误宏平均。每次都指出具体分母如何改变。

项目练习：整理不少于30条有来源的问题，覆盖可回答、不可回答、权限和冲突。冻结基线后比较一个改动，保存逐条结果与退步列表。真实业务样本不足时明确样本来源与推广边界，不把合成评测写成生产准确率。

## 单页速记

- 相关性、可回答性与最终任务成功分别标注。
- 指标必须写分母；N/A、缺失和失败不可混为成功。
- 固定集配对对比，保留回归与关键失败门槛。
- 语料和评测数据都需要权限、版本、去重与删除。
