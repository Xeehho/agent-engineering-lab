# S5-L04｜RAG 评测与数据治理

教材状态：已编写，可提前学习；不代表学习者已作答或通过考试。
阶段：05 RAG 与知识数据工程。先修：01 的模型基础，03 的权限，04 的版本/状态。
建议投入：35–60 分钟 + 项目练习。允许 AI 协作，要求本人解释与验证。

## 本课目标

- 建立分层标注
- 防止评测泄漏与偏样本
- 让变更可追溯

## 1. 建立分层标注

为每条问题保存查询、可接受答案范围、相关文档/片段、权限身份、时间与版本。检索评测关注相关证据是否进入候选，回答评测关注忠实性、完整性与引用支持；把两者合成一个“准确率”会掩盖排错方向。无答案样本需单独口径，不能硬算零分或满分混入。

## 2. 防止评测泄漏与偏样本

开发集用于调切分和阈值，保留测试集用于检验新版本。根据看到的测试题不断改 Prompt 又宣称测试客观，会高估泛化。样本应覆盖精确编号、改写、权限拒绝、旧版本、冲突和无法回答；保留失败案例，不只挑最好看的十条。

## 3. 让变更可追溯

记录文档、索引、embedding、检索参数、Prompt 与模型版本，在同一组查询上做配对对照。报告分层指标、样本数和成本/延迟，不从很小样本推出生产可靠性。个人信息、敏感文档和保留期限也需有治理规则；评测集不能成为未经授权的数据副本。

## 动手验证

先写预测，再运行，最后修改一个条件观察反例。不要把网页机制演示当成真实基础设施验证。

## 实验：检索正确率和回答正确率分开算

先预测输出，再运行并修改一个条件。这是教学用的 JavaScript 机制演示，不是真实模型、数据库、协议 SDK 或生产系统。

~~~js
const cases = [{retrieved:true,faithful:true},{retrieved:true,faithful:false},{retrieved:false,faithful:false}];
console.log("检索命中",cases.filter(x=>x.retrieved).length+"/"+cases.length);
console.log("回答合格",cases.filter(x=>x.faithful).length+"/"+cases.length);
console.log("标签为人工假设，不是真实 RAG 实测");
~~~

观察方向：检索 2/3，回答 1/3。第二条帮助定位“找到却答错”。

提示：不同层的指标分母和意义要说清。

先写你预期的行为，再让 AI 协作实现。提交具体 commit、输入、预期、实际、命令、失败复盘与未验证项；本教材不代做学习者项目。
