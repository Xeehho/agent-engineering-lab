# S8-L02 速记

## 三个关键判断

- 按约束而不是组件名设计：先澄清用户规模、延迟/费用目标、数据权限、任务时长、可恢复性和部署条件，再选择服务、队列、存储、检索与模型。
- 建立从症状到证据的排错顺序：面对“助手突然答错”，先复现并锁定版本/输入，再查权限与数据、候选证据、Prompt/模型完成、工具结果和 UI 状态。
- 用取舍回应面试追问：解释为什么选 TS 主线、Python 桥接放在哪里、何时用 MCP、何时不用多 Agent。

## 代码阅读检查

- 数据与身份来自哪里？
- 哪一步真正验证或执行了约束？
- 哪类失败会被拒绝，何时停止或恢复？
- 证据来自机制演示、Mock、真实服务还是生产？结论有多大范围？
