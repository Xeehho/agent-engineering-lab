# S7-L02 一条用户请求怎样串起多段日志

## 先说我们要解决什么问题

用户说任务很慢。日志里有模型请求、工具调用和数据库写入，但找不到它们属于哪一次任务，也不知道费用记录缺失还是确实为零。

## 先把概念讲清楚

Trace是一次请求经过多个组件的关联记录；span是其中一段操作，例如一次模型调用。日志记录离散事件，指标汇总多个请求的趋势。它们互补，不能只靠一条error文本排完所有问题。

关联需要传播编号，内容需要脱敏，费用需要来源。usage缺失表示未知，不能填0假装免费。真实成本还依赖对应服务的计费规则、时间和模型版本；本课不硬编码实时价格。

## 名字与字段从哪里来

|名字或字段|来源与含义|
|---|---|
|traceId / spanId / parent|常见追踪概念；本例对象是课堂格式，不是完整OpenTelemetry数据|
|usage / null|课堂用null表达未知；非所有服务的原生格式|
|tokens|本课示意记录；输入输出及缓存计费需分别核对|
|summary|本课展示函数，避免把未知转为零|
