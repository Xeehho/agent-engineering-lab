# S3-L01 MCP 是应用之间约定好的说话方式

## 先说我们要解决什么问题

同一套工单能力要同时接进编辑器、聊天助手和网页助手。如果每个地方各写一套独有调用格式，维护就会越来越费力。怎样让不同应用按共同规则发现并调用能力？

## 先把概念讲清楚

MCP（Model Context Protocol，模型上下文协议）是一套互操作约定。先把它想成双方都能读懂的接口语言，而不是一个会思考的模型。Host 是用户正在用的AI应用，Client 是 Host 内负责协议连接的组件，Server 提供工具、资源等能力。它们是职责划分，不必等于三台电脑。

普通函数直接调用最简单；MCP 在需要跨应用、跨进程接入时有价值，也会增加连接、版本和权限管理。下面只用对象模拟“先发现名字，再调用”，没有发送协议报文。

## 名字与字段从哪里来

|名字或字段|来源与含义|
|---|---|
|host / client / server|MCP架构角色；代码中的对象仅是课堂替身|
|listTools / callTool|课堂便利函数名；不是JSON-RPC wire方法名|
|tools/list / tools/call|本课锁定的2025-11-25协议方法；由SDK包装|
|tools / name / description|课堂清单简化；真实工具描述还含输入契约等|
