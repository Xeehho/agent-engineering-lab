# S1-L03 逐字显示时，怎样挡住旧回答

## 先说我们要解决什么问题

用户先问订单A，马上又问订单B。A的回复慢一点才回来，如果直接拼到界面，就会把两条回答混在一起。

## 先把概念讲清楚

流式响应是把完整回答拆成多段事件逐步传来。事件不是每个字符都一定对应一次网络包，应用应按协议解析。React state 是渲染所依赖的数据；reducer 则是一个“旧状态 + 事件 → 新状态”的普通函数。先在网页里用数组代替网络，学会拒绝旧请求，之后再接真实流。

请求编号用于区分两次工作，序号用于区分同一次工作里的先后。它们解决不同问题。

## 名字与字段从哪里来

|名字或字段|来源与含义|
|---|---|
|requestId|本课事件字段，标识属于哪一次请求|
|seq|本课事件序号；真实服务的字段由适配器转换|
|text / done|本课状态字段，表示文本与是否结束|
|reduce / apply|Array.reduce 是 JS 标准；apply 是课堂自己的状态更新函数|
