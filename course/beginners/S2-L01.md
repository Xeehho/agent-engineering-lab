# S2-L01 工具调用就是提出一个函数请求

## 先说我们要解决什么问题

模型说“我已经查过T-42工单”，但你的系统根本没调用数据库。怎样让“想查”与“确实查到了”在代码里分开？

## 先把概念讲清楚

模型本身不能直接访问你没提供的业务系统。工具调用是模型生成一个结构化提议，包含工具名和参数；你的应用验证后才运行函数。工具注册表是应用自己保存的“允许名称 → 实际函数”的映射。不要把模型给出的字符串当代码执行。

先只开放读工单。白名单解决“能调用什么”，参数校验解决“这次请求格式是否合法”，授权还要判断“当前用户能否读这个工单”。这三者不能互相替代。

## 名字与字段从哪里来

|名字或字段|来源与含义|
|---|---|
|proposal / name / args|本课工具提议格式；服务商接口需转换|
|registry / readTicket|本课工具注册表和普通业务函数|
|ticketId|本课业务参数，必须是字符串|
|result|应用实际执行后的返回，不是模型自称已完成|

## 运行结果与逐步解释

~~~text
订单页白屏
~~~

先创建注册表，不执行工具；再创建提议，也不执行工具；dispatch 检查名字和参数，最后一行函数调用才读取固定工单。这里只验证格式，没有验证真实身份、工单归属和返回结构，因此不能直接接敏感业务。

2. 把 ticketId 改成数字，说明为何不能执行。
3. 用自己的话解释函数定义、模型提议、函数调用三者。
