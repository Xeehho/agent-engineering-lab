# S8-L01 毕业项目先从验收边界画起

## 先说我们要解决什么问题

你想做“能处理一切的AI助手”，范围很大却很难判断什么时候算完成。面试时也只剩一段演示，没有可靠证据。

## 先把概念讲清楚

毕业项目把课程串成一个边界明确的产品，例如“有权限的工单资料检索与回复草稿助手”。先列用户、输入、允许操作、不允许操作和验收案例，再设计数据流。最小纵向切片是能从界面一路走到后端并返回结果的一条短路径；逐步加检索、工具、持久任务和评测。

作品完成与学习掌握是两种结论。AI可以帮实现，但你要能解释关键路径、修改约束、复现故障并说明证据范围。网页演示不能代替真实毕业项目。

## 名字与字段从哪里来

|名字或字段|来源与含义|
|---|---|
|requirements / evidence|课堂需求编号与证据清单|
|requirementId / scope|课堂证据关联字段；真实提交带commit、环境和复现方法|
|missing|本例没有覆盖的需求，不自动判定已覆盖项合格|
|filter / some|JavaScript集合匹配，用来检查清单完整性|


逐条需求寻找同编号证据，可取消没有记录所以缺失。已有记录只是有条目，不说明质量、覆盖范围和真实性合格。项目提交应让陌生开发者按README复现，区分Mock、真实组件、真实模型和未验证边界。

## 在网页里完成三件小事

1. 补可取消记录，并说明具体触发步骤。
2. 把需求拆成正常、错误、越权、重试四类验收。
3. 画从界面到工具结果再回到答案的完整路径。
