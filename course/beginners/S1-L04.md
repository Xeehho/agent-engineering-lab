# S1-L04 测试通过，到底证明了什么

## 先说我们要解决什么问题

AI 帮你写了代码并说“测试全绿，可以上线”。如果测试中的模型只是返回固定答案，这句话缺少哪一段证据？

## 先把概念讲清楚

证据是支持某个具体结论的可检查记录。Mock（替身）用固定行为代替外部组件，让本地检查可重复；它不能证明那个真实组件也有相同行为。验收要先写结论，再问证据是否覆盖结论。

区分三件事：软件在特定输入下按预期工作；真实服务能够接通；真实任务的效果达到目标。一次成功响应通常只证明某次接通，不能直接证明总体质量。

## 名字与字段从哪里来

|名字或字段|来源与含义|
|---|---|
|claim|想支持的结论，课堂字段|
|kind / passed|证据类型与该项是否通过，课堂约定|
|controlled / real|本课证据分类，不是任何测试框架的保留字|
|canClaimReal|课堂判断函数；真实验收还需要任务、环境、版本和日期|

## 运行结果与逐步解释

~~~text
本地检查通过： true
可声称真实接通： false
~~~

数组第一项通过，支持“某次受控检查通过”。函数主动寻找 real 且 passed 的记录，没有就返回 false。把第二项手动改为 true 只改了声明，仍需保留真实请求的脱敏记录；代码不能把自报数据变成可信证据。
