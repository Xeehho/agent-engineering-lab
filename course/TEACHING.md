# 课堂资料沉淀约定

## 每次授课的交付

1. 完整讲义：学习目标、先修、概念、例子、反例、边界与来源。
2. 复习速记：适合回看的一页提要，链接到完整解释。
3. 可运行示例：标明运行环境、预期观察、是否调用真实模型。
4. 随堂练习：先允许学习者作答，后按实际回答补讲。
5. 学习状态：区分已经讲授、待作答、已评阅与已掌握。

聊天中的新增知识点、纠错与有复用价值的答疑，应在当前课内或补充页同步整理。纯进度交流无需保存原始聊天。

互动课堂：同步维护 public/learn.html 单文件教材。Markdown 讲义与速记通过 npm run classroom:build 生成到页面；新实验、公开自测与通用讲评也需保留可读的课程资料。页面的本机活动进度、选择题分数与老师的评阅记录分别处理，不能由页面自动标记阶段 passed。后续课程沿用讲义、实验、练习、自测、笔记的结构增补。

## 面向开源

- 讲义使用通用描述、合成案例和可复现步骤，不默认复制学习者原话、履历、个人答案或成绩。
- 个人笔记可放learning/private/；个人原始提交可放submissions/private/。这两个目录被Git忽略。
- 既有阶段提交与进度文件仍按当前流程使用。真正公开仓库前，应复核既有文件及历史中的个人信息、第三方内容和验证范围。
- 开源意向不自动改变GitHub可见性。本次仓库继续私有，许可证尚待项目所有者选定。
- 技术事实就近引用官方来源；练习题和教学类比明确是本项目设计。
- 不复制整篇官方文档、完整第三方课程或大量招聘原文。
- 示例的Mock、真实模型、模拟故障和实际运行证据分开记录。

## 答案与考试

课堂可以讲解例题，并在学习者回答后补充通用讲评。正式考试变式仍在交卷后生成；不提前把答案放进课程。材料生成、示例运行或CI通过都不自动标记学习者已掌握。
