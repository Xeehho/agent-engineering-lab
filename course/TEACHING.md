# 课堂资料沉淀约定

## 每次授课的交付

1. 完整讲义：学习目标、先修、概念、例子、反例、边界与来源。
2. 复习速记：适合回看的一页提要，链接到完整解释。
3. 可运行示例：标明运行环境、预期观察、是否调用真实模型。
4. 随堂练习：先允许学习者作答，后按实际回答补讲。
5. 学习状态：区分已经讲授、待作答、已评阅与已掌握。

聊天中的新增知识点、纠错与有复用价值的答疑，应在当前课内或补充页同步整理。纯进度交流无需保存原始聊天。

互动课堂：同步维护 public/learn.html 单文件教材。Markdown 讲义与速记通过 npm run classroom:build 生成到页面；新实验、公开自测与通用讲评也需保留可读的课程资料。页面的本机活动进度、选择题分数与老师的评阅记录分别处理，不能由页面自动标记阶段 passed。后续课程沿用讲义、实验、练习、自测、笔记的结构增补。

## 面向开源

- 讲义使用通用描述、合成案例和可复现步骤，不默认复制学习者原话、履历、个人答案或成绩。
- 个人笔记可放learning/private/；个人原始提交可放submissions/private/。这两个目录被Git忽略。
- 个人进度保存到learning/private/progress.json，公共仓库仅提供progress.example.json空模板。公开前复核工作树与可达历史。
- 项目所有者已授权公开发布，代码MIT、原创课程与脑图CC BY 4.0，混合产物范围见LICENSING.md。
- 技术事实就近引用官方来源；练习题和教学类比明确是本项目设计。
- 不复制整篇官方文档、完整第三方课程或大量招聘原文。
- 示例的Mock、真实模型、模拟故障和实际运行证据分开记录。

## 答案与考试

用户已要求提前开发全部课程，不等待逐阶段学完。材料状态按实际源文件记录，区分简版与详细教程，不以目录、段落数或文件数证明教学完整性。正式考试仍按个人提交生成，个性化补练根据实际表现调整。教材发布不计为学习者掌握。

详细教程源在 course/tutorials/，独立实操代码在 code/，逐函数讲解与执行追踪在 walkthrough/。浏览器实验源在 course/browser-demos/，任务和范围在 course/browser-guidance.mjs。构建统一生成讲义、笔记、实操文件与单页课堂。

默认学习路径在网站内完成，不要求先clone、安装或启动项目。每课网页实验有清楚任务、可读代码、可观察结果与明确范围。真实Python、数据库、MCP和完整项目作为进阶实操；不把推演冒充真实组件，不把真实项目验证门槛强加到普通阅读路径。

教学代码优先明确变量名、单一职责与分段控制流，不使用压缩表达式掩盖步骤。完整代码前讲清输入输出、关键函数、具体数据变化和失败原因。SQL按子句排版。修改后运行 teaching:format，再 classroom:build 与 check。运行检查不等于教学质量审阅，仍需逐课核对讲解与代码一致。

课堂可以讲解例题，并在学习者回答后补充通用讲评。正式考试变式仍在交卷后生成；不提前把答案放进课程。材料生成、示例运行或CI通过都不自动标记学习者已掌握。

## 入门主线的写作顺序

先讲一个具体问题，再定义概念和角色，说明字段来自课堂、标准还是SDK，然后给最小代码、预期输出、逐步追踪和三道小练习。先修课有明确跳转。原完整教程和旧实验在进阶折叠区；入门进度仅要求入门实验、F1–F3和FQ1–FQ2。旧题号与答案保留，不删除学习者记录。

每课脑图有中心问题、四条分支与先修/后续关系。工程架构按请求、知识管道和质量交付三个视角串联；图中的连接必须能解释输入输出，不能把MCP当成所有工具的必经路径。图与速记由同一数据生成，修改源后统一构建。
