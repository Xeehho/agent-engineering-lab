# S2-L01 速记

## 三个关键判断

- 拆开提议、校验、授权与执行：用户要查工单 T-42，模型可能输出工具名称和参数。
- 设计窄而清晰的工具契约：先提供 getTicket({ticketId})、searchDocs({query,limit}) 这样的有限能力，明确每个字段的含义、范围、缺失时行为以及返回上限。
- 把服务商协议隔离在适配器：不同模型 API 对工具调用标识、参数文本和结果消息的格式可能不同。

## 代码阅读检查

- 数据与身份来自哪里？
- 哪一步真正验证或执行了约束？
- 哪类失败会被拒绝，何时停止或恢复？
- 证据来自机制演示、Mock、真实服务还是生产？结论有多大范围？
