## 本课目标

- 先定义循环的输入与终止条件
- 区分多种预算
- 决定什么时候需要 Agent

## 1. 先定义循环的输入与终止条件

一个最小循环是读取任务状态、请求模型决策、验证决策、执行工具、追加结果，再继续或结束。最终答案、步数用尽、总截止时间、费用预算、取消和不可恢复错误都可能终止循环。自然语言里说“最多三次”只是提示，程序必须实际执行计数与限制。

## 2. 区分多种预算

模型轮次、工具执行次数、并发数、token 和费用不是同一量。一次响应可能包含多个工具调用；按模型轮次限三步，不代表工具最多调用三次。重试也要消耗预算，且不能通过换 runId 绕过任务级上限。实际费用应来自服务计量与定价记录，估算值要标明。

## 3. 决定什么时候需要 Agent

固定的分诊→检索→生成草稿流程可以由确定性 workflow 编排；未知路径探索才可能需要动态决策。先做可测的简单基线，再比较 Agent 带来的收益与成本。案例中重复查询同一工单却没有新信息时，应检测停滞或耗尽预算，不能靠不断补 Prompt 期待它自觉停下。

## 实验：永不结束的提议如何被截止？

先预测输出，再运行并修改一个条件。这是教学用的 JavaScript 机制演示，不是真实模型、数据库、协议 SDK 或生产系统。

~~~js
let calls = 0;
const limit = 3;
while (calls < limit) {
  const decision = {tool:"searchDocs"}; // 固定假决策
  calls++;
  console.log("执行", calls, decision.tool);
}
console.log("停止原因: TOOL_BUDGET_EXCEEDED");
~~~

观察方向：只能执行三次。改为每轮两个工具，检查计数应放在每次执行还是每轮外侧。

提示：计数单位要与实际约束一致。
