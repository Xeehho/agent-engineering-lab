## 本课目标

- 为一个循环定义状态、决策、工具结果和终止原因。
- 分别限制模型轮次、工具次数与整体期限。
- 让批量工具与预取消都有可预测的行为。

## 1. 从一个会无限搜索的助手开始

用户要求查订单故障，助手查到文档后仍然反复 searchDocs，没有新增信息。自然语言里说“最多三次”可能有帮助，但若程序无限 while，系统仍可能一直花费资源。

最小 Agent 循环可以写成：读取任务状态→请求决策→验证决策→预检预算→执行工具→记录结果→继续或结束。与固定 Workflow 的差别在于下一步由模型动态提议，而执行控制仍属于应用。

## 代码阅读：有限循环不是简单的 while

### 状态由应用持有

runAgentLoop 输入决策函数和预算，输出轮次、工具数、历史与停止原因。decide 在本课是固定函数，真实项目才替换成模型适配器。rounds 在请求决策之前加1，tools 在每次工具执行前加1，计数单位不同。

传给 decide 的是 structuredClone(state)，防止它修改应用持有的预算。模型可以提出“再查一次”，但只有循环本身能决定是否还有额度。

### 跟踪正常流程

|步骤|rounds|tools|发生什么|
|---|---|---|---|
|开始|0|0|检查预取消|
|第一次决策|1|0|提议searchDocs|
|执行工具|1|1|追加真实工具结果的课堂夹具|
|第二次决策|2|1|看到历史，返回final|
|结束|2|1|reason=succeeded|

重复决策器在两个工具用完后还会再提出查询，循环拒绝整个超额批次并返回 tool_budget。预算结束属于受控停止，不能当成成功答案。

### 期限在等待中也要生效

awaitUntilAborted 把正在等待的 Promise 与取消信号连接起来。deadlineTimer 到期会让调用方结束等待；真实 decide 必须继续把 signal 交给上游，才能停止实际工作。一个永远不返回且不理会信号的操作，应用只能放弃等待，无法凭 Promise 强制杀死它。

~~~js
const decision = await awaitUntilAborted(
  () => decide(structuredClone(state), { signal: executionSignal }),
  executionSignal,
);
~~~

### 带提示的练习

先预测一批3个工具、剩余2次额度时，已经执行几个；答案应来自预检发生的位置。再返回 null，观察 invalid_decision。最后让决策器等待信号并统计清理，与永不响应取消的版本比较，分别报告“停止等待”和“工作已停止”。

## 2. 写状态表，再决定循环长什么样

至少区分 succeeded、cancelled、model_budget、tool_budget、deadline、failed。预算终止不是业务成功；应该保留部分证据与停止原因，而不是把最后一段文本强制包装成最终答案。

模型轮次不等于工具数。一轮可能提议三个工具；重试、并行分支也消耗预算。本课选择“批次超过剩余额度时整批拒绝”，这样不产生半批副作用。你也可以设计部分执行，但必须有明确结果与幂等约定。

## 3. 分步实现一个有界调度器

**选做本地验证：**运行 node examples/tutorials/S2-L02.mjs。第一个 provider 先读再答；第二个一直搜索；第三个一次提议过多工具。决策是脚本夹具，不是模型智能。

### 完整实操文件：S2-L02.mjs

~~~js file=S2-L02.mjs
import assert from "node:assert/strict";

// 让调用方在取消时结束等待。操作本身是否停止，仍取决于它是否响应 signal。
function awaitUntilAborted(startOperation, signal) {
  signal.throwIfAborted();

  return new Promise((resolve, reject) => {
    const handleAbort = () => reject(signal.reason);
    signal.addEventListener("abort", handleAbort, { once: true });

    Promise.resolve()
      .then(() => {
        signal.throwIfAborted();
        return startOperation();
      })
      .then(resolve, reject)
      .finally(() => signal.removeEventListener("abort", handleAbort));
  });
}

async function runAgentLoop(decide, options = {}) {
  const {
    maxRounds = 3,
    maxTools = 2,
    timeoutMs = 1000,
    signal: callerSignal = new AbortController().signal,
  } = options;

  const state = { rounds: 0, tools: 0, history: [] };
  const deadlineController = new AbortController();
  const deadlineTimer = setTimeout(() => {
    deadlineController.abort(new Error("DEADLINE_EXCEEDED"));
  }, timeoutMs);
  const executionSignal = AbortSignal.any([callerSignal, deadlineController.signal]);

  function stoppedResult(reason) {
    return { ...state, reason };
  }

  try {
    while (true) {
      executionSignal.throwIfAborted();
      if (state.rounds >= maxRounds) {
        return stoppedResult("model_budget");
      }

      state.rounds += 1;
      // 传副本，防止决策器改写应用持有的计数与历史。
      const decision = await awaitUntilAborted(
        () => decide(structuredClone(state), { signal: executionSignal }),
        executionSignal,
      );
      executionSignal.throwIfAborted();

      if (!decision || typeof decision !== "object") {
        return stoppedResult("invalid_decision");
      }
      if (decision.type === "final" && typeof decision.text === "string") {
        return { ...state, reason: "succeeded", answer: decision.text };
      }
      if (decision.type !== "tools" || !Array.isArray(decision.calls)) {
        return stoppedResult("invalid_decision");
      }
      if (decision.calls.length === 0) {
        return stoppedResult("no_progress");
      }

      const remainingTools = maxTools - state.tools;
      if (decision.calls.length > remainingTools) {
        return stoppedResult("tool_budget");
      }

      // 整个批次先检查，避免前半批执行后才发现后半批不允许。
      if (decision.calls.some((call) => !call || call.name !== "searchDocs")) {
        return stoppedResult("unknown_tool");
      }

      for (const call of decision.calls) {
        executionSignal.throwIfAborted();
        state.tools += 1;
        state.history.push({ callId: call.id, result: "local evidence" });
      }
    }
  } catch (error) {
    if (!executionSignal.aborted) {
      throw error;
    }
    return stoppedResult(deadlineController.signal.aborted ? "deadline" : "cancelled");
  } finally {
    clearTimeout(deadlineTimer);
  }
}

// 决策器一：第一次提议检索，看到结果后结束。它是固定夹具，不是模型。
async function decideSearchThenFinish(state) {
  if (state.tools > 0) {
    return { type: "final", text: "基于本地证据的草稿" };
  }
  return { type: "tools", calls: [{ id: "c1", name: "searchDocs" }] };
}
const successfulRun = await runAgentLoop(decideSearchThenFinish);
assert.equal(successfulRun.reason, "succeeded");

// 决策器二：不停检索，最终由程序的工具预算终止。
const repeatedRun = await runAgentLoop(
  async (state) => ({
    type: "tools",
    calls: [{ id: "c" + state.rounds, name: "searchDocs" }],
  }),
  { maxRounds: 10 },
);
assert.equal(repeatedRun.reason, "tool_budget");
assert.equal(repeatedRun.tools, 2);

const oversizedRun = await runAgentLoop(async () => ({
  type: "tools",
  calls: [1, 2, 3].map((id) => ({ id, name: "searchDocs" })),
}));
assert.equal(oversizedRun.tools, 0);

const preCancelledController = new AbortController();
preCancelledController.abort();
const cancelledRun = await runAgentLoop(
  async () => {
    throw new Error("should not call");
  },
  { signal: preCancelledController.signal },
);
assert.equal(cancelledRun.rounds, 0);

// 决策器永远不返回，调用方依然必须按总期限停止等待。
const hangingRun = await runAgentLoop(() => new Promise(() => {}), { timeoutMs: 5 });
assert.equal(hangingRun.reason, "deadline");
const invalidRun = await runAgentLoop(async () => null);
assert.equal(invalidRun.reason, "invalid_decision");

console.log("success=succeeded; repeat=tool_budget; oversized batch executed=0");
console.log("pre-cancel model rounds=0");
~~~

## 4. 这段代码证明什么，还缺什么

预算检查在实际工具执行前，所以整批拒绝时 tools=0。state.rounds 在请求决策前增加，失败请求也已消耗一次尝试，不能等成功后才计数。history 保存真实工具结果，不允许模型自行伪造“工具已经执行”。

这一版使用总期限信号与 awaitUntilAborted，即使 decide 永不返回，调用方也会按时结束等待。真实 provider 还必须接收并响应 signal，才能停止实际工作；程序无法仅凭 Promise 强制终止不配合取消的外部服务。观察停止原因与服务端清理，应分别取证。

费用预算还没有实现；toolCount 不能替代 token 或金额。需从实际模型返回计量、价格版本和事先预算检查中补齐，并在未知时保留未知。

## 5. 先决定是否需要动态循环

如果业务固定为“校验输入→检索→生成草稿”，确定性 Workflow 更容易验证。需要根据工具结果探索未知步骤时，Agent 才可能值得引入。给同一组任务建立简单基线，比较质量、调用次数、延迟与费用。

停滞检测可以检查重复工具+相同参数+无新增证据，但“重复一次”未必错误，例如暂时性失败重试。把停滞、重试与预算结合，不用一个字符串重复判断替代全部业务理解。

## 6. 故障练习

把预算检查放在工具循环之后，观察超大批次会先执行再停止；对于写操作，这已经太晚。把 history 直接传给不可信 decide 且不复制，模拟其篡改 tools 计数，说明执行控制面不能由模型输出覆盖。

让 decide 返回空工具列表，检查是否明确 no_progress。让 decide 永远等待，核对总期限确实结束等待；再换成响应 signal 的工作函数，对比任务清理情况，不把放弃等待当成外部工作已停止。

## 项目迁移与验收

接上上一课分发器时，用结构化结果区分最终答案与工具提议。写出最大轮次、最大工具数、批次策略、整体期限、重试计数、取消和部分结果的约定。

至少验证成功、重复提议、超额批次、非法决策、预取消与挂起 provider 六类路径。本人解释每种停止是否成功，以及从哪些证据得出。不要以“模型最终愿意停”代替程序有界性。

## 单页速记

- 决策可以动态，执行控制必须有界。
- 轮次、工具、token、费用、并发和截止时间分别计量。
- 批次先预检，取消先检查，失败尝试也计数。
- 边界检查不自动中断正在等待的操作，必须接上取消。
