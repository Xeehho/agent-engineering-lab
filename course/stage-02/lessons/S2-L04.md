# S2-L04｜Prompt 与上下文工程

教材状态：已编写，可提前学习；不代表学习者已作答或通过考试。
阶段：02 工具调用与 Agent 循环。先修：01 的契约、取消和证据边界。
建议投入：35–60 分钟 + 项目练习。允许 AI 协作，要求本人解释与验证。

## 本课目标

- 写清任务、输入、输出与缺信息行为
- 选择上下文并保留信任边界
- 通过版本对照改 Prompt

## 1. 写清任务、输入、输出与缺信息行为

从工单分诊的目标出发，说明哪些是用户事实、哪些是检索证据、允许的分类、摘要应保留什么、何时返回缺信息。少样例可以展示边界，但样例错误也会把模型带偏。不要只写“你是顶级专家，请认真思考”，却没有业务规则与验收口径。

## 2. 选择上下文并保留信任边界

系统指令、用户任务、历史、检索文档和工具结果的来源不同。应用应只选择与当前任务相关、权限允许、版本有效的内容，并明确将外部文本作为数据。把历史摘要当业务事实会传播错误；长期记忆应有来源、更新与删除规则，不应无限保存每句话。

## 3. 通过版本对照改 Prompt

记录 Prompt 模板版本、填充数据来源与模型设置，在相同样本上比较新旧版本。某次回答更好不代表整体提升。不要索要或依赖隐藏的内部思维链作为正确性证据；可以要求简短的结论依据与可核查引用。真正的质量仍由业务样例和执行记录支持。

## 动手验证

先写预测，再运行，最后修改一个条件观察反例。不要把网页机制演示当成真实基础设施验证。

## 实验：上下文选择不只是长度

先预测输出，再运行并修改一个条件。这是教学用的 JavaScript 机制演示，不是真实模型、数据库、协议 SDK 或生产系统。

~~~js
const context=[{id:"a",relevant:true,allowed:true,current:true},{id:"b",relevant:true,allowed:false,current:true},{id:"c",relevant:true,allowed:true,current:false}];
console.log(context.filter(x=>x.relevant && x.allowed && x.current).map(x=>x.id));
console.log("布尔标签为合成示例，不自动解决真实相关性与权限");
~~~

观察方向：只选择 a；长度适合但无权限/过期的内容也不能加入。

提示：相关、授权、时效是独立检查。

## 本课项目任务

S2-T4：提交可版本化 Prompt 模板、上下文选择规则和至少六条边界样例的配对结果。

先写你预期的行为，再让 AI 协作实现。提交具体 commit、输入、预期、实际、命令、失败复盘与未验证项；本教材不代做学习者项目。

## 本阶段验收边界

- 已知工具白名单、参数/结果验证和调用关联
- 最大轮次、工具次数、总期限、取消和停滞处理
- 读取/草稿/写入权限分离，具体确认与持久幂等
- 未知工具、注入、重复写入和预算耗尽均有拒绝路径
