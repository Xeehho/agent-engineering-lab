## 本课目标

- 区分请求、任务与执行尝试
- 用状态转换表达约束
- 把并发更新当作正常情况

## 1. 区分请求、任务与执行尝试

一次浏览器请求可以创建一个持续更久的任务；任务又可能被 worker 尝试多次。requestId、taskId、attemptId 分别回答哪次通信、哪个业务任务、哪次执行。不能把关闭页面等同于任务删除，也不能把连接断开直接记成业务失败。

## 2. 用状态转换表达约束

为 queued、running、waiting_approval、succeeded、failed、cancelled 定义允许转换与执行条件。终态不能被重放事件任意改回运行中。需要暂停时持久化可恢复的业务状态、输入/版本、已完成步骤和下一动作；只保存一份自然语言聊天摘要通常不足以恢复副作用边界。

## 3. 把并发更新当作正常情况

两个 worker 都读到 queued 时可能同时抢任务。使用事务、条件更新或版本号等方式争抢执行权，并验证冲突处理。数据库事务不能自动覆盖外部 API；外部写入仍需要幂等和恢复对账。课堂内存对象没有持久化、锁或真实并发保证。

## 实验：拒绝非法状态跳转

先预测输出，再运行并修改一个条件。这是教学用的 JavaScript 机制演示，不是真实模型、数据库、协议 SDK 或生产系统。

~~~js
const allowed = {queued:["running","cancelled"],running:["waiting_approval","succeeded","failed","cancelled"],waiting_approval:["running","cancelled"]};
function transition(from,to) {
  if (!allowed[from]?.includes(to)) throw new Error("INVALID_TRANSITION");
  return to;
}
console.log(transition("queued","running"));
try { console.log(transition("succeeded","running")); } catch(e) {console.log(e.message);}
~~~

观察方向：合法跳转成功，终态回到 running 被拒绝；数据库并发控制还没有被验证。

提示：状态名不够，还需要允许边和前置条件。
