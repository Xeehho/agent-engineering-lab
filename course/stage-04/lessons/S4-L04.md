## 本课目标

- 先为访问路径建数据模型
- 区别索引、约束与授权
- 用事务处理竞争而不是掩盖竞争

## 1. 先为访问路径建数据模型

任务、执行尝试、事件、幂等记录和文档版本有不同生命周期，不能只用一个超大 JSON 列取代所有约束。明确主键、外键、租户字段、唯一约束、创建/更新时间和保留规则。针对“按租户取最近任务”“按任务回放事件”写查询，再决定索引。

## 2. 区别索引、约束与授权

索引帮助某些访问路径，也有写入与存储成本；唯一索引/约束可参与保证唯一性，但普通索引不自动检查业务规则。带 tenant 条件的查询还需要可信身份与完整执行路径。动态值使用数据库库支持的参数绑定，不能拼接用户输入；动态标识符则另用受控白名单。

## 3. 用事务处理竞争而不是掩盖竞争

多个 worker 读取同一状态并同时写入，需要条件更新、版本号、唯一约束或适当锁等策略。选择隔离级别并理解可能冲突，必要时安全重试。事务内完成的数据库变更不包含第三方写入；可用 outbox 等模式协调提交后的动作，但消费者仍需幂等。

## 实验：先读后写的竞争窗口

先预测输出，再运行并修改一个条件。这是教学用的 JavaScript 机制演示，不是真实模型、数据库、协议 SDK 或生产系统。

~~~js
let version=1;
function conditionalUpdate(expected) {
 if(version!==expected) return false;
 version++; return true;
}
const workerARead=version,workerBRead=version;
console.log("A",conditionalUpdate(workerARead));
console.log("B",conditionalUpdate(workerBRead));
console.log("同步 JS 示意 CAS；真实数据库需原子条件更新");
~~~

观察方向：A 成功，B 因旧版本失败。普通应用层先检查再写并不能自动复制这种原子性。

提示：检查与写入要在真正的原子边界完成。
