# S3-L02 先连接，再发现，最后分清错误

## 先说我们要解决什么问题

工具清单里有readTicket，但调用时连接已经断了。另一次连接正常，却没有这个工单。界面都显示“工具失败”会让排错很困难。

## 先把概念讲清楚

传输负责把消息送到对方，例如本地标准输入输出（stdio）或HTTP；协议规定消息是什么意思。MCP初始化用于协商修订和能力，随后才能按协商结果交互。stdio的stdout用于协议，诊断文字放stderr，避免污染消息。

错误至少分两层：消息或连接没成功，和工具执行后报告业务问题。2025-11-25中工具结果可用isError表达工具执行错误，不能把它当成网络断开。

## 名字与字段从哪里来

|名字或字段|来源与含义|
|---|---|
|connected / connect|课堂连接状态与函数；真实SDK负责生命周期|
|call|课堂简化调用函数，不是完整MCP消息|
|isError / content|MCP工具结果概念；本例只保留部分结构|
|text|text内容块中的标准字段；这里省略type等完整格式|

## 先读这个最小例子

网页“动手实验”运行相同代码。先找输入、检查与输出；assert 是课堂提供的检查函数，不是模型能力。

~~~js
let connected = false;
function connect() {
  connected = true;
}
function call(ticketId) {
  if (!connected) throw new Error("连接尚未建立");
  if (ticketId !== "T-42") {
    return { isError: true, content: [{ text: "工单不存在" }] };
  }
  return { isError: false, content: [{ text: "订单页白屏" }] };
}
assert.throws(() => call("T-42"), /连接/);
connect();
console.log(call("missing").isError, call("T-42").content[0].text);
~~~

## 1. 三层结果不要混在一起

连接断开是传输问题；未知协议方法是协议错误；get_ticket 找不到工单是工具业务失败。即使收到合法 JSON，也可能是 isError=true。具体 SDK 如何封装，要看选定版本，不能凭经验写“所有错误都 throw”。

本实验的高层 McpServer 会把未知工具、Schema 校验错误转成 isError 工具结果；ping 等未知协议方法的错误不在这个业务封装里。客户端应分别检查 Promise 是否拒绝、返回结构是否合法、业务结果是否成功。

## 代码阅读：用两端证据证明取消

### 客户端和服务端各观察什么

客户端 pendingCall 的拒绝表示“不再等待结果”；Server 的 activeTasks=0 表示当前工作已退出，cancelledTasks=1 表示它确实看到了取消。只有第一条证据，不能推出第二条。

slow handler 把 requestContext.signal 交给可取消的 wait。收到取消后 catch 增加取消计数，finally 减少活动计数。stats 工具返回这些计数，便于从另一条协议请求核对服务端状态。

### 时间线是测试的一部分

1. 连接并发现三个工具。
2. 验证正常、未知工具、非法参数和业务无结果。
3. 发起 slow，并立即绑定拒绝处理。
4. 轮询到 active=1 后才 abort，确保测的是进行中取消。
5. 等待 active=0、cancelled=1，再关闭连接。

若取消发生在 Server 开始之前，可能根本没有执行工作，不能证明进行中清理。cleanupDeadline 则防止验证脚本无限等待。

### 错误结果如何读取

在本课锁定的高层 SDK 路径中，未知工具与参数校验失败会被包装为 isError=true。它与底层未知 JSON-RPC 方法导致的协议异常不是同一路径。看实际调用的 API 与版本，不把所有错误都写成一个 catch。

### 带提示的练习

删除 Server 的 signal 传递后，先预测客户端和服务端会各看到什么，再运行。不要只把测试等待时间调大；应恢复取消传播。接 HTTP MCP 后，另测认证、代理断连、连接生命周期，stdio 通过不能替代这些部署条件。

## 2. 服务端必须响应取消

### 完整实操文件：S3-L02-server.mjs

~~~js file=S3-L02-server.mjs
// 工具必须把请求信号接到真实等待；客户端取消不自动清理服务端工作。
import { McpServer } from "@modelcontextprotocol/sdk/server/mcp.js";
import { StdioServerTransport } from "@modelcontextprotocol/sdk/server/stdio.js";
import { setTimeout as wait } from "node:timers/promises";
import { z } from "zod";
const server = new McpServer({ name: "mcp-errors", version: "1.0.0" });
let activeTasks = 0,
  cancelledTasks = 0;
const createTextResult = (value) => ({
  content: [{ type: "text", text: JSON.stringify(value) }],
});
server.registerTool("lookup", { inputSchema: { id: z.string() } }, async ({ id }) => {
  return id === "known"
    ? createTextResult({ found: true })
    : { isError: true, content: [{ type: "text", text: "NOT_FOUND" }] };
});
server.registerTool(
  "slow",
  { inputSchema: {} },
  async (unusedArguments, requestContext) => {
    activeTasks++;
    try {
      await wait(10000, undefined, { signal: requestContext.signal });
      return createTextResult({ done: true });
    } catch (error) {
      if (requestContext.signal.aborted) {
        cancelledTasks++;
      }
      throw error;
    } finally {
      activeTasks--;
    }
  },
);
server.registerTool("stats", { inputSchema: {} }, async () =>
  createTextResult({ active: activeTasks, cancelled: cancelledTasks }),
);
await server.connect(new StdioServerTransport());
~~~
slow 把协议请求的取消信号接到实际异步等待，finally 释放活动计数。仅在 UI 上隐藏结果，服务端仍可能工作；所以必须同时观察服务端活动资源。

## 3. 客户端验证六种情况

### 完整实操文件：S3-L02.mjs

~~~js file=S3-L02.mjs
// 先确认工作已启动，再取消，并观察服务端活动计数归零。
import assert from "node:assert/strict";
import { fileURLToPath } from "node:url";
import { setTimeout as wait } from "node:timers/promises";
import { Client } from "@modelcontextprotocol/sdk/client/index.js";
import { StdioClientTransport } from "@modelcontextprotocol/sdk/client/stdio.js";
const client = new Client({ name: "mcp-checks", version: "1.0.0" });
const transport = new StdioClientTransport({
  command: process.execPath,
  args: [fileURLToPath(new URL("./S3-L02-server.mjs", import.meta.url))],
});
const readServerStatistics = async () =>
  JSON.parse((await client.callTool({ name: "stats", arguments: {} })).content[0].text);
try {
  await client.connect(transport);
  assert.equal((await client.listTools()).tools.length, 3);
  assert.notEqual(
    (await client.callTool({ name: "lookup", arguments: { id: "known" } })).isError,
    true,
  );
  for (const toolCall of [
    { name: "old_lookup", arguments: {} },
    { name: "lookup", arguments: { id: 12 } },
    { name: "lookup", arguments: { id: "missing" } },
  ]) {
    assert.equal((await client.callTool(toolCall)).isError, true);
  }
  const cancellationController = new AbortController();
  // 先绑定 rejection 处理，避免取消时产生未处理拒绝。
  const pendingCall = client
    .callTool({ name: "slow", arguments: {} }, undefined, {
      signal: cancellationController.signal,
    })
    .then(
      () => ({ rejected: false }),
      () => ({ rejected: true }),
    );
  const cleanupDeadline = Date.now() + 3000;
  while ((await readServerStatistics()).active !== 1) {
    assert.ok(Date.now() < cleanupDeadline, "slow never started");
    await wait(10);
  }
  cancellationController.abort();
  assert.equal((await pendingCall).rejected, true);
  let finalStatistics;
  do {
    finalStatistics = await readServerStatistics();
    if (finalStatistics.active === 0 && finalStatistics.cancelled === 1) {
      break;
    }
    assert.ok(Date.now() < cleanupDeadline, "server did not clean cancelled work");
    await wait(10);
  } while (true);
  assert.deepEqual(finalStatistics, { active: 0, cancelled: 1 });
  console.log("discovery/success/unknown/invalid/not-found: passed");
  console.log("client cancelled; server active=0, cancelled=1; connection closed");
} finally {
  await client.close();
}
~~~
~~~text expect=S3-L02.mjs
discovery/success/unknown/invalid/not-found: passed
client cancelled; server active=0, cancelled=1; connection closed
~~~

**选做本地验证：**运行 npm run tutorial -- S3-L02。它先确认 slow 已启动再取消，避免只测到“尚未执行的预取消”。轮询有总期限，不能无限等待测试自行变绿。最后 close 放在 finally，即使断言失败也会清理子进程。

## 4. 从 stdio 迁移到 HTTP 时要重做什么

stdio 的宿主可以控制启动命令、环境变量和进程生命周期。远程 HTTP 会增加端点身份、凭证作用域、代理、连接复用与暴露面的假设。使用采用修订支持的 Streamable HTTP 实现，不能把旧 SSE 教程换个 URL 就称为同一协议。

这份实验未启动 HTTP MCP 服务。练习要求补独立验证矩阵：无凭证、错误受众、过期凭证、未知会话、超时、断连和重连。不要把本地 stdio 成功当远程认证通过。

## 故障练习与项目迁移

删掉 extra.signal，再运行。客户端会停止等待，服务端 active 仍为1，测试应失败。这是区分“请求不等了”和“工作取消了”的核心证据。把旧工具名留在发现缓存，记录清单版本与调用错误，避免盲目重试未知工具。

项目中增加受控错误分类、输入/输出大小、每次调用期限与总任务期限。提交六类互通结果与服务端资源清理，不把内部堆栈、Token 或敏感参数直接回给模型。
