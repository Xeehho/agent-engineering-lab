# S3-L03 MCP 权限、缓存与服务信任

**网页主线：直接阅读讲解 → 动手实验 → 随堂练习 → 公开自测 → 复习速记。无需启动项目、安装依赖或提供 API Key。**

本课网页任务：把缓存键只保留工单编号，复现两个租户相互串用。

网页实验范围：合成身份和内存数据验证权限逻辑，不是登录认证。

**选做实操说明：**下面涉及 Node、Python、数据库或 SDK 的环境、命令和完整文件供进阶使用，不是阅读本课的前置条件。


上一课证明协议互通，这一课验证“谁能读到什么”。实验使用 SQLite 与合成认证上下文，不实现 OAuth 或真实登录；它不代表远程认证已经安全，也不代表学习者已掌握。

## 1. 两条独立的信任线

你信任某个 Server 的维护者与代码，不意味着每个调用者都能读它的数据。服务来源、版本、运行权限是一条线；用户身份、租户、资源与操作授权是另一条线。两者都要成立。

模型参数 tenant=B 只是一段输入，不能替代服务端认证。MCP 的工具描述和返回文本也属于外部内容，不能自动取得 Host 的执行权限。远程 Token 需要校验签发者、受众、范围与期限，不能把本应用凭证随意透传到另一个 Server。

## 代码阅读：查询正确，缓存也要正确

### 先解释 readTicket 的两个参数

authenticatedContext 包含服务端确认的 tenant、subject、scopes 与 policyVersion；toolArguments 只有工单编号。示例身份是课堂夹具，真实项目须由认证中间件构建，不能从模型正文读取。

readTicket 先检查 scope，再校验参数，之后才允许命中缓存。若先返回缓存再校验权限，用户被撤权后仍可能重放旧结果。

### 用相同编号追踪两个租户

|请求|查询范围|可展示结果|
|---|---|---|
|Alice属于A，查T-1|tenant=A且id=T-1|A的订单错误|
|Bob属于B，查T-1|tenant=B且id=T-1|B的付款错误|
|Alice额外传tenant=B|参数不合约|拒绝|
|Alice的scope为空|权限不足|拒绝，即使缓存已存在|

SQL 只 SELECT id,title，不读取 internal_note。参数化防止值变成 SQL 语法，tenant 条件防止查询越权，它们解决不同问题。

### 缓存键与副本

缓存键包含租户、主体、权限范围、策略版本与工单编号，避免不同授权结果共享一份数据。返回 structuredClone，防止调用者改动共享缓存对象。真实资源 ACL 变更还需要失效策略；仅有 policyVersion 不会自动知道权限已变化。

### 带提示的练习

先把缓存键缩减为工单编号，复现B读到A结果；再恢复缓存键、删除SQL租户条件，观察正确缓存无法修复错误查询。每次只破坏一层，并用具体返回值解释原因。

## 2. 在数据层建立边界

相同 ticketId 在两个租户里可能都存在。查询必须带租户条件，输出再按字段白名单收敛。缓存还要包含所有影响结果的身份范围与版本；仅使用 query 或 ticketId 会串用结果。

### 完整实操文件：S3-L03.mjs

~~~js file=S3-L03.mjs
// 阅读顺序：权限检查 → 参数检查 → 范围缓存键 → 带租户查询 → 字段白名单。
import assert from "node:assert/strict";
import { DatabaseSync } from "node:sqlite";
const database = new DatabaseSync(":memory:");
database.exec(
  `
CREATE TABLE tickets (
  tenant TEXT,
  id TEXT,
  title TEXT,
  internal_note TEXT,
  PRIMARY KEY (tenant, id)
)
`,
);
const insert = database.prepare("INSERT INTO tickets VALUES(?,?,?,?)");
insert.run("A", "T-1", "A 的订单错误", "A 内部评审");
insert.run("B", "T-1", "B 的付款错误", "B 内部评审");
const cache = new Map();
// 返回当前授权范围的工单副本；缓存命中也必须先通过授权。
function readTicket(authenticatedContext, toolArguments) {
  if (!authenticatedContext || !authenticatedContext.scopes.includes("ticket:read")) {
    throw new Error("FORBIDDEN");
  }
  if (
    typeof toolArguments.id !== "string" ||
    Object.keys(toolArguments).some((k) => k !== "id")
  ) {
    throw new Error("INVALID_ARGUMENTS");
  }
  const cacheKey = JSON.stringify([
    authenticatedContext.tenant,
    authenticatedContext.subject,
    [...authenticatedContext.scopes].sort(),
    authenticatedContext.policyVersion,
    toolArguments.id,
  ]);
  if (cache.has(cacheKey)) {
    return structuredClone(cache.get(cacheKey));
  }
  const ticketRow = database
    .prepare("SELECT id,title FROM tickets WHERE tenant=? AND id=?")
    .get(authenticatedContext.tenant, toolArguments.id);
  const result = ticketRow ? { id: ticketRow.id, title: ticketRow.title } : null;
  cache.set(cacheKey, result);
  return structuredClone(result);
}
try {
  const tenantAContext = {
    tenant: "A",
    subject: "alice",
    scopes: ["ticket:read"],
    policyVersion: 1,
  };
  const tenantBContext = { ...tenantAContext, tenant: "B", subject: "bob" };
  assert.equal(readTicket(tenantAContext, { id: "T-1" }).title, "A 的订单错误");
  assert.equal(readTicket(tenantBContext, { id: "T-1" }).title, "B 的付款错误");
  assert.equal(cache.size, 2);
  assert.equal("internal_note" in readTicket(tenantAContext, { id: "T-1" }), false);
  assert.throws(
    () => readTicket(tenantAContext, { id: "T-1", tenant: "B" }),
    /INVALID/,
  );
  assert.throws(
    () => readTicket({ ...tenantAContext, scopes: [] }, { id: "T-1" }),
    /FORBIDDEN/,
  );
  const callerResult = readTicket(tenantAContext, { id: "T-1" });
  callerResult.title = "污染客户端对象";
  assert.equal(readTicket(tenantAContext, { id: "T-1" }).title, "A 的订单错误");
  console.log("tenant query + scoped cache + field allowlist: passed");
  console.log("model tenant rejected; permission checked before cached replay");
} finally {
  database.close();
}
~~~

tenant query + scoped cache + field allowlist: passed
model tenant rejected; permission checked before cached replay
~~~

**选做本地验证：**运行 npm run tutorial -- S3-L03。Map 这里只用于缓存，权限来自调用 read 之前的合成 auth；数据库查询是实际执行的。本课不把 Map 称为分布式缓存。

## 3. 代码保证与剩余假设

权限检查发生在缓存命中之前，所以权限撤回后不能沿旧结果直接返回。policyVersion 可帮助改变策略后隔离缓存，但版本必须由服务端治理。若资源 ACL 发生变化，还需要资源权限版本、主动失效或短 TTL；不能认为加入一个字段就解决所有撤权时效问题。

字段白名单在 SQL 层先不取 internal_note，减少敏感数据进入进程和日志。返回对象再复制，防止调用方修改共享缓存对象。更复杂的字段级权限需要不同结果范围与缓存键，不能只看租户。

参数化 SQL 防止值被当成语法，但不自动完成业务授权。多租户过滤如果忘了写，参数化查询仍会忠实地返回错误范围的数据。

## 4. Server 安装前的最小审查

列出它能读的目录、网络端点、环境变量、数据库账号和写操作。把“只读工单”的 Server 放在能访问所有本机文件和生产密钥的进程中，会扩大故障半径。凭证按服务受众与最小权限配置，避免把整个环境继承给未知子进程。

记录维护者、来源、固定版本与升级差异。工具描述更新可能改变模型选择行为，即使程序接口未变，也需要回归。声明 readOnlyHint 等元数据有助于 UI，但它不是强制授权，Host 不能只相信服务自报。

## 故障练习与项目迁移

先把缓存键改成 args.id，验证 B 读到 A 的标题；再去掉 SQL 的 tenant 条件，看正确缓存也无法挽救错误查询。最后给 A 撤回 scope，验证缓存命中路径仍拒绝。

项目中把 read 放到 MCP handler 后端，并从真实认证中间件取 auth，工具 Schema 不开放 tenant、role 或 scopes。提交正常、越权、撤权、缓存串用、字段泄露、污染输出六类证据。只做课堂合成 auth 时，报告里明确认证尚未接入。

## 单页速记

- 服务可信与用户有权限分别判断。
- 身份来自认证上下文，资源查询带授权范围。
- 缓存不是绕过授权的入口，撤权与版本要有失效策略。
- 工具描述、输出文本和注解不能自行提升权限。
