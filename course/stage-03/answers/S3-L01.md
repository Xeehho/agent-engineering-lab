# S3-L01 老师讲评：协议连接的是能力边界

## 老师怎么判断这类问题

先画职责，不先画三台机器：Host管理用户、模型和任务，Client在Host中说协议，Server提供能力。模型可以提出工具请求，但不会自动成为Client；Server返回资料也不意味着它就是Agent。再决定是否真的需要跨应用互操作。

## F1 · 入门练习 1

题目：增加第二个只读工具，说明清单与执行代码各改哪里。
### 参考回答

在server.tools清单增加第二个工具的名称与描述，并在server.call中增加对应执行分支及明确输入输出。只加清单会出现“发现得到、执行不了”，只加分支则Host可能不知道能力存在。

### 推导与反例

实际MCP还需输入Schema等契约、注册与权限检查。第二个工具应明确只读，并验证未知参数和不允许资源。网页只模拟对象转发，不能因新增两行就声称真实协议发现和调用通过。

### 自查要点

- 清单与执行一致，未知工具仍拒绝。
- 分别观察发现结果和实际调用结果。

## F2 · 入门练习 2

题目：指出本例模型在哪里：它其实没有接入。
### 参考回答

网页例子没有模型。顶层代码直接指定readTicket，client转发到server对象。它展示角色关系，未实现模型选工具、SDK连接、初始化或传输。

### 推导与反例

变量叫client不意味着发送了MCP报文，返回工具资料也不意味着发生推理。真实应用会把允许的工具契约交给模型，收到提议后经执行检查再调用Client；进阶实验先证明本地SDK互通，仍不包含模型决策质量。

### 自查要点

- 找出谁直接指定工具名。
- 列出网页、真实SDK和真实模型三个不同验证范围。

## F3 · 入门练习 3

题目：画Host包住Client、Client连接Server的图。
### 参考回答

画成“Host应用〔用户界面、可信身份、任务、模型适配、MCP Client〕→连接→MCP Server→业务数据”。Client在Host内部，Server可独立进程；模型与Client是协作组件，不是同一角色。

### 推导与反例

角色可部署在同机或跨机，并非必须三台电脑。Host控制允许操作，Server/业务层仍按身份检查资源权限；跨进程不会让原工具自动安全。箭头应标发现与调用，而非写“Server替Host完成全部授权”。

### 自查要点

- Client被包含在Host内，模型和业务数据位置清楚。
- 图里标可信身份与实际业务执行点。

## C1 · 解释关键机制

题目：画出 Host、Client、Server 和模型的关系；说明权限判断分别在哪里。
### 参考回答

Host组织模型、用户、任务、工具审批；Client维护与某Server的协议连接；Server暴露工具等能力并执行业务边界。模型提议经Host的检查送到Client，结果回Host上下文。Host限制可用能力，Server与业务数据层再次核验当前身份、租户和资源范围。

### 推导与反例

不能把一次连接认证当作所有工单都可读。发现清单可以过滤，但执行前仍需检查；模型参数中的tenant不可信。图应区分协议、身份和业务调用，避免把工具名或Server描述当授权依据。

### 自查要点

- 能解释每个箭头的数据与责任。
- 跨租户与撤权测试在实际执行处失败。

## C2 · 定位一个反例

题目：如果只是同一个 Node 服务内部调用函数，什么需求会让你决定引入 MCP？
### 参考回答

若多个AI应用需要复用同一套能力、服务需独立运行或跨语言实现、希望通过统一发现和契约接入，可考虑MCP。同一Node进程内稳定调用普通函数，没有这些需求时，直接函数或既有API通常更易验证。

### 推导与反例

协议会引入生命周期、版本、传输、错误、权限和观测成本。不是用了MCP就更智能或更安全。比较改动范围、接入方数量与维护成本，再留下架构决策记录；别为了展示技术名词绕一层无收益连接。

### 自查要点

- 给出明确互操作需求和简单替代方案。
- 说明新增成本与何种条件下撤回协议层。

## C3 · 定义验证证据

题目：写一份实际互通验证清单：协议/SDK 版本、发现结果、调用输入、输出与失败。
### 参考回答

记录锁定运行环境、SDK版本、采用/协商协议修订、服务启动与初始化、发现的工具契约、一次合法输入与关联结果。再验证未知工具、非法参数、业务错误、取消/超时、关闭清理和stdout诊断隔离，保存命令与脱敏记录。

### 推导与反例

本仓库SDK1.32.2默认提议2025-11-25，不能把新网站修订直接套到这个实验。真实进程互通不代表远程OAuth、数据库授权或模型选工具正确；每种结论按实际证据另列。

### 自查要点

- 发现、调用、业务结果和清理分别有观察。
- 不把网页模拟、SDK默认提议和最终协商结果混称同一证明。

## FQ1 · MCP的Client通常在哪个角色内？

题目：MCP的Client通常在哪个角色内？

- A. Host应用内
- B. 模型权重里
- C. 数据库索引内
- D. 必须在第三台电脑

参考选择：A. Host应用内
Client通常是Host内部的协议组件，不在模型权重或数据库索引中，也不要求第三台电脑。先按职责判断位置，再讨论部署。Host可以含多个连接组件，但应用策略与业务授权仍需独立实现。

## FQ2 · 网页对象转发演示证明了什么？

题目：网页对象转发演示证明了什么？

- A. 真实SDK握手已通过
- B. 远程认证已完成
- C. 模型会选对工具
- D. 角色与发现调用的关系

参考选择：D. 角色与发现调用的关系
网页对象转发只证明角色与发现/调用关系。没有SDK握手、远程认证或模型决策，所以其他扩大结论不成立。真实本地Server/Client实验能增加协议路径证据，但仍不能证明模型会选择正确工具。

## Q1 · MCP 主要解决哪类问题？

题目：MCP 主要解决哪类问题？

- A. AI 应用与工具/上下文服务的互操作
- B. 自动替代业务权限
- C. 训练一个新模型
- D. 保证 Agent 永远答对

参考选择：A. AI 应用与工具/上下文服务的互操作
MCP主要解决AI应用与工具/上下文服务的互操作。它不是模型本身，不自动提供完整Agent执行策略，也不能替代业务权限。判断接入是否成功要看真实初始化、发现和调用，而不是只有角色图或安装日志。

## Q2 · Host 与 Client 的关系可以是？

题目：Host 与 Client 的关系可以是？

- A. 必须各用一台服务器
- B. Client 就是模型权重
- C. Server 永远运行在浏览器
- D. Client 是 Host 内的协议组件

参考选择：D. Client 是 Host 内的协议组件
Client可以作为Host内的组件，负责某个Server的协议连接。Host还包含UI、模型与任务管理，不能把它们都等同为Client。Server的业务函数即使独立部署，也不会自动承担Host的用户交互和全部授权决策。

## Q3 · 看新版规范前应先记录什么？

题目：看新版规范前应先记录什么？

- A. 只看教程发布日期
- B. 不需要版本
- C. 实际采用的协议修订与 SDK 版本
- D. 只记流行框架名字

参考选择：C. 实际采用的协议修订与 SDK 版本
先记录实际协议修订与SDK版本，再读对应文档。规范会演进，旧SDK可能不支持新字段或生命周期。依赖锁文件、初始化观察和版本化官方来源一起使用，不能以“官网最新”替代本实验采用的契约。
