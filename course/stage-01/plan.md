# 第一阶段：从模型响应到可信的分诊接口

目标：你可以借助AI独立做出一个可验证的AI应用模块，并解释从输入、模型响应到前端结果的所有关键路径。

建议总投入8–14小时，分3个项目单元、模型基础/Python桥接与一次考试；这是安排参考，达到验收即可提前交卷。初始诊断不计分。教材均可提前阅读，材料开发不等待作答。

## 单元A：定义正确，约1.5–2小时

先读lesson.md第1–3节和assignment.md契约。

当前授课材料：[S1-L01完整讲义](lessons/01-success-contracts.md)、[随堂题](exercises/01-checkpoint.md)；先完成C1–C3，再推进本单元实现。

- 完成S1-T1输入校验、S1-T2 Prompt与输出契约。
- 为正常、缺失、非法JSON、字段错误分别写出预期，再让AI实现。
- 画出浏览器 → API → provider → 校验 → UI的数据流。
- 回答questions.md中的Q1–Q4。

验收：解释TypeScript类型与运行时数据的关系；正常fixture正确返回，非法输入／输出分开分类。

## 单元B：处理失败，约2–3小时

- 完成S1-T3超时、取消、错误分类和验证来源。
- 跑practice:stage1，亲自定位至少一个失败。
- 为未覆盖的边界追加3条有意义测试；不能只复制已有案例。
- 回答Q5–Q8，完成D1、D2排错报告。

验收：超时具有有限截止时间，上游收到取消；已经取消的请求不发模型调用；不把错误包装成成功。

## 单元C：做成产品，约2–3小时

- 完成S1-T4流式接口和React流式面板。
- 完成S1-T5证据与复盘。
- 验证事件顺序、终止、浏览器取消、服务端取消及刷新后的展示约定。
- 完成D3、D4，并回答Q9–Q12。

验收：HTTP头写出前后的错误路径都可解释；显示的mock/live、模型、Prompt版本和usage与实际一致。

## 真实模型接入加题 S1-X1

已有可用API时，自行实现一个live provider，并使用本机环境变量接入。提交脱敏后的模型名、日期、输入、响应、用量与失败案例。不要提交Key。

没有授权API时保持Mock完成阶段考试，记录live_pending。Mock不能证明模型分类准确率；真实接入与效果作为后续毕业前的必补证据。
