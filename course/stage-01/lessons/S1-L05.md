## 本课目标

- 理解生成与训练的区别
- 管理上下文而不是无限追加
- 选择改进手段并做对照

## 1. 理解生成与训练的区别

语言模型将文本表示为 token，并在上下文条件下产生后续 token；常见 Transformer 架构利用注意力整合位置之间的信息。它不会因为输出语气自信就拥有事实依据。预训练学习广泛统计规律，后训练调整任务与指令行为，推理则使用已有权重处理这次输入；一次聊天不会自动更新模型权重。

## 2. 管理上下文而不是无限追加

上下文窗口是一次请求可处理信息的容量约束，不能用字符数精确等同 token 数；工具描述、历史、检索片段和输出预算都要考虑。长对话需要选择、摘要或外部状态，但摘要可能丢失否定、权限和关键事实。把可靠业务状态存入数据库，不能只保留在自然语言历史里。

## 3. 选择改进手段并做对照

采样设置影响输出分布，低 temperature 不构成业务正确或跨版本完全复现保证。RAG 补充可更新的外部证据，微调调整行为或特定分布，二者都需要评测；不要把微调当作任意最新知识库。比较模型时固定任务集、Prompt 和规则，记录质量、延迟、上下文及实际费用来源，不给模型排行榜背书。

## 实验：上下文预算是怎样超掉的？

先预测输出，再运行并修改一个条件。这是教学用的 JavaScript 机制演示，不是真实模型、数据库、协议 SDK 或生产系统。

~~~js
const budget = 12000;
const usage = {system:1000, tools:1800, history:5000, evidence:2800, outputReserve:2000};
const planned = Object.values(usage).reduce((a,b) => a+b,0);
console.log({planned,budget,excess:Math.max(0,planned-budget)});
console.log("数值是假设的 token 计数，不是分词器结果");
~~~

观察方向：计划总量为 12600，超出 600；真实计数与限制必须依据实际模型协议。

提示：输出预留也会占容量规划；不能把字符数冒充计费 token。
