## 1. 模型收到的不是“完整理解后的中文句子”

文本先经 tokenizer 转成 token 序列。token 可能是词、词的一部分、符号或其他片段，取决于词表与编码方法。字符数、单词数、汉字数不能直接替代某个模型的 token 计数。

常见自回归语言模型在已有上下文条件下，对下一个 token 给出分布，再逐步生成。训练时通常通过大量样本调整参数以减少预测误差；推理时使用已训练的权重计算输出。把新信息放进这次 Prompt，不等于把它写进了全局模型权重。

“预测后续 token”不意味着输出只有低层拼字：模型可以形成复杂模式与能力。但它的自信语气不是事实来源，正确性仍由任务、数据与证据判断。

## 代码阅读：亲手算一次概率与容量

### 先把名词落到数字

logit 是模型给候选项的原始分数，不是已经归一化的概率。softmax 把一组分数变成正数并除以总和。temperature 是缩放分数差异的参数；本例只研究数学变化，没有真正生成一句话。

输入 [2,1,0]、温度1。先减最大值2，得到 [0,-1,-2]；取指数约为 [1,0.368,0.135]；总和约1.503；最后的概率约为 [0.665,0.245,0.090]。温度0.3时，最大项概率约0.964，分布更集中。

### 按三步读 softmax

~~~js
const scaledLogits = logits.map((value) => value / temperature);
const largestLogit = Math.max(...scaledLogits);
const exponentials = scaledLogits.map(
  (value) => Math.exp(value - largestLogit),
);
~~~

减去同一个数不会改变最终概率比例，却能降低指数溢出的风险。程序还拒绝空数组、NaN、Infinity 和非正温度，避免产生看似有结果的无效数值。真实模型的采样参数支持范围由具体服务决定，不能直接用这份函数替代服务协议。

### 容量预算与概率是两条独立逻辑

|项目|题目给定单位|累计|
|---|---|---|
|系统指令|1000|1000|
|工具描述|1800|2800|
|历史|5000|7800|
|证据|2800|10600|
|输出预留|2000|12600|

假设总容量12000，就超出600。降低 temperature 不会减少这些输入占用。你应减少、筛选或压缩上下文，核查输出预留，并使用所选模型的实际计数与限制；这里的规划单位没有证明真实 token 数。

### 带提示的练习

先手算 [0,0] 的概率；再预测给所有 logit 同时加100，结果应怎样。对于容量问题，尝试只删历史600单位，并说明压缩时哪些否定、权限和任务状态不能丢。不要用“把温度调低”回答知识缺失或授权问题。

## 2. Transformer 和注意力需要理解到什么程度

应用开发至少应理解：输入被编码为向量，注意力让位置之间的信息相互作用，后续层产生用于预测的表示。位置与上下文、长度和任务形式会影响结果。这里只建立机制认识，不从一个二维向量演示声称实现了完整 Transformer。

生成时的 logits 经概率化处理后用于选 token。temperature 会调整分布尖锐程度；不同服务/模型对参数支持也不同。即使选最可能 token，数据、版本、执行环境与业务不确定性仍然存在，不能宣布业务绝对正确。

## 3. 分步实验：分布与预算是两种约束

**选做本地验证：**运行 node examples/tutorials/S1-L05.mjs。先预测温度变低后最大概率是否上升，再看上下文规划是否超限。这里的 logits 和 token 数均为合成值，不是某个服务的实测。

### 完整实操文件：S1-L05.mjs

~~~js file=S1-L05.mjs
import assert from "node:assert/strict";

function softmax(logits, temperature) {
  if (!Number.isFinite(temperature) || temperature <= 0) {
    throw new Error("TEMPERATURE_MUST_BE_POSITIVE");
  }
  if (logits.length === 0 || logits.some((value) => !Number.isFinite(value))) {
    throw new Error("LOGITS_MUST_BE_FINITE");
  }

  // 步骤一：缩放分数。温度低时，分数差异被放大。
  const scaledLogits = logits.map((value) => value / temperature);

  // 步骤二：减去最大值，避免 exp(很大的数) 溢出。
  const largestLogit = Math.max(...scaledLogits);
  const exponentials = scaledLogits.map((value) => Math.exp(value - largestLogit));

  // 步骤三：除以总量，使概率之和接近1。
  const exponentialSum = exponentials.reduce((sum, value) => sum + value, 0);
  return exponentials.map((value) => value / exponentialSum);
}

const normalDistribution = softmax([2, 1, 0], 1);
const sharperDistribution = softmax([2, 1, 0], 0.3);
assert.ok(sharperDistribution[0] > normalDistribution[0]);
const probabilitySum = sharperDistribution.reduce((sum, value) => sum + value, 0);
assert.ok(Math.abs(probabilitySum - 1) < 1e-9);
assert.throws(() => softmax([1, 2], 0), /POSITIVE/);
assert.throws(() => softmax([], 1), /FINITE/);

// 这些数字是题目给定的规划单位，不来自 tokenizer，也不来自账单。
const assumedTokenPlan = {
  system: 1000,
  tools: 1800,
  history: 5000,
  evidence: 2800,
  output: 2000,
};
const plannedTotal = Object.values(assumedTokenPlan).reduce(
  (sum, tokenCount) => sum + tokenCount,
  0,
);
const assumedCapacity = 12000;
const exceededBy = Math.max(0, plannedTotal - assumedCapacity);
assert.equal(plannedTotal, 12600);
assert.equal(exceededBy, 600);

console.log("lower temperature: sharper distribution, not a truth guarantee");
console.log("planned=12600; assumed budget=12000; excess=600");
console.log("synthetic numbers; not a tokenizer or provider invoice");
~~~
~~~text expect=S1-L05.mjs
lower temperature: sharper distribution, not a truth guarantee
planned=12600; assumed budget=12000; excess=600
synthetic numbers; not a tokenizer or provider invoice
~~~

减去 max 是数值稳定处理，不改变 softmax 的相对结果。示例拒绝 0，是为了避免除零；真实服务如何表达贪心选择，要查实际协议，不能直接把这个函数当作服务端采样器。

## 4. 上下文不是免费的数据库

系统指令、工具描述、历史、检索片段和输出预留都会影响容量规划。不同服务对输入/输出上限和缓存计量有不同规则，实际接入用它的计数与限制。示例的简单相加只是规划练习。

历史不断累加，会挤占证据与输出空间。摘要可以压缩，但可能丢失否定、权限与业务状态。把“已经创建工单、确认的是哪个参数版本、当前任务状态”存入可信系统，再挑选相关信息给模型，而不是指望对话永远记住。

故障练习：假设摘要漏掉“不能发送外部邮件”。你应恢复程序的权限控制与确认绑定，而不是只要求模型“记性好一点”。

## 5. 用问题选择改进手段

如果格式经常不合约，先明确任务与结构约束，应用仍做运行时检查。如果缺少最新业务知识，考虑带版本和权限的检索/工具。如果目标是稳定遵循某类行为或专门分布，再评估微调是否值得，并保留独立评测。

RAG 不自动让错误文档变真；微调不等于任意实时知识库；更大模型也不修复服务器越权或重复写入。先定位错误属于哪一层，再选改进手段。

## 6. 写一份模型选择 ADR

先固定任务集、Prompt、工具和评分口径，比较至少一个简单基线与候选。记录质量、完成/拒答、延迟、上下文要求、实际用量与费用来源。只比较单次最佳截图会把随机性当成进步。

ADR 至少写：业务约束、候选、选中理由、已知代价、未验证条件、何时重新评估。例如“在固定分诊样本达到最低质量前，不以低价模型替换；到达费用上限时只输出检索证据并标明降级”。这比列排行榜更接近工程决策。

## 单页速记

- token 不等于字符；推理不自动更新模型权重。
- 采样影响分布，不提供业务正确保证。
- 上下文需要选择；可靠业务状态要持久化。
- 先定位问题，再比较 Prompt、检索、微调与模型方案。
