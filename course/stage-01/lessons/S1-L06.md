## 先把概念讲清楚

后端服务在这里做三件事：接收 HTTP 请求、验证输入、调用业务函数并返回结果。路由是把“请求方法+路径”映射到处理函数的规则；框架是替你处理协议细节的工具库。Python 的 def 类似 JS 函数声明，dict 类似普通对象，async def 表示可异步等待的函数，并不自动把阻塞计算移出线程。

网页先用熟悉的 JavaScript 观察边界。进阶代码使用 Python、FastAPI 和验证模型，语法不同，但输入输出责任相同。

## 名字与字段从哪里来

|名字或字段|来源与含义|
|---|---|
|body|HTTP请求体解析后的课堂对象；不是可信身份|
|status / json|课堂模拟响应字段，不是原生 Response 实例|
|handle|课堂模拟路由函数；FastAPI 实际用装饰器登记路由|
|400 / 200|HTTP标准状态码；本例演示校验失败/成功；真实框架可能用422表示校验失败|

## 先读这个最小例子

在网页“动手实验”直接运行。先读输入，再找检查和输出；assert 是课堂提供的检查函数，不是模型能力。

~~~js
function handle(body) {
  if (!body || typeof body.text !== "string" || !body.text.trim()) {
    return { status: 400, json: { error: "需要非空text" } };
  }
  // 固定规则替身，不调用模型。
  return { status: 200, json: { group: "技术支持" } };
}
console.log(handle({ text: "" }).status);
console.log(handle({ text: "订单页白屏" }).json.group);
assert.equal(handle(null).status, 400);
~~~
## 运行结果与逐步解释

~~~text
400
技术支持
~~~

空文本在入口返回400，业务分组逻辑不执行；有效文本到固定分组。真正的 Python 路由还需要请求体模型、异常映射、认证和取消传递。网页没有启动 Python，也没有建立网络连接。先能解释这两个分支，再展开 Python 对照代码逐段读。

## 1. 不从语法大全开始，先追一次请求

你已有前端基础，先找这条路径：JSON 请求 → 路由 → 输入模型 → 业务操作 → 响应模型 → 调用方。Python 的 dict/list 对应常见对象/数组容器，函数和异常也承担类似职责；类型提示只描述意图，不会自动验证所有外部对象。

FastAPI 配合 Pydantic 的输入模型会实际执行验证，这与只在函数参数上写一个普通类型注解不同。默认类型转换策略也需要留意：若业务不接受字符串 "8" 当整数，就明确使用严格整数，而不是凭注解猜行为。

## 代码阅读：从前端请求追到 Python 路由

### 把新语法对应到已有经验

class ReadingIn 定义输入模型，作用类似“字段定义加运行时验证”；普通 Python 类型提示本身不承担全部验证。@app.post 是路由注册装饰器，把下面函数绑定到 POST /readings。async def 声明协程，await 等待它完成，async with 管理异步上下文的进入与退出。

不要一次背全套 Python 语法。先沿一条请求阅读：client.post 提交 JSON → FastAPI 用 ReadingIn 验证 → read_reading 设置期限 → process_reading 执行 → ReadingOut 检查响应 → client 收到结果。

### 跟踪正常与超时路径

|输入|是否进入 process_reading|结果|active 最终值|
|---|---|---|---|
|value=8|进入|200，value=16|0|
|value是字符串8|不进入|422|0|
|value=-1|不进入|422|0|
|value=8，delay_ms=200|进入后被期限取消|504|0|

process_reading 先把 active 加1。正常返回和取消都会进入 finally 减1。20毫秒期限短于200毫秒等待，所以 timeout 将取消传到 await asyncio.sleep，并由路由映射为504。

~~~py
async with asyncio.timeout(0.02):
    doubled_value = await process_reading(data)
~~~

这段控制的是协作式异步等待。换成 time.sleep 后，事件循环可能被阻塞，不能因为外面仍有 async 就认为期限同样有效。

### 测试到底在哪里执行

ASGITransport 直接把 HTTP 风格请求交给本进程 app，不开监听端口。base_url 只是构建请求地址，classroom 不是本课要访问的远程服务器。直接运行文件才调用 asyncio.run(verify_routes())；被 ASGI 服务器导入时只创建 app。

## 3. 分步实现输入、操作与响应

先预测四种请求会返回什么：合法整数、字符串整数、负数、耗时超过期限。再运行本课文件核对。演示领域是读数，不直接代做工单分诊作业。

### 完整实操文件：S1-L06.py

~~~py file=S1-L06.py
import asyncio

from fastapi import FastAPI, HTTPException
from httpx import ASGITransport, AsyncClient
from pydantic import BaseModel, Field, StrictInt

app = FastAPI()
app.state.active = 0


# 输入模型会在路由执行前验证 JSON。StrictInt 不把字符串 "8" 转成整数。
class ReadingIn(BaseModel):
    value: StrictInt = Field(ge=0)
    delay_ms: StrictInt = Field(default=0, ge=0, le=1000)


class ReadingOut(BaseModel):
    value: int
    source: str


async def process_reading(data: ReadingIn) -> int:
    app.state.active += 1

    try:
        # await 让当前协程等待，事件循环可以处理其他工作。
        await asyncio.sleep(data.delay_ms / 1000)
        return data.value * 2
    finally:
        # 无论正常返回、异常还是取消，都释放本任务的活动计数。
        app.state.active -= 1


@app.post("/readings", response_model=ReadingOut)
async def read_reading(data: ReadingIn):
    try:
        async with asyncio.timeout(0.02):
            doubled_value = await process_reading(data)

        return {"value": doubled_value, "source": "local"}
    except TimeoutError:
        raise HTTPException(status_code=504, detail="DEADLINE_EXCEEDED")


async def verify_routes():
    # ASGITransport 在进程内调用 app，不会启动 TCP 监听端口。
    transport = ASGITransport(app=app)

    async with AsyncClient(transport=transport, base_url="http://classroom") as client:
        valid_response = await client.post("/readings", json={"value": 8})
        assert valid_response.status_code == 200
        assert valid_response.json()["value"] == 16

        string_response = await client.post("/readings", json={"value": "8"})
        assert string_response.status_code == 422

        negative_response = await client.post("/readings", json={"value": -1})
        assert negative_response.status_code == 422

        slow_response = await client.post(
            "/readings",
            json={"value": 8, "delay_ms": 200},
        )
        assert slow_response.status_code == 504
        assert app.state.active == 0

    print("ASGI: valid=200; string=422; negative=422; deadline=504")
    print("active=0; no model calls; not a public deployment test")


# 被 ASGI 服务器导入时只创建 app；直接运行文件时才执行课堂验证。
if __name__ == "__main__":
    asyncio.run(verify_routes())
~~~

## 4. 对照 TS 阅读，而不是逐行翻译

ReadingIn 同时参与参数描述与框架的运行时验证；StrictInt 与 ge=0 是实际输入约束。ReadingOut 约束响应。process_reading 的输入已通过这一层，不代表其中任何业务结论都天然正确。

async def 返回协程，遇到 await asyncio.sleep 时允许其他工作推进。把它换成 time.sleep，并不会因为外层仍写着 async 就保持非阻塞。数据库和 HTTP 客户端是否异步，要看实际库接口。

asyncio.timeout 超时会取消当前等待，让 process_reading 的 finally 执行。这里只证明协作式 sleep 的清理；如果你吞掉取消异常、调用阻塞函数，或操作另一个不支持撤销的系统，结论就不同。

## 5. 亲自制造三个错误

将 StrictInt 改成普通 int，再发字符串 "8"，核对框架是否转换；然后解释为什么业务需要明确策略。将 active 的清理删除，超时后的计数断言应失败。

把 asyncio.sleep 换成阻塞等待后，不要单凭单请求返回来判断并发正确。你需要再设计两个同时请求的观察，记录第二条请求何时开始/结束。本课测试客户端也不验证代理、真实 TCP 断开或多进程部署。

实际本地服务还需要 ASGI 服务器、固定监听地址、CORS/代理和配置。先把 /readings 路由独立验证，再让 React 经应用代理请求；不要把模型 Key 放进前端。
