# S1-L04｜验证证据与第一阶段交卷

教材状态：已编写，可提前学习；不代表学习者已作答或通过考试。
阶段：01 模型应用基础。先修：能阅读 JavaScript / TypeScript。
建议投入：35–60 分钟 + 项目练习。允许 AI 协作，要求本人解释与验证。

## 本课目标

- 把主张与证据一一对应
- 用失败路径证明你读懂代码
- 形成可审阅的提交

## 1. 把主张与证据一一对应

“接口可靠”过于宽泛。把它拆成非法输入被拒绝、非法输出被识别、超时不悬挂、取消传递、终态正确等主张，每条写出输入、预期、实际结果、命令和 commit。截图只能证明截图出现的状态，不能替代服务日志、断言或源码追踪。

## 2. 用失败路径证明你读懂代码

先运行一次你知道会失败的案例，解释失败发生在哪个边界，再做最小修复并跑相关回归。如果修复只是把 expected 改成 actual，必须证明原来的业务约定确实需要修改。使用 AI 后仍需说明哪一段由你判断、哪一段由 AI 生成、你检查了哪些假设。

## 3. 形成可审阅的提交

提交 README、数据流图、契约、运行命令、失败复盘、AI 协作记录和未验证项。Mock 与真实模型分开列；没有授权 Key 时可以交离线阶段，但真实接入待补。公开自测满分不替代阶段项目和答辩，本课不预先暴露正式变式题。

## 动手验证

先写预测，再运行，最后修改一个条件观察反例。不要把网页机制演示当成真实基础设施验证。

## 实验：证据矩阵缺了什么？

先预测输出，再运行并修改一个条件。这是教学用的 JavaScript 机制演示，不是真实模型、数据库、协议 SDK 或生产系统。

~~~js
const evidence = [
 {claim:"输入校验", expected:400, actual:400, environment:"local"},
 {claim:"模型准确率", expected:"有标注评测集", actual:null, environment:"mock"}
];
for (const item of evidence) console.log(item.claim, item.actual === item.expected ? "有对应观察" : "证据不足");
~~~

观察方向：第二条证据不足。第一条也只证明这一条本地案例，不代表所有输入。

提示：检查证据支持的范围和环境。

## 本课项目任务

S1-T5：按现有提交模板交卷；保留全量校验结果、至少一个故障复盘和证据边界。

先写你预期的行为，再让 AI 协作实现。提交具体 commit、输入、预期、实际、命令、失败复盘与未验证项；本教材不代做学习者项目。

## 本阶段验收边界

- 输入与输出分别验证，保持业务规则与结构校验分离
- 有限超时、取消、流式终态与晚到事件处理
- 公开练习与失败复盘可复现，Mock/真实验证分别记录
- 能读懂 Python 最小路由与异步边界，不要求重复语言入门

## 练习与考核

随堂开放题需本人解释，自测为公开练习，不计正式成绩。正式考试在阶段交卷后生成新的概念与故障变式。
