# S1-L03 速记

## 三个关键判断

- 区分字节、消息与任务事件：流式传输一次 read 得到的 chunk 不是完整业务事件：一个事件可能被拆开，多个事件也可能合并到一个 chunk。
- 设计可验证的 UI 状态机：从 idle 到 running，再到 succeeded、failed 或 cancelled，终态之后拒绝旧 delta。
- 选择传输与处理失败：原生 EventSource 的用法与 fetch 流式读取不同；需要 POST 请求体或特定头时，应依据接口契约选传输。

## 代码阅读检查

- 数据与身份来自哪里？
- 哪一步真正验证或执行了约束？
- 哪类失败会被拒绝，何时停止或恢复？
- 证据来自机制演示、Mock、真实服务还是生产？结论有多大范围？
