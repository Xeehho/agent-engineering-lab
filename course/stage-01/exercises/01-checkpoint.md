## C1 进阶选做 · 这个结果该在哪一层处理？

输入：登录按钮点击后没有反应。接口 HTTP 200，字段全部符合课程契约。哪些检查通过了？哪里仍有问题？改写 TypeScript 类型能解决吗？

~~~text
{
  "category": "feature", "priority": "medium",
  "summary": "新增登录按钮动画", "missingInformation": []
}
~~~

提示：把“调用状态”“字段约束”“内容与输入的关系”分别说明，不要合成一个成功标志。

## C2 进阶选做 · 没有解析错误就能显示吗？

JSON.parse 成功。你会让页面显示“分诊完成”吗？指出一个可以由程序确定检查的规则。

~~~text
{"category":"question","priority":"low","summary":"   ","missingInformation":[]}
~~~

提示：考虑字符串长度与去除两侧空白后长度的区别。

## C3 进阶选做 · as 到底改变了什么？

运行时 result.value 是什么类型？谁负责保证它是数字？解释编译器与实际数据之间的关系。

~~~text
type Reading = { value: number };
const result = JSON.parse('{"value":"8"}') as Reading;
~~~

提示：对照实验 01；这段是 TypeScript 阅读题，网页实验运行的是去除类型后的 JavaScript。

## C4 进阶选做 · 合法 JSON 的边界

分别解释以下文本被 JSON.parse 后得到什么，以及能否直接当作工单分诊对象使用。

~~~text
null
[]
"done"
42
{"category":"bug"}
~~~

提示：成功解析只回答语法问题。为每个值继续检查外层结构和必需字段。

## C5 进阶选做 · 你会怎样要求 AI 改代码？

AI 提出：“用 JSON.parse 加 as 就够了，只要不抛异常就返回成功。”写一段修正要求，包含任务边界、失败类型和验证证据，不要粘贴完整实现。

提示：先描述预期行为与失败分类，再要求提供可复现的检查。你要能解释证据支持的范围。
