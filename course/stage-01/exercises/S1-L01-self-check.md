# S1-L01 公开自测与解析

这是公开练习，不是正式考试。HTML 默认在提交后显示解析；此文件公开保留课程内容。

## FQ1 JSON能解析就能直接分诊吗？

- A. 能，HTTP成功足够
- B. 只要有group字段就行
- C. 还需类型、业务与正确性检查
- D. 能，JSON已经保证语义

公开解析：C。JSON解析只把文本变成值，不能判断类型约束和真实业务。

## FQ2 group为数字7时，最小例子在哪层拒绝？

- A. 真实模型评测
- B. 字段类型检查
- C. 网络连接
- D. 业务分组名单

公开解析：B。它是合法JSON，但group不是约定的字符串。

## Q1 Fetch 收到 HTTP 503，首先应怎么判断？

- A. 只要没有进入 catch 就算成功
- B. 检查 response.ok / status，并识别这是哪个接口的响应
- C. 强制断言为业务结果
- D. 直接显示完成

公开解析：B。Fetch 对 HTTP 错误状态仍可能返回 Response；还需区分浏览器到应用、应用到模型两次调用。

## Q2 JSON.parse('null') 没抛错，可以说明什么？

- A. 已经是工单对象
- B. JSON 语法合法，但仍需检查业务对象契约
- C. 包含所有必需字段
- D. 模型理解了任务

公开解析：B。合法 JSON 可以是 null、数组或基本值。解析成功不等于结构与字段合格。

## Q3 把外部值写成 as Reading，运行时会发生什么？

- A. 自动把字符串转成数字
- B. 自动拦截非法值
- C. 不会增加运行时检查，也不会转换原值
- D. 自动补全缺失字段

公开解析：C。类型断言在编译时移除。必须用实际运行的校验检查外部值。

## Q4 summary 只有三个空格，属于本课的哪类失败？

- A. 数据契约中的非空字段约束失败
- B. 网络连接失败
- C. 单凭这一点可证明分类正确
- D. 没有失败，字符串都合法

公开解析：A。课程要求摘要去除空白后非空。这是可由程序确定检查的局部字段约束。

## Q5 字段完全合法，却把白屏故障写成新增需求，主要还需验证什么？

- A. TypeScript 能不能编译
- B. JSON 是否有缩进
- C. HTTP 是否是 200
- D. 内容是否忠于输入、符合业务规则

公开解析：D。结构满足约束不代表内容正确，需要样例、业务规则与证据支持。

## Q6 固定 Mock 的四个演示全部通过，能支持什么结论？

- A. 真实模型准确率达到 100%
- B. 本地演示路径符合观察，真实模型效果仍待验证
- C. 第一阶段正式考试通过
- D. 所有真实输入都可靠

公开解析：B。Mock 用于工程行为验证。课堂自测、基础 CI 与正式阶段考核彼此独立。
