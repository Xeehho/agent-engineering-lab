# S8-L01 毕业项目：从需求到可验收作品

目标作品是一个“有证据、可恢复的研发工单助手”，让你的 React 经验成为 AI 工程的产品优势。本课执行验收证据审计，未替你完成毕业作业，不代表学习者已掌握。

## 1. 用一个真实用户路径收敛范围

用户提交问题 → 识别意图 → 授权检索工单与文档 → 生成带来源的草稿 → 人工确认 → 幂等写入 → 可追踪与恢复。先实现这条纵向路径，再考虑更多角色和功能。

需求至少写清角色、输入、可执行动作、权限、缺信息行为、失败恢复与成功证据。不要以“用了 RAG、MCP、多 Agent”作为用户价值；它们是实现选择，必须解释为什么需要。

将验收拆成可观察条件：跨租户拒绝、引用可还原、超时清理、任务重启恢复、审批变更失效、重复写不增加记录、关键回归门槛。每条绑定测试、日志或演示，而非只有一个勾。

## 3. 项目结构与里程碑

前端负责任务状态、流式输出、来源、审批与错误恢复；后端负责身份、执行控制、数据库、模型适配与工具；数据层负责版本、权限、索引与删除；质量层负责评测、观测与发布门槛。

第一个里程碑只做固定 workflow 和本地夹具，验证纵向路径；第二个接真实数据与检索，对照基线；第三个在授权范围接模型与评测；第四个演练恢复、部署与展示。每个里程碑都有可运行 commit 和未验证清单，不按日历自动过关。

## 4. AI Coding 的学习要求

你可以让 Agent 写代码，但要能指出可信输入在哪里、哪个函数会产生副作用、哪个条件阻止越权、超时如何传播、哪些证据支持结论。要求先预测，再运行，再解释差异，最后做一个未知变更。

保留 AI 协助范围：生成了什么、你修改了什么、你怎样验证。作品集说明 AI Coding 的工程过程比伪装手写更有说服力。考试会要求你独立解释和排查变式，不能只背这份教程的输出。

## 故障练习与项目迁移

给旧 commit 的截图贴上新版本名称，检查审计如何发现。用 fixture-test 替代 live-eval，说明为什么不满足模型质量。构造“测试通过但用户路径失败”的场景，补浏览器与请求副作用证据。

毕业交付至少有需求、架构、启动、数据与权限、评测、故障恢复、部署、演示和限制说明。实际证据未齐全时保留 unverified，不写“生产可用”。老师按真实提交逐项验收，再安排未公开变式考试。

## 单页速记

- 一个完整用户路径优先于堆技术名词。
- 每条需求绑定当前 commit 的合适证据。
- 证据元数据可检查，内容仍需审阅。
- AI 可以写代码，判断、解释、排错与责任需要你掌握。
