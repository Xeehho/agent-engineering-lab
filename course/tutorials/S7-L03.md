# S7-L03 上线、限流、降级与回滚

应用可启动与应用能受控运行是两件事。本课启动真实回环 HTTP 服务，验证限流、有限降级与配置回滚；没有部署云环境或执行生产压测，不代表学习者已掌握。

## 1. 给运行行为一个明确契约

模型暂时不可用时，可以返回明确标注的检索结果或人工入口；无权限时不能通过换另一个服务绕过拒绝；结构非法时不能把错误文本直接展示成成功答案。降级要保留用户目标与安全边界，并明确功能减少。

健康检查分进程存活与是否准备接流量。检查不能每秒触发一次付费模型调用。配置需版本化，启动校验，发布后观察关键指标，超过门槛可切回已知可用配置。

## 3. 补齐真正的运行条件

生产限流考虑主体、租户、并发、token/费用与共享存储。收到429时返回约定的重试信息，不让客户端立即重试形成风暴。健康端点与管理入口也需要独立暴露策略。

配置快照让一次请求使用同一版本。真正回滚还需要应用制品、数据库迁移兼容、队列任务版本和索引引用。若新版删除了旧字段，切回旧镜像可能仍无法工作，所以迁移先考虑兼容窗口。

容器化时固定 Node 主版本与依赖锁，构建与运行分层，使用非 root 用户，只注入所需环境，监听约定端口。密钥运行时注入，不能写进镜像层。这里没有执行 Docker 构建，项目作业需补实际构建、启动与健康验证记录。

## 4. 一份可执行的发布顺序

先完成离线契约与评测，构建可追溯制品；在测试环境验证依赖、认证、恢复与观测；按受控比例放流量，比较关键错误、质量、费用和延迟；到达预先约定的门槛就回滚并保留失败 trace。

不要靠“没有报错日志”推断成功，要有成功分母与用户任务完成证据。发布后回归数据可补进开发集，保留集仍保持独立。

## 故障练习与项目迁移

把所有错误都降级，验证403被吞掉；把配置对象原地修改，构造同请求读到不同版本；启动两个服务实例，观察内存限流额度翻倍。

项目练习：写部署说明、环境校验、健康检查、限流、降级矩阵和回滚手册，实际演练一次故障与回滚。报告明确本机、测试环境和生产验证的范围，不将本课 HTTP 测试称为已上线。

## 单页速记

- 降级只处理约定故障，不能绕过权限。
- 限流维度、共享状态与重试策略一起设计。
- 配置与制品可追溯，迁移保证回滚兼容。
- 发布门槛事先定义，恢复需要实际演练。
