# S7-L03 上线、限流、降级与回滚

应用可启动与应用能受控运行是两件事。本课启动真实回环 HTTP 服务，验证限流、有限降级与配置回滚；没有部署云环境或执行生产压测，不代表学习者已掌握。

## 1. 给运行行为一个明确契约

模型暂时不可用时，可以返回明确标注的检索结果或人工入口；无权限时不能通过换另一个服务绕过拒绝；结构非法时不能把错误文本直接展示成成功答案。降级要保留用户目标与安全边界，并明确功能减少。

健康检查分进程存活与是否准备接流量。检查不能每秒触发一次付费模型调用。配置需版本化，启动校验，发布后观察关键指标，超过门槛可切回已知可用配置。

## 2. 运行一个受控 HTTP 实验

~~~js file=S7-L03.mjs
import assert from "node:assert/strict";
import { createServer } from "node:http";
import { once } from "node:events";
let config = Object.freeze({version:"v2",mode:"primary"});
const knownGood = Object.freeze({version:"v1",mode:"retrieval-only"});
const counts = new Map();
function limited(subject) {
  const n = (counts.get(subject)||0)+1;
  counts.set(subject,n);
  return n>2;
}
async function primary(kind) {
  if (kind==="forbidden") throw Object.assign(new Error("FORBIDDEN"),{status:403});
  throw Object.assign(new Error("TEMPORARY"),{status:503});
}
const server = createServer(async (req,res) => {
  const url = new URL(req.url,"http://127.0.0.1");
  const send = (status,body) => {
    res.writeHead(status,{"content-type":"application/json"});
    res.end(JSON.stringify(body));
  };
  if (url.pathname==="/health") return send(200,{ready:true,version:config.version});
  // 仅为夹具身份，真实服务必须替换为认证中间件。
  const subject = "fixture-user";
  if (limited(subject)) return send(429,{code:"RATE_LIMITED"});
  const snapshot = config;
  try {
    await primary(url.searchParams.get("kind"));
    return send(200,{source:"primary"});
  } catch (error) {
    if (error.status!==503) return send(error.status||500,{code:"REQUEST_REJECTED"});
    return send(200,{source:"retrieval-only",degraded:true,version:snapshot.version});
  }
});
server.listen(0,"127.0.0.1");
await once(server,"listening");
const base = "http://127.0.0.1:"+server.address().port;
try {
  const first = await fetch(base+"/answer");
  assert.deepEqual(await first.json(),{source:"retrieval-only",degraded:true,version:"v2"});
  assert.equal((await fetch(base+"/answer?kind=forbidden")).status,403);
  assert.equal((await fetch(base+"/answer")).status,429);
  config = knownGood;
  assert.deepEqual(await (await fetch(base+"/health")).json(),{ready:true,version:"v1"});
  console.log("localhost HTTP: temporary failure degraded; forbidden stayed 403; third request=429");
  console.log("config pointer rolled back v2 -> v1; no cloud deployment performed");
} finally {
  await new Promise(resolve => server.close(resolve));
}
~~~

config pointer rolled back v2 -> v1; no cloud deployment performed

运行 npm run tutorial -- S7-L03。端口0由系统分配，避免抢占用户正在使用的5173/8787。实验计数器只有每进程前两次额度，没有时间补充和分布式一致性；它是可观察的最小限流边界，不是生产限流器。

## 3. 补齐真正的运行条件

生产限流考虑主体、租户、并发、token/费用与共享存储。收到429时返回约定的重试信息，不让客户端立即重试形成风暴。健康端点与管理入口也需要独立暴露策略。

配置快照让一次请求使用同一版本。真正回滚还需要应用制品、数据库迁移兼容、队列任务版本和索引引用。若新版删除了旧字段，切回旧镜像可能仍无法工作，所以迁移先考虑兼容窗口。

容器化时固定 Node 主版本与依赖锁，构建与运行分层，使用非 root 用户，只注入所需环境，监听约定端口。密钥运行时注入，不能写进镜像层。这里没有执行 Docker 构建，项目作业需补实际构建、启动与健康验证记录。

## 4. 一份可执行的发布顺序

先完成离线契约与评测，构建可追溯制品；在测试环境验证依赖、认证、恢复与观测；按受控比例放流量，比较关键错误、质量、费用和延迟；到达预先约定的门槛就回滚并保留失败 trace。

不要靠“没有报错日志”推断成功，要有成功分母与用户任务完成证据。发布后回归数据可补进开发集，保留集仍保持独立。

## 故障练习与项目迁移

把所有错误都降级，验证403被吞掉；把配置对象原地修改，构造同请求读到不同版本；启动两个服务实例，观察内存限流额度翻倍。

项目练习：写部署说明、环境校验、健康检查、限流、降级矩阵和回滚手册，实际演练一次故障与回滚。报告明确本机、测试环境和生产验证的范围，不将本课 HTTP 测试称为已上线。

## 单页速记

- 降级只处理约定故障，不能绕过权限。
- 限流维度、共享状态与重试策略一起设计。
- 配置与制品可追溯，迁移保证回滚兼容。
- 发布门槛事先定义，恢复需要实际演练。
