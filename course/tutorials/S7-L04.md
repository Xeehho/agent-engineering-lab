# S7-L04 真实模型适配器与验证证据

本课把服务商 HTTP 协议隔离在适配器，使用 Responses API 形状的本地服务器测试成功、限流和结构错误。它没有访问真实模型，不能证明模型效果、线上兼容或费用；不代表学习者已掌握。

## 1. 内部契约不要直接等于一家 SDK

应用希望拿到 text、usage、providerRequestId、模型版本和停止原因；不同服务商有不同字段、工具调用与流事件。适配器将外部协议转成内部契约，业务代码不应到处读取 provider.output[0]。

HTTP 200 后仍要验证 JSON、响应状态与内容形状。拒答、未完成、空文本、工具调用与完整文本是不同结果。此课只支持已完成的文本响应，其他形态显式拒绝，后续扩展时新增测试。

## 3. 这份适配器还缺什么

本例为了聚焦契约，没有实现响应体大小限制、工具调用、流式事件、拒答映射、真实模型名称校验、完整错误分类和有限重试。流式接入可复用 S1-L03 的分帧思想，但必须按服务商真实事件类型解析，不能直接套用课堂自定义事件。

预取消测试不能证明进行中的真实请求已取消。你要增加等待中的本地服务器、观察断连和资源清理；真实服务即使收到取消，也可能已产生计量，需查询服务记录。

## 4. 如何做一次真实验证

在已授权服务、模型、费用上限和非敏感数据范围内，配置本地密钥，先只做少量代表性请求。记录模型标识、API/适配器版本、Prompt、输入集、请求关联、计量、延迟与错误。不要把密钥写入代码、浏览器、Git 或共享截图。

先验证协议成功，再运行业务评分。真实模型输出不应成为脆弱的固定字符串单测，而应按结构、事实与业务要求评分。模型路由变更后重跑同集，保留回归与不确定性。

本课没有执行上述付费验证。你提交时明确分开：夹具契约通过、真实服务互通、业务质量评测、生产运行。四者不能用一个“测试通过”概括。

## 故障练习与项目迁移

让200返回非法 JSON、未完成状态或拒答内容，分别设计错误映射。没有 usage 时保留 null，非法计量才拒绝，不能混淆未知与错误。让429反复出现，加入全局重试预算与退避。增加进行中取消并观察服务端清理。

项目练习：让应用只依赖内部 adapter 接口，保留 Mock 与至少一个真实适配设计。只有实际授权执行并保存证据后，才在作品集写真实模型互通或质量结论。

## 单页速记

- 外部协议在适配器边界收敛，内部契约独立。
- 200、完成、文本、业务正确分别判定。
- 取消、重试、计量和错误都保留来源与范围。
- 本地夹具、真实互通、质量与生产验证分别报告。
