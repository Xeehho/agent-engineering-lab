# S8-L03 作品集、简历与岗位映射

这门课的目标是让你能展示并解释 AI 应用工程能力。教材不能承诺具体薪资或录用；岗位要求需要按投递时真实招聘信息更新。本课验证能力声明与证据映射，不代表学习者已掌握。

## 1. 从“熟悉技术”变成可核查结果

“熟悉 RAG、多 Agent、MCP”信息量很低。更具体的描述是：“为研发工单助手实现版本化检索与引用定位，在固定的30条验证集报告 Recall@5，并保留失败与权限案例。”这里的样本数、指标、实现范围都必须真实。

你已有前端经验，可以强调流式交互、复杂状态、任务恢复、审批体验与可观察性，再用服务端执行控制、数据、检索、评测证明转型深度。不要把前端经历抹掉，也不要把生成一份代码仓库写成独立设计并运营过生产系统。

## 2. 对能力声明做证据审计

~~~js file=S8-L03.mjs
import assert from "node:assert/strict";
const evidence = new Map([
  ["mcp-local",{kind:"local-integration",verified:true}],
  ["rag-fixture",{kind:"fixture-metric",verified:true}],
  ["ui-demo",{kind:"browser-demo",verified:true}]
]);
const claims = [
  {text:"完成本地 MCP 客户端/服务端互通",requires:"local-integration",evidenceId:"mcp-local"},
  {text:"生产 RAG 准确率99%",requires:"production-eval",evidenceId:"rag-fixture"},
  {text:"实现任务状态与审批界面演示",requires:"browser-demo",evidenceId:"ui-demo"},
  {text:"已承受十万用户并发",requires:"load-test",evidenceId:"missing"}
];
function inspect(claims,evidence) {
  return claims.map(c => {
    const e = evidence.get(c.evidenceId);
    return {...c,supported:!!e?.verified && e.kind===c.requires};
  });
}
const rows = inspect(claims,evidence);
assert.deepEqual(rows.map(r => r.supported),[true,false,true,false]);
assert.equal(rows.filter(r => r.supported).length,2);
const jobs = [
  {id:"frontend-ai",needs:["React","streaming","evaluation"]},
  {id:"agent-app",needs:["tools","MCP","SQL","evaluation"]}
];
const demonstrated = new Set(["React","streaming","tools","MCP"]);
const gaps = jobs.map(j => ({id:j.id,missing:j.needs.filter(n => !demonstrated.has(n))}));
assert.deepEqual(gaps,[{id:"frontend-ai",missing:["evaluation"]},{id:"agent-app",missing:["SQL","evaluation"]}]);
console.log("supported claims=2/4; fixture cannot justify production metric");
console.log("gaps: frontend-ai=evaluation; agent-app=SQL,evaluation; jobs are synthetic");
~~~

~~~

运行 npm run tutorial -- S8-L03。例子里的岗位是合成能力组合，不能替代当下 BOSS 直聘的真实 JD。声明“缺少SQL证据”也不等于“完全不会SQL”，只是作品集暂不能证明，需要补项目与问答。

## 3. 作品集应让评审快速复现

README 用一段话说明用户与问题，再放一条真实演示路径、架构图、启动命令、数据与权限设计、评测报告、故障恢复、限制和 AI 协助说明。公开版本移除密钥、个人答案、私有数据与无权公开的素材。

演示控制在8分钟左右：问题与约束1分钟，主路径3分钟，故障与恢复2分钟，质量证据与取舍2分钟。不要把全部时间用来朗读技术栈。准备一个可以重放的失败案例，比只有成功录屏更能展示判断能力。

## 4. 针对岗位做学习闭环

投递时保存岗位原文、公司、地点、薪资口径、日期与链接，按前端/AI应用方向映射必需与加分能力。比较薪资时核对月薪、薪月、奖金、税前与范围，不能只看一个30k数字。

对每项要求标“已实现且能解释”“实现但证据不足”“只学过概念”“未覆盖”，选最常出现且与你目标相符的缺口优先补。不要为某条 JD 的每个名词都开一个项目。

具体岗位与薪资是时效信息，本课不重新虚构招聘样本。课程完成后仍需用最新真实 JD 与面试反馈调整，录用取决于经验、岗位匹配、面试与市场。

## 5. 面试后的改进

记录被追问的概念、没解释清的数据流、没排出的故障与表达问题。先在项目中补一个最小可验证实验，再更新笔记与简历。不要为了迎合面试把未验证指标写进去。

你可以持续使用 Agent，但要能审查它提出的方案、指出风险、设计实验并解释结果。面试时如实说清工具帮助与本人负责部分，用未知变更展示迁移能力。

## 练习与阶段验收

写三个真实项目要点，每条包含问题、行为、证据与范围；给每条能力链接到 commit、测试、报告或演示。挑两个真实目标岗位做差距表，制定下一轮最小补强任务。

最终验收包括作品复现、系统设计、未知故障、简历核验与模拟面试。看完课程、跑完公开脚本或获得自测满分，都不自动等于能胜任岗位；阶段考试与项目证据决定下一步。

## 单页速记

- 简历写可核查行为与结果，指标必须真实。
- 前端优势与后端 AI 工程能力共同构成定位。
- 作品集保留失败、取舍、限制和 AI 协助范围。
- 岗位信息随时间更新，求职能力用项目与面试反复验证。
