# S5-L04 RAG 评测与数据治理

“我问了三个问题，都答得不错”不足以证明检索系统可用。本课计算逐条检索与拒答指标，使用公开合成样本；没有大规模真实用户评测，不代表学习者已掌握。

## 1. 先定义样本与分母

每条样本需要 query、租户、语料版本、可回答性、相关文档集合、预期关键事实和限制条件。训练/调参集帮助改系统，保留集用于最后判断；把保留集看过并据此改阈值后，它就不再是干净的保留集。

Recall@K 是前K条命中相关文档数除以该问题相关文档总数；MRR 用第一个相关结果的倒数排名。两者衡量不同问题：只找到一个相关文档可能 MRR 很好，但多来源问题 Recall 仍低。无相关文档的问题不应硬填 Recall=1 来美化平均数。

Recall@2=0.75; MRR@2=0.75; retrieval denominator=2
abstention decisions=2/3; q2 false refusal; q3 retrieval N/A

**选做本地验证：**运行 npm run tutorial -- S5-L04。q1 只召回2个相关文档中的1个，Recall=0.5；q2 在第二位召回唯一相关文档，Recall=1、RR=0.5。平均后两者都是0.75，这只是本样本巧合。q2 检索成功却拒答，说明生成/决策层还存在问题。

## 3. 分层诊断比一个总分更有用

对每条失败分别问：文档是否正确入库？权限是否允许？候选是否包含证据？排序是否保留？生成是否忠实？引用是否定位正确？用户最终任务是否完成？不要因为答案错就先换模型。

报告按查询类型、语言、文档类型、租户与长尾场景切片。小样本百分比波动很大，要给出分子分母与失败 ID；上线前用代表性样本和适当不确定性估计。关键越权案例可以设零容忍发布门槛，但有限测试未发现不等于证明永远不会发生。

## 4. 数据生命周期是质量的一部分

语料需要来源许可、采集范围、敏感字段策略、更新与删除责任人。文档被撤权后，索引、rerank 输入、缓存和已生成引用都要处理。评测集本身也可能含个人信息，不能因为是测试数据就公开。

去重不仅是降低成本：相同模板的近重复问题同时出现在开发集和保留集，会让结果虚高。按文档、业务实体或时间切分，降低泄漏。保存数据集版本与标签变更理由，评审者有分歧时先写准则，再仲裁。

## 故障练习与项目迁移

删除一次运行记录，系统应该报缺失，不能从分母剔除。把重复候选当不同命中，构造虚高 Recall。把 q3 的 N/A 填成1，比较错误宏平均。每次都指出具体分母如何改变。

项目练习：整理不少于30条有来源的问题，覆盖可回答、不可回答、权限和冲突。冻结基线后比较一个改动，保存逐条结果与退步列表。真实业务样本不足时明确样本来源与推广边界，不把合成评测写成生产准确率。

## 单页速记

- 相关性、可回答性与最终任务成功分别标注。
- 指标必须写分母；N/A、缺失和失败不可混为成功。
- 固定集配对对比，保留回归与关键失败门槛。
- 语料和评测数据都需要权限、版本、去重与删除。
