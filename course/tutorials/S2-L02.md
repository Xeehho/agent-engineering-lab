# S2-L02｜有限 Agent 循环：把继续执行和停止条件写进程序

教材已扩写，不代表学习者已经掌握。Node 24，本地固定决策，无真实模型。先修：工具分发器、取消与错误分类。

## 本课目标

- 为一个循环定义状态、决策、工具结果和终止原因。
- 分别限制模型轮次、工具次数与整体期限。
- 让批量工具与预取消都有可预测的行为。

## 1. 从一个会无限搜索的助手开始

用户要求查订单故障，助手查到文档后仍然反复 searchDocs，没有新增信息。自然语言里说“最多三次”可能有帮助，但若程序无限 while，系统仍可能一直花费资源。

最小 Agent 循环可以写成：读取任务状态→请求决策→验证决策→预检预算→执行工具→记录结果→继续或结束。与固定 Workflow 的差别在于下一步由模型动态提议，而执行控制仍属于应用。

## 2. 写状态表，再决定循环长什么样

至少区分 succeeded、cancelled、model_budget、tool_budget、deadline、failed。预算终止不是业务成功；应该保留部分证据与停止原因，而不是把最后一段文本强制包装成最终答案。

模型轮次不等于工具数。一轮可能提议三个工具；重试、并行分支也消耗预算。本课选择“批次超过剩余额度时整批拒绝”，这样不产生半批副作用。你也可以设计部分执行，但必须有明确结果与幂等约定。

## 3. 分步实现一个有界调度器

运行 node examples/tutorials/S2-L02.mjs。第一个 provider 先读再答；第二个一直搜索；第三个一次提议过多工具。决策是脚本夹具，不是模型智能。

~~~js file=S2-L02.mjs
import assert from "node:assert/strict";
async function run(decide,{maxRounds=3,maxTools=2,signal=new AbortController().signal}={}) {
  const state = {rounds:0,tools:0,history:[]};
  const deadline = Date.now()+1000;
  for (;;) {
    if (signal.aborted) return {...state,reason:"cancelled"};
    if (Date.now()>=deadline) return {...state,reason:"deadline"};
    if (state.rounds>=maxRounds) return {...state,reason:"model_budget"};
    state.rounds++;
    const decision = await decide(structuredClone(state));
    if (signal.aborted) return {...state,reason:"cancelled"};
    if (decision.type==="final" && typeof decision.text==="string")
      return {...state,reason:"succeeded",answer:decision.text};
    if (decision.type!=="tools" || !Array.isArray(decision.calls))
      return {...state,reason:"invalid_decision"};
    if (!decision.calls.length) return {...state,reason:"no_progress"};
    if (decision.calls.length>maxTools-state.tools)
      return {...state,reason:"tool_budget"};
    for (const call of decision.calls) {
      if (signal.aborted) return {...state,reason:"cancelled"};
      if (call.name!=="searchDocs") return {...state,reason:"unknown_tool"};
      state.tools++;
      state.history.push({callId:call.id,result:"local evidence"});
    }
  }
}
const success = await run(async s=>s.tools
  ? {type:"final",text:"基于本地证据的草稿"}
  : {type:"tools",calls:[{id:"c1",name:"searchDocs"}]});
assert.equal(success.reason,"succeeded");
const repeated = await run(async s=>({type:"tools",calls:[{id:"c"+s.rounds,name:"searchDocs"}]}),{maxRounds:10});
assert.equal(repeated.reason,"tool_budget");
assert.equal(repeated.tools,2);
const batch = await run(async()=>({type:"tools",calls:[1,2,3].map(id=>({id,name:"searchDocs"}))}));
assert.equal(batch.tools,0);
const controller = new AbortController(); controller.abort();
const cancelled = await run(async()=>{throw new Error("should not call");},{signal:controller.signal});
assert.equal(cancelled.rounds,0);
console.log("success=succeeded; repeat=tool_budget; oversized batch executed=0");
console.log("pre-cancel model rounds=0");
~~~

## 4. 这段代码证明什么，还缺什么

预算检查在实际工具执行前，所以整批拒绝时 tools=0。state.rounds 在请求决策前增加，失败请求也已消耗一次尝试，不能等成功后才计数。history 保存真实工具结果，不允许模型自行伪造“工具已经执行”。

这里 Date.now 只检查循环边界，不能中断一个永不返回的 decide。真实实现必须把剩余期限传给支持取消的 provider，并为挂起请求设置可执行的截止机制，使用第一阶段的方法。这个局限是实验要你发现的关键点，不能把有限 for 检查当成全部超时控制。

费用预算还没有实现；toolCount 不能替代 token 或金额。需从实际模型返回计量、价格版本和事先预算检查中补齐，并在未知时保留未知。

## 5. 先决定是否需要动态循环

如果业务固定为“校验输入→检索→生成草稿”，确定性 Workflow 更容易验证。需要根据工具结果探索未知步骤时，Agent 才可能值得引入。给同一组任务建立简单基线，比较质量、调用次数、延迟与费用。

停滞检测可以检查重复工具+相同参数+无新增证据，但“重复一次”未必错误，例如暂时性失败重试。把停滞、重试与预算结合，不用一个字符串重复判断替代全部业务理解。

## 6. 故障练习

把预算检查放在工具循环之后，观察超大批次会先执行再停止；对于写操作，这已经太晚。把 history 直接传给不可信 decide 且不复制，模拟其篡改 tools 计数，说明执行控制面不能由模型输出覆盖。

让 decide 返回空工具列表，检查是否明确 no_progress。让 decide 永远等待，使用本课尚未实现的上游取消把它修好，并证明 timer、监听器及执行任务都被释放。

## 项目迁移与验收

接上上一课分发器时，用结构化结果区分最终答案与工具提议。写出最大轮次、最大工具数、批次策略、整体期限、重试计数、取消和部分结果的约定。

至少验证成功、重复提议、超额批次、非法决策、预取消与挂起 provider 六类路径。本人解释每种停止是否成功，以及从哪些证据得出。不要以“模型最终愿意停”代替程序有界性。

## 单页速记

- 决策可以动态，执行控制必须有界。
- 轮次、工具、token、费用、并发和截止时间分别计量。
- 批次先预检，取消先检查，失败尝试也计数。
- 边界检查不自动中断正在等待的操作，必须接上取消。
