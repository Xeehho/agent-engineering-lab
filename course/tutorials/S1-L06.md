# S1-L06｜Python 桥接：用真实 FastAPI 路由理解服务边界

教材已扩写，不代表学习者已经掌握。本课运行 Python 3.12、FastAPI 0.162.0 与 httpx 0.28.1。示例使用本进程 ASGI 测试客户端，没有访问模型，也不把它当作公网部署验证。

## 本课目标

- 把 TS 的接口、unknown 校验、异常与异步概念对应到 Python。
- 在网页推演输入与超时契约；进阶时可选运行真实路由。
- 通过错误输入与状态观测检查行为，而不是只读语法。

## 1. 不从语法大全开始，先追一次请求

你已有前端基础，先找这条路径：JSON 请求 → 路由 → 输入模型 → 业务操作 → 响应模型 → 调用方。Python 的 dict/list 对应常见对象/数组容器，函数和异常也承担类似职责；类型提示只描述意图，不会自动验证所有外部对象。

FastAPI 配合 Pydantic 的输入模型会实际执行验证，这与只在函数参数上写一个普通类型注解不同。默认类型转换策略也需要留意：若业务不接受字符串 "8" 当整数，就明确使用严格整数，而不是凭注解猜行为。

## 4. 对照 TS 阅读，而不是逐行翻译

ReadingIn 同时参与参数描述与框架的运行时验证；StrictInt 与 ge=0 是实际输入约束。ReadingOut 约束响应。process_reading 的输入已通过这一层，不代表其中任何业务结论都天然正确。

async def 返回协程，遇到 await asyncio.sleep 时允许其他工作推进。把它换成 time.sleep，并不会因为外层仍写着 async 就保持非阻塞。数据库和 HTTP 客户端是否异步，要看实际库接口。

asyncio.timeout 超时会取消当前等待，让 process_reading 的 finally 执行。这里只证明协作式 sleep 的清理；如果你吞掉取消异常、调用阻塞函数，或操作另一个不支持撤销的系统，结论就不同。

## 5. 亲自制造三个错误

将 StrictInt 改成普通 int，再发字符串 "8"，核对框架是否转换；然后解释为什么业务需要明确策略。将 active 的清理删除，超时后的计数断言应失败。

把 asyncio.sleep 换成阻塞等待后，不要单凭单请求返回来判断并发正确。你需要再设计两个同时请求的观察，记录第二条请求何时开始/结束。本课测试客户端也不验证代理、真实 TCP 断开或多进程部署。

## 6. 服务如何给 React 调用

实际本地服务还需要 ASGI 服务器、固定监听地址、CORS/代理和配置。先把 /readings 路由独立验证，再让 React 经应用代理请求；不要把模型 Key 放进前端。

项目迁移应保持可观察契约：哪些输入被拒绝、返回哪些字段、超时怎样展示、来源是什么。TS 与 Python 不必代码行数相同，但同一输入和前置条件应得到约定的行为。

要正式启动网络服务，可在独立练习目录安装并锁定 ASGI 服务器，依据它当前文档加载本文件的 app，再补真实 HTTP 与取消验证。这一步不能由 ASGITransport 的 200 自动推出。

## 练习与验收

1. 为额外字段定义允许/拒绝策略，并写一条真实路由用例。
2. 给 TS 和 Python 的读数实现使用同一组 JSON 夹具，比较错误与转换策略。
3. 完成自己的 health/validate 服务和 React 调用，提交命令、环境、响应与局限。

验收重点是你能追踪验证、await、异常映射和清理。复制示例不自动代表已经完成 Python 服务或第一阶段工单作业。
