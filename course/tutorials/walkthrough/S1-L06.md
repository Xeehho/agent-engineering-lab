## 代码阅读：从前端请求追到 Python 路由

### 把新语法对应到已有经验

class ReadingIn 定义输入模型，作用类似“字段定义加运行时验证”；普通 Python 类型提示本身不承担全部验证。@app.post 是路由注册装饰器，把下面函数绑定到 POST /readings。async def 声明协程，await 等待它完成，async with 管理异步上下文的进入与退出。

不要一次背全套 Python 语法。先沿一条请求阅读：client.post 提交 JSON → FastAPI 用 ReadingIn 验证 → read_reading 设置期限 → process_reading 执行 → ReadingOut 检查响应 → client 收到结果。

### 跟踪正常与超时路径

|输入|是否进入 process_reading|结果|active 最终值|
|---|---|---|---|
|value=8|进入|200，value=16|0|
|value是字符串8|不进入|422|0|
|value=-1|不进入|422|0|
|value=8，delay_ms=200|进入后被期限取消|504|0|

process_reading 先把 active 加1。正常返回和取消都会进入 finally 减1。20毫秒期限短于200毫秒等待，所以 timeout 将取消传到 await asyncio.sleep，并由路由映射为504。

~~~py
async with asyncio.timeout(0.02):
    doubled_value = await process_reading(data)
~~~

这段控制的是协作式异步等待。换成 time.sleep 后，事件循环可能被阻塞，不能因为外面仍有 async 就认为期限同样有效。

### 测试到底在哪里执行

ASGITransport 直接把 HTTP 风格请求交给本进程 app，不开监听端口。base_url 只是构建请求地址，classroom 不是本课要访问的远程服务器。直接运行文件才调用 asyncio.run(verify_routes())；被 ASGI 服务器导入时只创建 app。
