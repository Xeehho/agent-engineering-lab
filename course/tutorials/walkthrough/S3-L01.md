## 代码阅读：两个文件怎样合作

### 先看部署而不是 import 数量

S3-L01.mjs 是最小 Host 与 Client，S3-L01-server.mjs 是被启动的独立 Node 进程。StdioClientTransport 的 command 指向当前 Node，args 指向 Server 文件。它们通过 stdin/stdout 交换协议消息，不需要自己选择端口。

运行客户端入口即可；不要先手动运行 Server 后再猜 Client 为什么没连上。手动启动的 Server 正在等待标准输入，而客户端默认会另外启动自己的子进程。

### 从连接走到业务结果

|步骤|客户端调用|你应检查什么|
|---|---|---|
|初始化|connect|进程是否启动、版本是否兼容|
|发现|listTools|是否存在get_ticket及参数Schema|
|调用|callTool|工具名、arguments和结果|
|结束|close|连接及子进程能否清理|

Server 的 registerTool 连接三部分：名字、输入/输出 Schema、实际 handler。handler 返回 structuredContent 供程序消费，content 中的 text 供文本展示。NOT_FOUND 是业务结果，不应凭收到了 JSON 就显示成功。

### 版本字段不要混淆

server version=1.0.0 是应用版本，SDK=1.32.2 是库版本，2025-11-25 是协议修订。requestedProtocolVersion 记录初始化时提出的修订，不能把它与全部协商过程等同。升级时分别核对三者。

### 带提示的练习

先改客户端工具名，观察发现和调用哪个环节失败。再给 Server 加 stdout 日志，理解为何协议通道被污染；诊断改用 stderr。最后画出真实模型接入后谁提议、谁批准、谁执行，MCP 本身不替你决定授权。
