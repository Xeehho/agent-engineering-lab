# S1-L04｜验证与交卷：把结论连接到可复现的观察

教材已扩写，不代表学习者已经掌握。本课使用 Node 24 本地执行产生证据；不伪造真实模型结果。先修：能运行第一阶段实验，读懂成功和失败路径。

## 本课目标

- 将“稳定、准确、做完了”拆成能被检查的具体主张。
- 区分源码、断言结果、日志、截图与模型效果证据。
- 形成别人能够按同一版本复现的提交。

## 1. 从一句不能验收的话开始

“我让 AI 把接口写完了，测试全绿。”这里没有说明测试检查什么、用什么 provider、运行在哪个 commit，也没有说明测试是否真的执行了关键分支。

先把主张拆开：合法输入得到结果；缺少字段被拒绝；输出不合约时不显示成功；超时有截止时间；取消传到工作操作；旧响应不更新 UI。这些主张应分别对应输入、预期、实际和观测点。

截图能证明某个时刻页面出现了文字，不能独自证明服务端停止、权限隔离或模型准确。代码存在能说明实现意图，运行证据才能说明那条路径被实际触发。

## 2. 证据表必须能追到版本

至少记录 caseId、commit、环境、输入、预期、实际、结论与限制。真实模型另有 provider/model/Prompt版本/日期/usage，未知就写未知。不要把无法获取的字段填成 0 或“已经验证”。

环境是结论的一部分。内存 Map 的去重不能当作数据库跨实例保证；本地固定输出不能当成模型理解输入。测试数量也不是能力评分，同一主张重复一百次可能仍只覆盖一个边界。

## 3. 跟着做：生成一份真实的本地检查报告

**选做本地验证：**这个示例验证一个与工单作业无关的计数契约，让你观察报告来自实际运行，而不是先填写 passed。运行 node examples/tutorials/S1-L04.mjs。

~~~js include=S1-L04.mjs
~~~
~~~text expect=S1-L04.mjs
normal: true (2)
string: true (INVALID_COUNT)
null: true (NOT_OBJECT)
negative: true (INVALID_COUNT)
scope: four local contract cases; no model accuracy claim
~~~

先运行未修改版本。然后把 count < 0 的拒绝删掉：negative 用例将失败。不要修改 expected 去迎合错误实现，先回到“计数允许负数吗”这个需求。若需求真的变化，须同时修改契约、用例与说明。

## 4. 用一次失败证明你理解了路径

一个可审阅复盘包含：原始现象、复现输入、所在版本、最初假设、支持/否定假设的证据、定位、最小改动和回归。它不需要写成日志流水账，而要让读者理解为什么这个改动解决这个问题。

例如字符串 "2" 被错误接收，不要直接归因于模型。先检查 JSON.parse 后实际类型，再看运行时 validator。若 AI 建议加 as Count，这不增加校验。你应要求它在接收外部值的位置加入可执行约束，并验证正常路径没有被破坏。

## 5. 迁移到项目的交卷目录

用已有 submissions/stage-01/README.md 列出作业 commit，给每个验收项放可复现命令或脱敏材料。图中标明浏览器→API→provider→校验→UI，并指出谁决定成功、谁处理取消。

公开练习通过后，再补它未覆盖的风险：例如预取消不调用 provider、空白摘要被拒绝、流结束但未收到 terminal。先写预期，再让 AI 实现；保留你亲自解释与验证的部分。

个人原始答案放被忽略的 private 目录。不要把 Key、真实用户工单或完整未脱敏日志提交到未来公开教材。

## 6. 代码审阅演练

按这个顺序问自己：输入从哪里进入；数据何时从 unknown 被收窄；错误在哪层被转成响应；资源在哪条结束路径释放；同一结果能否在固定版本复现。若回答只能是“AI说这样可以”，该处还没有通过本人理解检查。

在项目自述中使用准确表述：“已验证四条本地契约用例，真实模型效果待测”，而不是“应用准确率100%”。一次失败被正确处理也是有价值的证据，不应为了展示漂亮而删除。

## 练习与验收

1. 为同一个功能写三条独立主张，并写清哪种证据足够、哪种不够。
2. 亲自破坏一个边界，保存失败输出，再解释最小修复。
3. 补齐项目提交模板，说明 AI 生成、本人判断、本人运行和仍待验证的范围。

通过标准是别人能复现、主张与证据对应、限制诚实、本人能解释。阶段正式考试仍在交卷后生成新题，本课公开检查不计正式成绩。

## 单页速记

- 主张先拆小，再选择观测点。
- 代码、运行、截图、Mock、真实模型有不同证明范围。
- 失败复盘回答“为什么这处修复有效”。
- 交卷固定 commit、命令、环境、实际结果与未验证项。
