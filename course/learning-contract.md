# 学习与考核制度

## 学习方式

学习者继续使用AI Coding。老师不以手写行数评分，检查你是否能定义正确结果、理解关键实现、发现错误并验证修复。

练习、项目和实战排错允许AI；每次提交记录AI做了什么、你做了什么。概念答辩和关键代码追问要求你不查资料、不让AI代答。文字交流无法技术监考，独立完成属于你的声明。

## 每一阶段的流程

诊断／回顾 → 学习单元 → 作业 → 公开练习 → 交卷 → 老师review当前commit → 新变式考试 → 反馈与进度记录。

公开题、公开测试和CI都不是正式考试。正式试题在交卷后生成；不把“题目写在另一个公开文件”当作隐藏考试。

## 评分

|部分|分值|考核方式|
|---|---|---|
|概念与代码答辩|30|本人解释数据流、关键取舍、边界和失败原因|
|项目与证据|50|按阶段契约检查实现与可复现验证|
|现场变式排错|20|复现、定位、修复、回归；可用AI但需解释过程|

通过条件：总分至少80；答辩至少20/30、项目至少35/50、排错至少12/20，且无未解决的关键正确性问题。90分以上且答辩扎实可加快后续阶段，不安排重复练习凑时长。

密钥入库、伪造验证、删改测试绕过要求，应先纠正，相关证据不计分。缺少真实模型条件时可以完成离线阶段；真实模型接入与效果明确记为待验证，毕业前补交一轮实际接入证据。

## 进度记录

learning/progress.json记录当前阶段、作业commit、考试尝试、分数和未验证事项。只有老师完成评阅才标passed，测试脚本不自动打分。锁定后续阶段属于教学约定，不是仓库访问权限。

若暂停或换聊天，使用course/continue-with-teacher.md恢复上下文；不依赖老师自动在其他聊天记住进度。
