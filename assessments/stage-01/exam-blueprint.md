# 第一阶段考试蓝图

正式考题在作业提交后，由老师根据提交commit生成。这里公开考核维度，不预置正式试卷、隐藏答案或自动考试通关按钮。

## 准考条件

- 提交代码commit和AI协作说明。
- npm run check通过，11条公开练习通过。
- 至少3条有意义新增边界验证。
- 流式成功／失败／取消的可复现证据。
- 已声明Mock与真实模型验证范围。

## 考试构成，建议60–90分钟

|部分|分值|内容|
|---|---|---|
|本人答辩|30|随机追问概念、真实提交的数据流与错误路径；不查资料、不让AI代答|
|项目评阅|50|契约与校验15、异常/超时/取消15、流式交互10、测试/来源与证据10|
|现场变式|20|老师给未提前暴露的故障或需求变更；复现6、定位8、修复与回归6|

现场变式允许AI Coding，但你必须解释为什么相信修复正确；老师可临时改变输入或要求你预测执行结果。文字环境无法技术监考，独立答辩属于学习者声明。

总分80及以上，并满足答辩20/30、项目35/50、变式12/20才通过。规则见course/learning-contract.md。

## 老师出题流程

1. 获取学习者当前分支和commit，检查是否有未提交改动。
2. 阅读提交材料、运行公开检查，并挑选实现中的关键假设。
3. 出3–5个概念／代码追问；一次不要把答案或完整修复一起给出。
4. 根据实现生成一个新变式，例如响应分块、错误优先级、非法枚举、取消竞争；改变公开案例的数据或调用时序。
5. 对实际证据评分，并记录未验证事项；不把真实模型不可用误说成已验证。
6. 未过关时给最小补学题，再安排同等难度的新变式。
