## 实验：先分清：收到回答与完成业务

先读本课讲义中概念和字段的解释，再运行这个小例子。无需安装或启动项目。

~~~js
// 三个候选都假设已经通过网络返回。
const candidates = [
  "不是JSON",
  '{"group":7}',
  '{"group":"火星组"}',
  '{"group":"技术支持"}',
];
function parse(raw) {
  let value;
  try {
    value = JSON.parse(raw);
  } catch {
    return "文本不能解析";
  }
  if (!value || typeof value.group !== "string") return "字段类型不对";
  if (!["技术支持", "账务支持"].includes(value.group)) return "业务不允许";
  return "可以分诊";
}
for (const raw of candidates) console.log(parse(raw));
assert.equal(parse(candidates[3]), "可以分诊");

~~~

观察方向：浏览器本地教学替身。只验证代码明确检查的条件，不证明真实模型、网络或生产组件行为。

提示：先跟踪一组具体输入怎样变成输出；每次只改一个条件，不急着展开完整实现。

## 实验：类型写对了，值就对了吗？

先预测 typeof 的输出，再运行。这里是去除 TypeScript 类型后的等价 JavaScript；浏览器不会执行 as 语法。

~~~js
const reading = JSON.parse('{"value":"8"}');
console.log("实际类型：", typeof reading.value);
try {
  console.log(reading.value.toFixed(1));
} catch (error) {
  console.log(error.name + ": " + error.message);
}

// 这才是实际运行的检查；typeof 断言不会自动改变字符串。
function hasNumericValue(value) {
  return (
    value !== null &&
    typeof value === "object" &&
    typeof value.value === "number" &&
    Number.isFinite(value.value)
  );
}
assert.equal(hasNumericValue(reading), false);
assert.equal(hasNumericValue({ value: 8 }), true);
assert.equal(hasNumericValue(null), false);
console.log("运行时校验：字符串、数字、null 已分别检查");

~~~

观察方向：观察 string 和捕获的 TypeError。试着把 JSON 中的字符串改成数字，再运行比较。

提示：双引号里的 8 是字符串。类型声明不负责转换它。

## 实验：合法 JSON，一定是业务对象吗？

这些文本都能被 JSON.parse 解析。记录每个值的类型、是否为数组，以及它是否具有完整的工单字段。

~~~js
for (const text of ["null", "[]", '"done"', "42", '{"category":"bug"}']) {
  const value = JSON.parse(text);
  console.log(text, "=>", typeof value, "数组:", Array.isArray(value));
}

~~~

观察方向：注意 typeof null 的历史行为。typeof 为 object 仍不能证明是完整业务对象。

提示：分别检查 null、数组、缺少字段的对象；不要只检查 typeof。

## 实验：HTTP 503，会直接进入 catch 吗？

这是本地构造的 Response，不是一次远程 Fetch。用它观察 status 与 ok，真实 Fetch 的行为参见讲义中的 MDN 来源。

~~~js
const response = new Response('{"error":"unavailable"}', {
  status: 503,
  headers: { "Content-Type": "application/json" },
});
console.log("status:", response.status);
console.log("ok:", response.ok);
console.log("body:", await response.json());

~~~

观察方向：503 对应 ok: false。把 status 改为 200，再比较；这仍不能证明业务内容正确。

提示：Response.ok 只根据 200–299 状态范围判断。

## 实验：固定 Mock，到底证明了什么？

这个 Mock 无论输入什么都返回同一结果。尝试更换输入，再描述它能验证和不能验证的事情。

~~~js
function mockProvider(input) {
  return {
    category: "bug",
    priority: "medium",
    summary: "订单页白屏",
    missingInformation: [],
  };
}
for (const input of ["订单页白屏", "请增加深色模式"]) {
  console.log("输入：", input);
  console.log("输出：", mockProvider(input));
}

~~~

观察方向：能观察到固定返回与处理路径；不能据此评价真实模型的理解能力或分类准确率。

提示：第二条输入是否被输出忠实描述？一次工程演示与模型效果证据要分开。
